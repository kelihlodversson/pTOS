pTOS - userspace AES and kernel CUIS (#661)
==========================================

Migration boundary
------------------

The current source API/extension matrix and remaining cutover gates are in
doc/libaes-compatibility.md. That matrix describes external libaes, separately
from the legacy kernel AES service documented in aes-x32.txt. RCS's x32/libaes
target is merged and its resource load/edit/save/reload regression passes.

The target is an ordinary per-process libaes.so over native Core User
Interface Services (CUIS). There is no userspace AES daemon. Kernel CUIS
owns shared authoritative GUI state; VDI owns drawing/hardware services.
The initial #675 slice implements sessions and application-local rectangle
helpers. #679 adds caller-local object-tree editing and coordinate calculation. It does not yet supply a complete GEM AES API or replace the
existing kernel AES. Existing x32 import clients remain available while
operations migrate; they are not the native CUIS protocol.

GEM source compatibility is the public contract. Applications use standard
GEM headers, function names, signatures, structures, constants and return
conventions (appl_*, evnt_*, wind_*, menu_*, form_*, objc_*, graf_*, rsrc_*,
shel_* and scrp_*). The aes_session_*, aes_window_* and similar
CUIS wrappers currently exported for migration tests are transitional
implementation helpers, not a replacement application API. Move these behind
the library boundary as the standard adapters migrate; applications must not
need CUIS handles, sender grants or other pTOS-specific setup calls.

Preserve GEM behavior as well as syntax: application IDs and discovery,
message layouts/lengths/ordering, blocking and nonblocking reads, event masks
and multi-event results, click/rectangle/timer predicates, focus and window
messages, redraw iteration/update locking, and resource/object ownership.
Map private CUIS handles/errors to the documented GEM IDs/results; do not
truncate native handles into WORD application IDs or leak negative CUIS
errors through APIs whose GEM convention is Boolean. The initial four-word
transport is a foundation, not a permanent 16-byte limit on appl_write/read.

Inventory meaningful MultiAES, MagiC and XaAES extensions against tos.hyp and
GEMlib headers, with a per-feature support/semantics/test matrix. Implement
applicable extensions through the familiar API, including mt_* entry points
where provided by the chosen GEM binding. Report unsupported features using
the documented AES conventions and capability queries; never claim support
through appl_getinfo before it exists. These GEM compatibility queries are
library behavior, not version negotiation in the CUIS syscall protocol.
Compile representative existing GEM source against the normal headers and
link to libaes, then exercise its behavior in isolated x32 clients before
claiming the migration complete. Kernel primitives must permit these
semantics; hiding a conflicting protocol behind a renamed wrapper is not
sufficient.

Inventory of the current implementation and intended ownership:

                                                bounded authorized delivery

Current sources expose the migration points: gemaplib/gemevlib/gemasync and
aes_service.c combine registration, scheduling, GEM messages and waits;
gemwmlib/gemwrect and aes_window.c combine authoritative windows with
GEM decorations; gemoblib/gemobjop/gemobed, aes_tree.c and
aes_objects_kernel.c implement tree operations; gemrslib/rsload_portable
load resources; gemfmlib/gemmnlib/gemgraf implement local interaction and
rendering with scheduler dependencies. These dependencies must be split,
not copied wholesale into the shared library. Native CUIS must never expose
AESPD, EVB, WINDOW, GEM message arrays or kernel pointers.

Initial implementation and deployment
------------------------------------

CONF_WITH_LIBAES is off by default and initially depends on x32 and
CONF_WITH_ELF_SHARED. It selects the internal CONF_WITH_CUIS kernel support.
It does not require the old AES service or a desktop just to use sessions
and local geometry. ARM and m68k now have separate-address-space and
shared-linker configurations, but libaes and CUIS remain x32-only. Extending
them to those architectures and native m68k trap compatibility are later slices.

The build produces obj/libaes/libaes.so (SONAME libaes.so, SysV hash,
ordinary PIC ELF32/x32), installed with the LD.SO runtime at:

    obj/ldso/runtime/GEMSYS/LIB/X32/LIBAES.SO

A native executable links to -laes and the dynamic CRT, and records an
ordinary DT_NEEDED for libaes.so. No PT_PTOS_IMPORTS, fixed client image or
kernel symbol resolution is used. The transitional test interface is
lib/aes/native_bindings.h (private): aes_session_open/query/close and the existing local
inside/rc_constrain/rc_equal/rc_intersect/rc_union geometry helpers.
The library remembers its session in private writable data for normal
finalization. Kernel process teardown is authoritative on faults, _Exit
and any skipped library cleanup. Starting a session is idempotent for one
process. Handles never recycle during a boot, including end/restart by the
same process.

Native scalar session syscalls
------------------------------

include/cuis.h defines the x32 syscall class 0x103 and individual function
numbers. RAX contains (0x103ULL << 32) | function. Arguments are passed
flat in registers using the normal native RDI/RSI/RDX/R10/R8/R9 convention;
the result is returned in RAX. The session calls use only RDI, for a handle,
or no arguments at all. Unused registers are ignored. Kernel-mode calls and
builds without CUIS return EINVFN.

    Function  Call                    Success result
    --------  ----                    --------------
    0         session_start()         Non-negative session handle
    1         session_query(handle)   0 if the caller owns this live handle
    2         session_end(handle)     0 after revoking the caller's session

All calls return a negative GEMDOS error code on failure. The corresponding
libaes.so functions are aes_session_open(), aes_session_query(handle) and
aes_session_close(handle), with the same scalar results. There are no
parameter blocks, reply structures, version fields or feature negotiation.

Handles range from 0 through 0x7fffffff; zero is a valid handle. Session
start returns an existing handle if the caller is already registered, or
allocates one session. The allocator stops at the signed 32-bit limit so
success can never be mistaken for a negative error. Sessions are bounded
to one per process; no session call yields or waits.

The kernel validates the full-width handle slot before narrowing it.
Out-of-range handles return EINVAL; foreign, stale or missing handles
return EACCDN. Unknown function numbers return EINVFN, and allocation or
handle-space exhaustion returns ENSMEM. A failed allocation publishes no
session and consumes no handle. The current kernel process establishes
ownership; a handle grants no authority over another process's session.

This compiles the production session service for host tests of scalar

Caller-local GEM object operations (#679)
----------------------------------------

libaes.so exports objc_add(), objc_delete(), objc_order() and objc_offset()
over the application's own native OBJECT array (24-byte entries on x32).
These are ordinary C functions and need no CUIS session. No tree, object
specification or output pointer crosses a syscall boundary. Resource loading,
rendering and hit testing with display metrics are subsequent slices.

The #730 slice adds objc_find() and mt_objc_find(), plus mt_* forms of the
editing/offset calls above, with standard GEM signatures. Hit testing uses
logical object rectangles in screen coordinates, includes the starting object
at depth zero, excludes hidden subtrees, and gives later siblings precedence.
Each child list is scanned once before descending into its last matching
child, keeping traversal linear without recursion or temporary arrays.
Right/bottom edges are exclusive. A non-root start includes its ancestor
offsets. No hit (or a negative start/depth) returns -1. The search is iterative
and does not invoke USERDEF callbacks or dereference object specifications.
These local mt_* calls ignore the global array and need no registration.
Trees must have valid GEM parent/sibling links; invalid pointers fault in
userspace. 3D hit areas follow native expansion rules, including outlined objects and
the logical hit rectangle used for shadowed objects.

With CONF_WITH_LIBAES enabled, the algorithms in aes/shared/gemobjtree.c are
also used by kernel AES. With the feature disabled, the original kernel
implementations and object list are retained unchanged.
Parent/sibling links retain GEM conventions: a parent's head and tail name
its first/last child, the last child's next points to the parent, the root's
next is NIL, and an empty child list has head/tail NIL. Deleting an object
unlinks its subtree without destroying its contents; adding attaches it at
the end of the destination parent's children. A detached object's next field
is not reset by deletion; objc_add assigns its new parent link.

objc_order uses zero-based sibling positions; NIL (-1) means the end.
Invalid positions return zero before modifying links. Reordering an only
child preserves both the parent's head/tail and the child's parent link.
Root deletion/reordering fails. objc_offset accumulates the object's and
its ancestors' relative coordinates into the caller's WORD outputs. These
functions return one on success, zero on rejected operations, following the
GEM C API rather than the CUIS syscall error convention.

As with ordinary GEM C functions, the caller supplies a valid array and tree
links. Local routines do not copy or register it in the kernel. An invalid
pointer faults in user mode, and process teardown releases that client's
CUIS session. The kernel diagnostic wrapper for legacy ob_delete remains
outside the pure shared core.

The host and real ring-3 tests share tests/cuis/objects.c. They cover nested
coordinates, subtree relocation, head/middle/tail deletion and ordering,
invalid positions without mutation, single-child ordering and preservation
of object specifications. The dynamic client also calls objc_offset with
an unmapped pointer: only that child faults, and its parent continues.

When CONF_WITH_DYNAMIC_DESK and CONF_WITH_LIBAES are enabled together,
EmuDesk links its public objc_add/objc_order/objc_offset calls through
DT_NEEDED libaes.so, rather than defining GEM trap wrappers for them.
Internal desktop geometry helpers use the same extracted core. Other
AES operations continue through the existing adapters during migration.
Static desktops and builds without libaes retain their existing bindings.

Native window metadata (external libaes only)
-------------------------------------------
CUIS class 0x103 now reserves these flat-register calls:

  3 CREATE     RDI=x, RSI=y, RDX=width, R10=height
  4 CONFIGURE  RDI=window, RSI=x, RDX=y, R10=width, R8=height
  5 DESTROY    RDI=window

CREATE returns a non-negative window handle or a negative GEMDOS error.
CONFIGURE and DESTROY return zero or a negative GEMDOS error. Unused slots
are ignored. The current process must have an open CUIS session; a session
handle is not repeated in these calls. Window and session handles occupy
separate namespaces. libaes exports aes_window_create/configure/destroy;
these native calls do not yet implement the GEM wind_* API.

Window handles are never recycled during a boot. Only the owning process
may configure or destroy a window. A missing session, unknown/stale handle
or foreign window returns EACCDN; malformed active register slots return
EINVAL. A maximum of 64 windows per session bounds kernel allocations;
quota, allocation and handle exhaustion return ENSMEM without consuming a
handle. Closing a session or exiting/faulting frees all its windows.

Geometry arguments are sign-extended 32-bit integers. Origins may be negative;
extents must be positive and the exclusive right/bottom edges must fit in a
signed 32-bit integer. Invalid configuration leaves the old geometry intact.
These windows are metadata only: creation does not show a window, draw or
change focus. Visibility, Z-order and redraw polling are described below;
clipping, rendering coordination and event delivery remain subsequent work. No legacy AES window state is changed by these calls.
All new kernel paths compile only with CONF_WITH_CUIS, selected by the
external CONF_WITH_LIBAES feature.

Visibility, stacking and damage
--------------------------------------
Additional calls in CUIS class 0x103 each take the window handle in RDI:

  6 SHOW     insert a hidden window at the front
  7 HIDE     remove a visible window
  8 RAISE    move a visible window to the front
  9 LOWER    move a visible window to the back

All return a negative GEMDOS error on failure. SHOW/HIDE/RAISE/LOWER return
zero on success. libaes exports aes_window_show/hide/raise/lower.
Unused registers are ignored; ownership and full-width handle validation
are identical to the earlier window calls. SHOW on an already-visible
window and HIDE on a hidden one are no-ops. RAISE/LOWER on a hidden window
return EINVAL. Raising the front window or lowering the back window is a
no-op. CONFIGURE with identical validated geometry is also a no-op and
preserves pending redraws. New windows start hidden with no pending redraw.

CUIS maintains one front-to-back list across registered processes, separate
from the legacy AES window manager. Showing, hiding, moving, resizing,
reordering or destroying a visible window conservatively marks every
remaining visible CUIS window for a full redraw. Showing also marks the
newly visible window. Hidden windows retain no redraw indication; their
next SHOW schedules one. Repeated changes coalesce. Invalid operations
leave both order and pending redraws intact. Closing a session or exiting
removes all its visible windows and marks surviving windows for redraw.

Damage is observed through EVENT_WAIT or managed NOTICE_PEEK and delivered
through NOTICE_PUBLISH. Libaes constructs the GEM redraw bytes. Publication
clears the matching notice only after successful stream admission; failed
copyout or queue pressure leaves it pending. DISPLAY_LOCK controls drawing.

Visible-region snapshots and display ownership
---------------------------------------------
Production drawing uses DISPLAY_LOCK for recursive session-owned display
coordination and WINDOW_REGION for visible rectangles. Libaes applies GEM
window and workstation clipping policy. There is no separate per-window
kernel update owner or second clipping ABI.

WINDOW_REGION subtracts higher visible windows from the physical display
intersection. Rectangles are disjoint and positive; touching edges do not
occlude. A fully covered or off-screen window has an empty list. Allocation
or bounded intermediate fragmentation overflow returns ENSMEM with no
published replacement. All outputs are validated before copying. Failed
FIRST copyout leaves a held list intact; NEXT continues its immutable list
while DISPLAY_LOCK is held. FIRST explicitly refreshes it. Session exit and
final display release reclaim the associated lists.

Physical display and native VDI integration
-------------------------------------------
WINDOW_REGION intersects windows with the current physical display before
subtracting higher windows. Libaes consumes these rectangles and supplies
explicit drawing clips. The VDI renderer additionally applies physical and
signed-coordinate limits and the workstation clip to screen writes.

CUIS clients require owned DISPLAY_LOCK for checked native screen writes;
a foreign display owner returns EAGAIN and an unowned client returns
EACCDN. This is display-wide drawing permission. Window-specific clipping
belongs to libaes and its WINDOW_REGION iterator. Attribute setters remain
available without drawing ownership.

Whole-screen reads remain allowed for every app, including screenshot apps:
VDI pixel reads do not require CUIS display ownership and are not restricted
to a window or its unoccluded area. Normal physical-coordinate and output
memory validation still apply. A screenshot may read while another client
holds display ownership. Screen-copy source pixels are likewise unrestricted.
Screen-to-screen copies by CUIS clients require owned display access and clip
only the destination. Rows and disjoint row segments are processed in
memmove order so overlapping copies do not overwrite later source pixels.
Workstation clipping still restricts destination writes and is restored.

Non-CUIS native VDI clients retain their previous drawing behavior when no
display owner is active. These changes do not retrofit the legacy AES
service or its direct kernel drawing, and are not a sandbox for all legacy
interfaces. The external desktop still uses its legacy session path while
GEM window/form/menu migration continues. Screen-to-memory raster binding
coverage follows the existing VDI implementation; whole-screen read access
is permitted independently of that binding's supported operations.

All new VDI policy, clipping and copy paths are under CONF_WITH_CUIS. With
external libaes disabled, the original native VDI paths remain in use.

Native workstation lifetime under external libaes
------------------------------------------------
Native OPEN/CLOSE operate on process-owned virtual workstations. If native
VDI needs to initialize the physical workstation, it preserves the console
and framebuffer instead of implicitly entering graphics mode and clearing
the screen. Once initialized, that physical workstation stays available
when the last client closes, fails to open a virtual handle, exits or faults.
Client cleanup still frees every owned virtual workstation and callback.

The kernel display/legacy AES path retains responsibility for explicit
physical-workstation and console transitions. Before reopening an active
physical workstation, a production handoff closes the old workstation
without an intermediate console clear. This removes timer/mouse hooks and
invalidates old virtual handles before installing new hooks, preventing
the timer from chaining to itself. Native clients must reopen virtual
handles after a kernel physical-display reinitialization.

A native screenshot client can
open a virtual workstation and read the whole screen during another client's
update without clearing the display or switching console mode. Kernel-only
memtest fixtures can explicitly reset an idle service-owned physical
workstation when changing synthetic display dimensions; those resets also
preserve the console. With external libaes disabled, physical workstation
lifetime and console transitions retain their original behavior.

Focus ownership foundation
--------------------------
CUIS_FOCUS_QUERY takes an owned window handle and returns 1 if focused, 0
if not, or a negative GEMDOS error. Malformed full-width handles return
EINVAL; absent sessions and unknown/stale/foreign handles return EACCDN.
No foreign focus handle is exposed.

libaes configures managed activation through WINDOW_POLICY. Showing or
raising a managed window transfers focus; lowering the focused managed
window selects the new front window. Unmanaged windows retain their
existing stacking behavior. Raising an already focused front window is a
no-op. Actual focus changes mark visible windows for redraw.

Hiding/destroying a focused window transfers focus to the remaining front
visible window, or clears it if none remains. The same rule applies while
closing sessions and reclaiming normal, raw-exit or faulted processes. A
focus pointer is always removed before its window is freed. Removing an
unfocused window does not change focus.

Focus QUERY remains available while display ownership is held. Managed
activation is driven by the existing libaes window policy and trusted input.
All kernel focus state remains under the external libaes configuration.

Focused keyboard queues and atomic waits
---------------------------------------
Trusted keyboard input is consumed through SESSION_WAIT and its INPUT_RESULT
snapshot. A ready wait commits one key; a rejected result copy leaves that
snapshot available for retry. EVENT_WAIT(CUIS_EVENT_KEY) observes readiness
without consuming keys. There is no separate private native keyboard read.

Each window has a fixed 16-key FIFO. The existing BIOS keyboard translation
feeds the focused window through an IRQ-safe, allocation-free producer.
Values retain the BIOS representation: translated character in the low
word, scan code in bits 16-23, modifier state in the high byte. Interpretation
belongs in libaes. There is no CUIS syscall for posting synthetic keyboard
input. Consumed keys do not also enter the legacy BIOS input queue. A full
focused queue drops the newest key and still consumes it, preventing overflow
from exposing another application's input to legacy consumers. With no CUIS
focus, normal BIOS input behavior is retained.

Focus transfer clears both the old and newly focused window's queues;
release, hide, destruction and exit cannot leave stale input for a later
focus owner. Repeating a request for the already-focused front window keeps
its queued input. Publication/removal of the focus pointer and queue updates
use the selected interrupt backend, so keyboard IRQs cannot retain a pointer
to a freed window. IRQ code neither traverses client lists nor allocates.

READ validates and backs writable output memory before its short queue
transaction, then rechecks focus. Copyout failure leaves the oldest key
queued for retry. Empty reads do not inspect the output pointer. WAIT checks
focus, queue and deadline with interrupts masked, then uses the x32 atomic
STI/HLT/CLI sequence to sleep and recheck. Pending input cannot land between
an empty check and sleep without waking the caller. Entry interrupt state
is restored on return. Positive timeouts use the 200 Hz monotonic tick with
a guard for the current partial tick, avoiding early expiry; deadlines use
unsigned differences so counter wraparound is supported. A queued key takes
priority over timeout at a wake boundary.

An empty blocking wait while the caller owns a display update returns
EACCDN; zero-time polls and already-pending input remain available. This
prevents sleeping indefinitely with the drawing update held. Focus loss
observed after wake returns EACCDN. Managed kernel tasks block only the caller and
let another runnable client execute. Outside a managed group, waits retain
the native IRQ sleep path. No legacy AES scheduler or userspace daemon is
added; asynchronous public process-launch integration remains later work.

All kernel input state, BIOS hooks and the selected interrupt/wait backend
compile only with CONF_WITH_CUIS, selected by external CONF_WITH_LIBAES.
Kernel memtests inject one translated key from a real timer IRQ after the
wait reaches its sleep path and verify it does not enter the BIOS queue;
no user-callable test injection interface is exposed.

Pointer routing and combined waits
----------------------------------
EVENT_WAIT takes an owned window, an event mask and a sign-extended LONG
millisecond timeout. libaes uses it for native window-control dragging.
INPUT_STATE supplies current absolute screen coordinates, button bits and
modifiers. SESSION_WAIT with INPUT_BUTTON commits input from event history;
INPUT_RESULT returns the retryable snapshot. A press and release delivered
before the waiter resumes therefore retain the historical button result.

A trusted relative mouse packet is clamped to the physical display and live
VDI viewport. Hit testing uses the topmost shown window and half-open bounds.
Pressing a CUIS window focuses it without raising it and implicitly captures
all pointer input until every button is released. A legacy drag begun outside
CUIS remains legacy through release. Hiding, destroying or exiting a capture
owner suppresses the remaining gesture until release, preventing orphan
button releases from reaching another recipient. Enter/leave snapshots also
track window visibility, geometry and Z-order changes. CUIS-owned input keeps
the visible VDI cursor moving without publishing legacy motion/button or
native VDI input callbacks. Input outside CUIS retains existing behavior.

Each window has a resident 16-snapshot FIFO. Consecutive pure motion snapshots
with matching buttons and inside state coalesce. Button edges and inside
transitions remain ordered. Overflow discards the old FIFO, reports ERANGE
once, and retains a current-state snapshot with no asserted button changes;
callers must resynchronize their gesture state after ERANGE. The per-session
64-window limit remains; a global 256-window limit bounds allocation-free IRQ
hit testing and focus redraw work. Creation beyond either limit returns
ENSMEM. No userspace synthetic-input entry point is added.

EVENT_WAIT accepts any nonempty combination of CUIS_EVENT_KEY (1),
CUIS_EVENT_POINTER (2), and CUIS_EVENT_REDRAW (4). It returns 1 if any requested
source is pending, 0 on timeout, or a negative error; it consumes nothing and
returns no event mask. Callers poll their requested sources after waking.
Pointer overflow counts as pending; redraw remains pending until its managed notice is published. KEY-only waits require focus; mixed waits can observe pointer/redraw in
a background window, while keyboard readiness still requires focus. Windows
must be shown. Unknown mask bits and malformed timeouts return EINVAL.
Zero timeout polls, -1 waits indefinitely, and other negative or noncanonical
timeouts fail EINVAL. Blocking while owning an update fails EACCDN. Predicate checks and
sleep use the same IRQ exclusion, avoiding lost wakeups between sources.

Host tests exercise ownership, capture, enter/leave, coalescing, overflow,
copyout failures, cancellation, legacy drags and global bounds. Kernel tests
inject press/release packets from a real timer IRQ after an empty mixed wait
has reached sleep, and check cursor movement, legacy callback isolation and
owner teardown in both display-backed and headless configurations. Guarded
show/hide/redefinition keeps logical coordinates synchronized and flushes
deferred cursor movement when the outer guard ends. CUIS packets invalidate
queued legacy motion/cursor notifications and advance a generation checked
before applying an in-flight native motion callback's result. IRQ fixtures
cover guarded motion and reject an older callback completion after CUIS input.

Peer messages use the opaque STREAM_WRITE/READ/PEEK services. Message
readiness composes through SESSION_WAIT with CUIS_READY_STREAM and a byte
minimum. No separate four-word message queue or message EVENT_WAIT bit exists.
Native process/scheduler fixtures exchange explicit application packets over
these active streams; a packet's reply endpoint is payload, not authenticated
kernel provenance. Public GEM messages remain libaes policy.

Kernel-managed native task scheduling
-------------------------------------
CONF_WITH_CUIS selects the hidden CONF_WITH_NATIVE_SCHED option. Generic
process scheduling and MiNT process calls use that option, while GUI
services retain CONF_WITH_CUIS guards. Initially Kconfig limits the native
scheduler backend to x32 with separate address spaces. It reuses the
existing process-context save/restore implementation, without AESPD/EVB/UDA
state or the legacy AES dispatcher. No userspace daemon or application-facing
CUIS scheduling syscall is introduced. Standard asynchronous calls within
managed groups and ordinary launch integration are described below. Full
GEM appl_*/evnt_* adapters remain separate work.

The kernel-only ksched_run() accepts up to eight distinct, already prepared,
unlaunched processes and runs the group until all tasks finish. Allocation
failure before launch leaves all programs with the caller. A successful run
consumes them and returns each exit status. Every task gets a private kernel
bootstrap stack, separate from its process's syscall stack; both outlive
suspended continuations and are reclaimed only from another live stack.
The synchronous group launcher stays alive until every task exits, so its
children never retain a freed parent. Dynamic children use the standard
process calls described below; the kernel group controller stays alive until
every descendant finishes.

CUIS keyboard, combined event and session-message waits publish a bounded
kernel-state predicate while IRQs are masked and suspend the current task.
The scheduler scans at most eight predicates in round-robin order and runs
another ready task. Message/input/redraw readiness, focus or visibility loss,
and timeout expiry all resume the waiter, which rechecks its original
conditions. If every task is blocked, the root context uses STI/HLT/CLI after
the predicate scan, avoiding a lost IRQ between checking and sleeping.
Unmanaged waits keep the existing atomic IRQ sleep path. Pending events,
zero-time polls and owned-update restrictions keep their previous behavior.

Context transfer preserves the active process, page tables, syscall and IRQ
stacks, saved user RSP, GS syscall state, launch nesting, disk-error recovery
buffer, FPU/SSE state, IRQ state and managed-task identity. Legacy AES saves
and restores that identity with its coroutine contexts; new accessory
coroutines are unmanaged even while a foreground group is active. Their
Syield is a no-op and async launch is rejected, including from their nested
synchronous children. Returning to a managed foreground restores its task.
Identities are never reused across task slots or groups, so an obsolete
context cannot attach to a later task. Desktop boot tests exercise both the
unmanaged accessory path and managed launch/wait after AES returns.
A nested synchronous Pexec stays in the
same task and may itself block in CUIS; child exit/fault returns through its
normal launch continuation. Scheduling is cooperative at blocking CUIS
waits, child waits and explicit Syield calls. Busy clients are not preempted
and still require cooperative scheduling points.

Boot fixtures run two isolated standard-ELF/libaes clients through 64 message
exchanges, with private data/library state and SSE checks. They also exercise
focus-loss wakeup, all-blocked timeouts, a nested child's timed wait, normal
exit, _Exit, faults, group bounds/duplicate rejection, allocation failure
before launch and exact allocator/resource reclamation. Clients discover
fixture labels through the existing directory and exchange stream packets;
there is no kernel bootstrap transport or additional application API.

Standard asynchronous process calls in managed groups
---------------------------------------------------
With CONF_WITH_NATIVE_SCHED, managed x32 clients use ordinary MiNT GEMDOS calls:

 Pexec(100, path, tail, env)  load and asynchronously launch; return child PID
 Pexec(106, name, bp, env)    asynchronously launch/free a caller-owned loaded
                            basepage; return child PID (name/env unused)
 Syield()            0x0ff  cooperatively run another ready task, return E_OK
 Pwait()             0x109  Pwaitpid(-1, 2, NULL)
 Pwait3(flags, usage) 0x11c  Pwaitpid(-1, flags, usage)
 Pwaitpid(pid, flags, usage) 0x13a

These are standard process interfaces, not new libaes APIs. Pexec modes
0/3/4/6 retain their synchronous/load behavior. Pexec(100/106) require a
managed caller; elsewhere they return EINVFN. Ordinary native Pexec(0/4/6)
starts a single-root group when none is active, so launched shells and
applications can use async calls without custom setup. ROM/kernel-code and
explicit accessory entry paths keep their existing launch behavior; nested
synchronous Pexec stays in the active task. Mode 104 is EINVFN: its
FreeMiNT shared-address-space/thread semantics must not be presented as an
isolated process launch. No fork, signals API, stopped jobs or preemption is
added. Syield outside a managed task is a successful no-op. Preemption,
Pfork and other architecture backends are follow-up #713.

Ordinary group startup allocates its task array and bootstrap stack before
transferring retained basepage/environment ownership or entering user mode.
Pexec(4) keeps caller ownership and its existing image-return semantics;
Pexec(6) transfers ownership only at task entry. A startup allocation failure
leaves retained blocks freeable, and Pexec(0) cleans up its failed launch.
The controller waits until every descendant exits, even if the root program
has already terminated. The original root's full synchronous exit status
is returned, independently of later orphan exits. Boot tests cover all three
entry modes, retained blocks and failures of both group allocations.

The original group slots stay reserved until group completion. Remaining
slots admit dynamic children, including zombies, up to the eight-slot group
bound. A full group returns EAGAIN; allocation failure returns ENSMEM. Mode
100 unwinds a failed load/launch completely. Mode 106 transfers ownership
only after successful preparation; pre-publication failure leaves its
basepage/environment with the caller. As with existing image-adoption
failures, a preparation failure may invalidate the loaded image, but retained
blocks remain freeable. A successful launch revokes the loader's mappings
of the child's basepage/environment before returning, so it cannot rewrite
those blocks or free them while the child runs.

Pwaitpid currently accepts a positive child PID or -1 for any direct child.
Process-group selectors (0 and values below -1) return EINVFN until process
groups exist. Flag bit 0 is WNOHANG: return 0 when matching children exist but
none has exited. Bit 1 is accepted; there are no stopped children to report.
Unknown flag bits return EINVAL. With no matching unreaped child, return
EFILNF, as documented for MiNT. A blocking wait suspends only this task.

On success, the PID occupies bits 16-31 and native MiNT status occupies bits
0-15: normal Pterm status is narrowed to its low eight bits; CPU/process
faults report the terminating signal number in bits 8-15. This is MiNT's raw
format, not the POSIX byte order used by a libc wrapper. Optional usage is
two 32-bit LONGs (user/kernel milliseconds), using the existing approximate
process-usage accounting, with system time zero. Invalid output returns
EIMBA without consuming the zombie, and successful copy/reaping happens once.
Reaped child usage is charged to the waiting parent. No pointer is inspected
when there is no status to return.

A child PID remains reserved after KPROC destruction until reaping or orphan
cleanup, preventing PID reuse from aliasing an unread status. Logical parent
identity is separate from its kernel launch continuation: Pgetppid reports
the spawning process while it lives, then the long-lived group controller.
Only a read-only ancestor snapshot retains historical parent information;
the child's supervisor exit mapping pins the controller, not the original
parent. Parent exit clears ownership of live children and zombies. Orphans
continue running and are automatically reclaimed on exit. The group returns
only after all runnable/blocked descendants finish; no freed parent basepage
is used as an exit continuation.

Boot fixtures exercise asynchronous return, Pgetppid, explicit yield,
blocking/nonblocking/any-child waits, one-time reaping, normal/raw/fault
status, invalid and read-only usage outputs, loaded-basepage ownership and
mapping revocation (Maccess), group exhaustion with freeable unlaunched
blocks, slot reuse, nested or raw-image launch, normal/raw/fault parent exit, and abandoned
zombies. With native VDI callbacks enabled, a parent invokes its blocked
child's callback, survives the child's UD2 fault, then reaps SIGILL after
the child's deferred termination. Every cycle checks process/task memory,
file/directory references and CUIS sessions.

Public GEM lifecycle and timer bindings (#717)
-----------------------------------------------
The ordinary shared library exports appl_init, appl_exit, appl_yield,
evnt_timer and appl_getinfo, with matching mt_* forms, aes_global[15],
gl_apid and gl_ap_version. include/gem.h declares this implemented subset;
the same application fixture also compiles against GEMlib's normal headers.
This is the first public adapter slice, not a complete GEM AES replacement.
Discovery and application pipes are described below. Message/timer combinations are described below; window/input event adapters
remain subsequent work. At that stage aes_session_*/aes_window_* exports
remain transitional test/migration interfaces, not application requirements.

appl_init implicitly opens the caller's CUIS client and returns its distinct
AES client ID (1..32767), or -1 on failure. This ID is not a PID or TID. Opaque
CUIS handles remain private and are never truncated to produce application
IDs. Repeated initialization reuses the process registration. The caller's
15-word global array is initialized with AES global-layout ABI 0x0400,
multitasking sentinel -1 and its application ID; other slots are
zero until their facilities migrate. This ABI value does not claim complete
AES 4 functionality. Unsupported appl_getinfo queries return 0 and clear their output words;
implemented discovery/polling queries are described below. Optional
MultiAES/MagiC/XaAES query results follow implementation and behavioral tests.

The mt_* forms use the supplied AES global array and the same process-owned
registration. Successful exit clears that array and the library's exported
globals, closes the session and returns 1. Invalid/stale state or transport
failure returns 0; negative transport errors never escape Boolean GEM APIs.
Ordinary finalization closes implicit sessions, while kernel teardown remains
authoritative for faults and _Exit. No new application setup is required.

CUIS_SESSION_DELAY (function 24) takes the owned session handle and an
unsigned 32-bit millisecond interval in flat registers; E_OK or a negative
error is its scalar result. It waits for time alone, without a window,
focus, or input/message consumption. A positive interval is rounded up to
200-Hz ticks with a guard tick, including tick-counter wrap; all intervals
through 0xffffffff ms are accepted. Zero yields once. Positive delays while
owning a display update return EACCDN, matching other blocking CUIS waits.
The library maps successful delay/yield to 1 and failure to 0. These native
calls add neither feature negotiation nor versioned request structures.

Host tests cover failure mapping, opaque-handle/application-ID separation,
caller globals, delay width/rounding/wrap, ownership, IRQ restoration and
queued messages. Real dynamic parent/child fixtures use the public GEM
calls, verify private globals, preserve a queued message across a timer,
and reclaim implicit sessions through finalization and _Exit.

GEM discovery and application byte pipes (#719)
-------------------------------------------------
libaes exports appl_find, appl_read, appl_write and evnt_mesag, including
mt_* forms with GEMlib-compatible prototypes. appl_init publishes the
executable basename as an eight-byte, space-padded label, folding ASCII
lowercase to uppercase and stopping at the first extension separator. The
kernel records only a bounded, unmodified basename (up to 32 bytes) and
opaque label bytes; GEM normalization remains in userspace. Anonymous
basepage-only programs need not have a name. Duplicate labels resolve to
the oldest still-registered session. Exit removes the label; reopening the
same PROCESS uses a fresh private handle and may receive a different AES ID.
A closed client ID can eventually be reused; private endpoint handles never
recycle and continue to protect blocked operations against replacement.

appl_find accepts normal eight-character names (short NUL-terminated names
are padded), NULL/upper-word-zero self lookup, and the MultiTOS 0xffff/PID
and 0xfffe/application-ID pointer selectors. Only registered peers convert;
missing, exited or unregistered applications return -1. Handles are resolved
and checked before conversion to a positive short AES ID; they are not narrowed.
The 0xffff selector converts a generic PROCESS PID to the lowest live AES
client ID among its endpoints; 0xfffe converts an AES ID to its generic
PROCESS PID. Ordinary discovery, writes and activation route by AES ID, never
PID. Several clients may share a PROCESS number/PID without aliasing.
Standard appl_getinfo AES_PROCESS (4) returns 1 with outputs 0,1,0,1:
cooperative scheduling, PID conversion, no appl_search, native rsrc_rcfix.
AES_INQUIRE (6) returns 1 with outputs 1,0,0,0, advertising APR_NOWAIT only.
Other queries remain unsupported; no protocol negotiation is introduced.

appl_write accepts the complete nonnegative short byte-length range
0..32767 and waits for enough queue space for the whole write. Input bytes
are captured before waiting. appl_read accepts the same lengths and blocks
until exactly that many bytes are available; ap_id must be the caller's ID,
or APR_NOWAIT (-1) to poll without consuming an insufficient prefix. Zero
lengths succeed without inspecting the buffer. evnt_mesag reads exactly
16 bytes; appl_read can then retrieve the excess described by the caller's
message header. Reads may cross write boundaries. All supplied payload
bytes are preserved, including caller-defined header words; the kernel
neither interprets GEM message types nor rewrites opaque byte streams.
Boolean APIs return 1 on success and 0 on error, not native negative errors.

Each receiver has a lazy 65536-byte payload ring and a parallel 16-bit sender
AES-client-ID ring (192 KiB total), independent of message/write boundaries. Partial
reads immediately free capacity. A transfer's 32767-byte maximum is below
half the byte capacity, avoiding metadata/packet fragmentation deadlocks
between exact reads and atomic writes. One pending write snapshot per
sender is bounded by the same transfer limit and is attached to its session
before user copying can fault. There are no unbounded packet lists. Native
sender metadata comes from the kernel and survives sender exit; it describes
the first byte read and is separate from peer-supplied GEM header contents.
Historical sender client IDs are not authentication of a currently live process.
Peer bytes do not manufacture trusted keyboard/pointer/redraw events.

All queued storage and pending snapshots are released on session/process
exit, including faults and _Exit. Failed input copies do not publish data;
failed read validation/copyout, including wrapped reads, consumes nothing.
Writer wait predicates retain only the non-reused receiver handle and
re-resolve it after every switch. Receiver close/exit wakes blocked writers
with an error; reopening, even under the same PID, cannot receive the old
pending write. Blocking operations which would sleep while owning a display
update fail with EACCDN. Ready/zero/poll operations retain their normal behavior.

Native CUIS calls use flat registers and scalar lengths/handles/errors:

 26 SESSION_LABEL(handle, bytes, length)   -> E_OK; opaque labels up to 32 bytes
 27 LABEL_FIND(bytes, length)             -> peer handle
 30 STREAM_WRITE(peer, buffer, length, block) -> exact byte count
 31 STREAM_READ(own, buffer, length, block, optional_sender_id) -> exact count

Invalid arguments/ownership and missing peers return ordinary negative
errors. block is 0 (EAGAIN when not ready) or 1 (wait). These GUI services compile only with CONF_WITH_CUIS;
PROCESS basename and identity snapshots are generic Ssystem services. Message/timer combined waits are described below; input/window integration
remains subsequent work.

Host tests cover lookup/ownership, capacity and allocation failures,
wrapped reads and copy failures, partial/cross-writer reads, captured input
mutation, historical sender metadata, update ownership and receiver exit.
Real dynamic GEM clients cover named and PID discovery, full-range and
split transfers, blocking backpressure, registration close/reopen, sender
exit and a receiver reopening while a pending write still targets its old
handle. Allocator/session/process snapshots verify complete reclamation.

GEM combined message/timer waits and state reads (#722)
-------------------------------------------------------
evnt_multi and mt_evnt_multi retain the complete standard GEM signatures.
This initially implemented MU_MESAG (0x10), MU_TIMER (0x20) and their
combination. The #741 input adapters below extend this to all six classic
GEM event sources. The following describes the original message/timer subset.
The result is the GEM mask of every ready requested source, including both
bits together; it is never a native negative error. Unsupported keyboard,
button, rectangle and extension masks, and an empty mask, return 0 before
waiting, consuming message bytes or changing caller outputs. Their proper
adapters follow window/input integration; requested events are not silently
dropped. Unrequested button/rectangle parameters and timer arguments are
ignored, as are message pointers when MU_MESAG was not requested.

A message requires at least 16 bytes in the application pipe. A partial
header cannot wake it, and the transitional four-word queue is a different
source. Native readiness consumes nothing; the library copies exactly the
16-byte GEM header only when ready, retaining any excess for appl_read.
Failed message copyout returns 0 and leaves all bytes unread. A timer-only
wait never consumes messages, including when its ignored message pointer is
invalid. Combined waits preserve one deadline across IRQs and scheduler
wakeups and use unsigned millisecond intervals through 0xffffffff, with
ceil-to-tick rounding, a guard tick and modulo tick-counter wrap.

With a zero timer, an already ready message returns both bits immediately.
Otherwise the zero poll yields once to cooperative peers, then checks all
requested sources again; a message produced during that yield is included
alongside MU_TIMER. A positive timer can expire alone, a message can arrive
first, or both can be ready at the same atomic kernel check. Blocking an
empty wait while owning a display update returns EACCDN; ready and zero
operations retain the existing behavior.

graf_mkstate and mt_graf_mkstate return a read-only logical mouse/button/
modifier snapshot for a registered caller. The same state fills successful
evnt_multi outputs, with key return and click count zero because those
input events are not implemented in this slice. Coordinates use signed
GEM shorts (saturated at their range), buttons are left/right bits 0..1,
and modifiers are the standard right-shift/left-shift/control/alt bits 0..3.
NULL scalar output pointers are accepted. No window/focus is required;
state reads neither invoke callbacks nor consume pointer/keyboard events.
Standard-vector snapshots follow synchronized Line-A state; custom-vector
snapshots use CUIS's initialized logical position/buttons, falling back to
Line-A before initialization. This includes packets consumed only by CUIS.
Invalid non-NULL scalar output pointers are ordinary userspace faults;
kernel teardown remains authoritative for cleanup.

CUIS_SESSION_WAIT (32) takes (owned_session, minimum_bytes, ready_mask,
unsigned_milliseconds) in flat registers and returns CUIS_READY_STREAM (1),
CUIS_READY_TIMER (2), their union, or a negative error. Masks must select
at least one source. minimum_bytes is 1..32767 when selecting the stream;
otherwise it is ignored. The interval is validated only when selecting the
timer. This is generic byte readiness/deadline handling, not a kernel GEM
mask or event parameter-block interpreter. CUIS_INPUT_STATE (33) takes the
owned session and four LONG output addresses for x, y, buttons and modifiers,
returning E_OK or a negative error. It backs all outputs before sampling one
logical state under IRQ exclusion. Kernel additions remain CUIS-configured;
there are no versioned blocks, feature negotiation or new public CUIS setup.

Host tests cover all source combinations, simultaneous/early readiness,
partial headers, opaque-queue separation, zero-yield arrival, full intervals,
wrap and unchanged deadlines, IRQ restoration, update ownership, snapshots,
mask/result mapping and copyout failures without consumption. Real dynamic
GEM clients cover ordinary and mt_* calls, header/excess reads, unsupported
masks, read-only message buffers, timed peer producers, zero-yield delivery
and scalar-output user faults with exact resource reclamation. Normal GEMlib
headers compile the same fixture; other AES/event families remain staged.

Final configuration cutover
---------------------------
Once external libaes is complete, Kconfig must make CUIS and in-kernel AES
mutually exclusive. In-kernel AES must also depend on !CONF_WITH_USER_ASPACE
on every architecture. Protected GUI kernels use libaes over CUIS; kernels
without separate address spaces can retain the traditional in-kernel AES.
Remove the superseded kernel AES entry paths and AES-specific user-object,
AESPB/tree validation and snapshot machinery at that cutover. Native CUIS
syscalls continue checking ownership, scalar arguments and user buffers.
Transitional combinations retain their validation until replacement libaes
behavior and boot/desktop coverage allow those entry paths to be disabled.


GEM plain-window lifecycle and geometry (#732)
--------------------------------------------

libaes exports wind_create/open/close/delete/get/set/calc and their standard
mt_* forms. This section describes the metadata/lifecycle foundation for
kind == 0 windows. Title/info frame rendering is added by #787 below.
Window messages/focus and stack/owner queries are added by #738 below. Desktop handle 0, foreign-window
geometry queries, sliders and other
fields remain unsupported (return 0 without changing outputs). Update locking and rectangle enumeration are added by #734 below. No additional
appl_getinfo capabilities are advertised by these slices.

Application code uses positive short GEM window identifiers, not CUIS handles.
CUIS_WINDOW_IDENTIFY (function 34) takes the owned native window handle in the
first scalar argument and returns a positive, globally unique live-window
identifier or a negative error. Identifiers range from 1 to the global window
quota (256); zero is reserved. They are stable while the window exists and may
be reused after destruction, as with ordinary GEM handles. Knowing an identifier
never confers ownership of its underlying CUIS window. Unused registers are
ignored; malformed/foreign/stale native handles fail ordinary ownership checks.
All kernel additions remain under CONF_WITH_CUIS.

Each library tracks up to 64 owned windows and maps the small identifier to the
full opaque native handle. Registration is required for window lifecycle and
queries. Repeated appl_init in the same session retains windows; successful
appl_exit or registration of a new session clears the local map. Kernel session
teardown reclaims all windows independently of library finalization, including
raw process exits. A failed close/delete preserves the map for retry.

wind_create returns -1 on failure, otherwise a positive GEM identifier. Its
rectangle is saved as WF_FULLXYWH; current and previous rectangles start zero.
Native hidden metadata uses an invisible positive-size placeholder because
CUIS geometry requires positive extents. wind_open configures then shows the
window and initializes both current and previous rectangles to the supplied
border rectangle. Opening an already open window and closing a closed window
return 0. A failed show leaves the window closed and its GEM rectangles intact;
its hidden native geometry may have been prepared for the attempted open.
wind_close saves the last current rectangle as previous and clears current.
wind_delete also accepts an open window, hiding and destroying it in CUIS.

wind_get supports WF_KIND, WF_CURRXYWH, WF_PREVXYWH, WF_FULLXYWH and
WF_WORKXYWH. wind_set supports WF_CURRXYWH, even while closed; only a successful
configure advances previous/current. Open and configure require positive border
width/height. Full geometry is retained exactly as provided at creation.
All ordinary results are GEM 1/0, never negative CUIS error codes.

For kind zero, wind_calc requires no registration. WC_WORK insets
the border by one pixel on each side, and WC_BORDER reverses that calculation,
matching classic GEM plain-window geometry. WF_WORKXYWH uses the same rule on
the current border rectangle. In particular, after wind_close the zero border
produces (1,1,-2,-2), matching the existing GEM AES close/draw_change/wm_calc
path; it is not clamped to an invented zero work rectangle. A closed window
can subsequently receive WF_CURRXYWH and reports the corresponding work area
without becoming visible. Unrepresentable signed WORD results fail without
wrapping or changing outputs. Outputs may alias inputs; optional
NULL outputs are ignored. Non-NULL invalid pointers fault in userspace.

Host tests cover full native handle bits, transport errors, retry/state retention,
quota exhaustion, session invalidation and standard source signatures. The
GEMWIN.TOS fixture checks actual flat syscalls, shared-library state, isolated
identifiers and raw-exit cleanup. Its standard window contract also compiles
against unmodified GEMlib headers.


GEM update locking and visible work rectangles (#734)
----------------------------------------------------

wind_update/mt_wind_update support END_UPDATE (0), BEG_UPDATE (1), and the
standard NO_BLOCK (0x100) modifier on BEG_UPDATE. A successful begin returns
1, a busy nonblocking begin or other failure returns 0. Locks nest per
registered process, including across different mt_* global arrays: only the
final matching end releases ownership. Unmatched/foreign ends fail. Mouse
control (BEG_MCTRL/END_MCTRL) uses independent mouse ownership (see #743 below),
not the screen update semaphore. Unknown codes return 0.

The screen semaphore freezes competing native window mutations and screen
writes, rather than tying an application to a single window. Standard window
mutations acquire/release it internally and nest inside an explicit update
section, as GEM permits. Ordinary begins block cooperatively; NO_BLOCK does
not dispatch or sleep. Timer/input/message waits are allowed while owning the
GEM semaphore, as required for modal interaction; applications remain
responsible for avoiding circular waits between peers.
Session close, normal/raw/fault exits release all nesting levels. Preemption
and other architecture backends remain future work under #713.

An owner holds the whole-screen update section and may paint dialog/menu
areas outside its windows. Native VDI writes remain clipped to the captured
screen bounds; other processes cannot write until release. Read/copy access
to the entire screen remains available to all apps, including screenshot
apps. Traditional in-kernel AES migration remains incomplete;
its final exclusion from CUIS kernels is still required at the epic cutover.

wind_get(WF_FIRSTXYWH) restarts a per-window iterator, and WF_NEXTXYWH advances
it independently of iterators for other windows. Each successful result is
intersected with the window's GEM work area and the screen, excluding all
higher windows' visual footprints. Nonempty rectangles do not overlap. A
closed/offscreen/fully covered window, or the end of the list, returns GEM
success 1 with width and height zero; x/y at end are not a sentinel contract.
Native allocation/copy/ownership failures return GEM failure 0 without
advancing the cursor or changing caller outputs. A new FIRST can retry.
NEXT before FIRST or after exhaustion returns an empty rectangle. Hold
BEG_UPDATE through the FIRST/NEXT loop to prevent changes by other apps;
restart FIRST after changing window geometry/visibility/stacking yourself.

Plain GEM windows reserve a two-pixel right/bottom shadow, matching existing
AES w_getsize(WS_TRUE)/newrect behavior. This footprint participates in
occlusion even though frame/shadow painting is still a subsequent rendering
slice. Work/border geometry returned by wind_get/wind_calc and native pointer
hit bounds exclude this visual outset. The kernel interprets only generic
native geometry; libaes sets the GEM shadow policy when creating a window.

Additional flat CUIS calls (all under CONF_WITH_CUIS):

  35 DISPLAY_LOCK(session, acquire, block) -> E_OK / negative error.
     acquire and block are canonical 0/1; release requires block=0. Ownership
     is checked against the current process, depth overflow fails, and exit

     be waited upon by its own process. Unused register arguments are ignored.

  36 WINDOW_REGION(native_window, index, x*, y*, width*, height*) -> 1/0/error.

     the caller to hold DISPLAY_LOCK. Read-only enumeration remains available

     While the caller owns DISPLAY_LOCK, index zero refreshes a per-window

GEM window messages, topping and focus (#738)
--------------------------------------------

Plain libaes windows now receive standard WM_REDRAW (20) and WM_TOPPED (21)
through appl_read/APR_NOWAIT, evnt_mesag and evnt_multi(MU_MESAG), including
mt_* forms. Messages contain eight GEM shorts: AES sender 0, extra length 0,
and the global short window identifier in word 3. Redraw bounds in words 4-7
conservatively cover the current work area (nonnegative extents); applications
still use wind_update and FIRST/NEXT to paint only visible rectangles. Topping
requests leave words 4-7 zero. Repeated notices for the same window/kind can
coalesce. Ordinary application pipe bytes keep their FIFO order and original
contents; converted system messages append to that same byte stream and can
be read in parts just like other GEM messages.

Opening a standard window makes it frontmost and gives it keyboard focus.
WF_TOP raises an owned open window and gives it focus, including an already
frontmost window; WF_BOTTOM lowers it and gives the new top window focus if
necessary. Hide/delete/normal/raw/fault exit of the focused window falls back
to the next visible window. Existing native test/migration windows keep their
previous explicit-focus behavior unless opted into client-managed activation.

Clicking a visible part of a background standard window sends WM_TOPPED; it
neither raises nor focuses the window automatically. Its application decides
whether to honor the request with wind_set(WF_TOP). The activating press and
matching release are consumed as a topping gesture rather than delivered as
ordinary button input. Existing pointer capture/release suppression remains
in force when that window hides or exits. Input is routed to the current focus
until the application actually tops the requested window.

wind_get(WF_TOP) ignores the input handle and returns top ID, owner AES client ID,
next ID below, and zero. WF_BOTTOM returns the bottom visible window ID,
excluding the desktop, with other outputs zero. An empty stack returns ID 0.
WF_OWNER accepts a live global ID (including another app's window) and returns
owner AES client ID, open status, ID above and ID below; closed windows report no
neighbors. Queries are read-only; they do not grant permission to mutate a
foreign window. Invalid/deleted IDs return GEM failure without changing
outputs. Native metadata is range-checked before conversion to GEM shorts;
invalid identifiers/client IDs or non-Boolean open status fail without truncation.
Foreign geometry and desktop handle-0 metadata remain later work.
No additional appl_getinfo extension bits are advertised in this slice.

Window move/size gadget requests, WM_NEWTOP and optional AES4
WM_ONTOP/WM_UNTOPPED notifications are not synthesized here. Decoration
interactions and their applicable GEM/MultiAES semantics migrate with the
renderer/input adapters. A programmatic geometry change or close does not
fabricate a user request to perform that same operation.

SESSION_WAIT adds READY_NOTICE=4 to the existing stream/timer readiness bits.

without dropping the pending notice. Blocking reads wait for either sufficient
stream bytes or notices; nonblocking reads pump once then return normally.
Timer-only waits never pump notices. Combined message/timer waits use one
native deadline and retain simultaneous readiness; an already pending notice
also prevents the unnecessary zero-timer yield.

Host tests cover high native handles, message layout, full-pipe backpressure,
source/destination failures, retained notices, simultaneous timer readiness,
background-click activation without premature focus, stack queries, display-
lock ownership and focus fallback. GEMFOC.TOS exercises isolated apps using
standard GEM source: redraw delivery, top/bottom operations, foreign owner
queries and close/raw-exit fallback. Existing GEMWIN/GEMUPD fixtures now accept
real redraw messages while waiting for their application control messages.


GEM keyboard, button and mouse rectangle events (#741)
-----------------------------------------------------
evnt_keybd, evnt_button, evnt_mouse and evnt_dclick now have standard and
mt_* bindings. evnt_multi/mt_evnt_multi support every combination of the six
classic masks: MU_KEYBD, MU_BUTTON, MU_M1, MU_M2, MU_MESAG and MU_TIMER.
An empty mask or an unknown extension mask fails with GEM 0 before any wait
or consumption. Unrequested parameters remain ignored. No new appl_getinfo
extension bits are advertised. Wheel/extended-key masks remain separate work;
mouse-control grabs are described in #743 below.

Keyboard waits belong to the application, following whichever of its windows
has focus; they can remain blocked while another application owns focus.
Native BIOS scan/ASCII keys become GEM words with scan code in bits 8-15 and
ASCII in bits 0-7. Keys are consumed only when requested and ready. Pointer
waits follow the focused application or existing pointer capture; background
activation gestures remain WM_TOPPED requests, not button input. A drag's
release predicates are sampled before capture is cleared, so another client's
focus change cannot steal the captured release. Activation-gesture releases
bypass that sampling. No untrusted application can inject hardware input.
Applications without focused windows
can still use message/timer waits and graf_mkstate.

A rectangle is half-open on its right/bottom boundaries. MO_ENTER waits for
inside, MO_LEAVE for outside; the predicate is also tested immediately, so no
new movement is needed if it already holds. Zero/negative extents are empty.
Both rectangles are tested independently and can complete together. Trusted
packet processing latches a matching crossing during an active wait even
when another packet reverses it before userspace runs.

Button equality is ((buttons ^ state) & mask) == 0. Clicks' low byte limits
the returned count; bit 0x100 reverses equality, as in classic GEM. Other
high-byte extensions (including 0x200) are not advertised and fail with 0.
A matching current state or queued transition completes the quick check;
a completed multi-click count is retained while the matching state is held,
including across later requests with smaller count limits.
Otherwise a pending multiple-click wait starts its click window on the first
matching transition. Additional matches extend the original window by three
200-Hz ticks, with a bounded count. Expiry is checked before admitting a
new press, so a delayed waiter cannot extend an already expired window.
Once a button result is ready, later edges enter history for the next wait.
The wait returns the actual count, capped by the requested maximum, after
the interval, including a single click when
a double click was requested. The matching position/button/modifier snapshot
is retained when a release follows. A bounded 16-edge per-session history
retains press/release pairs arriving between calls independently of the raw
native per-window pointer queues. A history scan consumes through the first
matching edge only, leaving subsequent transitions for later waits in FIFO
order, including alternating press/release waits. Trusted queued edges are
matched independently of current focus: a captured release arriving after a
focus handoff remains available to its original owner when it next waits.
Live predicates still require current mouse ownership. Overflow discards
oldest edges; ownership loss/hide clears old history. Zero requested clicks
return count zero.

evnt_dclick queries/sets the global standard rate index 0..4, corresponding
to 450, 330, 275, 220 and 165 ms; the initial rate is zero. A running click
window retains its original interval. Invalid set/rate parameters fail with
0 without changing it. All six event sources use a single native wait;
keyboard/message/timer completion cancels unfinished button accumulation.
Timer deadlines are never restarted by pointer traffic. Input already ready
also avoids the unnecessary zero-timer cooperative yield. Results include
all requested sources ready at completion; unrequested key/count outputs are
zero and optional scalar outputs may be NULL.

Native additions, all built only under CONF_WITH_CUIS:

  43 INPUT_RECT(session, slot_flags, x, y, width, height) -> E_OK / error.
     Flat signed LONG geometry. Slot_flags bit zero selects rectangle 0/1,
     bit one selects outside rather than inside. Other bits are rejected.

  44 INPUT_BUTTON(session, mask, state, maximum_count, invert, unused=0)
     -> E_OK / error. Mask/state are unsigned 16-bit, count 0..255, invert
     canonical 0/1. Configuration belongs to the calling session.

  45 INPUT_RESULT(session, key*, count*, x*, y*, state*) -> E_OK / error.
     Five separate validated LONG outputs from the latest input-enabled wait.
     Key retains native BIOS encoding; state contains button bits 0..15 and
     modifier bits 16..31. No request/reply structures cross the ABI. Re-reading
     is non-consuming, including after failed copyout; a later input wait
     replaces the snapshot. A completed wait transfers a ready key from its
     focused window queue into this session snapshot under IRQ exclusion.

  46 INPUT_INTERVAL(session, milliseconds, set, 0, 0, 0) -> interval / error.
     Generic global click interval, 1..5000 ms, canonical set=0/1. Query ignores
     the milliseconds argument. Public GEM rate indices remain in libaes.

SESSION_WAIT (32) additionally accepts native READY_KEY=8, READY_BUTTON=16,
READY_RECT1=32 and READY_RECT2=64. Stream minimum and timer interval validation
still apply only when selecting those sources. Configuration, initial checks,
IRQ event latching and the scheduler's test-and-sleep use IRQ exclusion; no
allocation or user-memory access occurs in that critical path. Active wait
pointers refer to resident syscall stacks and are cleared on completion/error;
process teardown removes the session before it can outlive that stack.

Host tests exercise full native handles, routing/ownership, historical presses,
reversed crossings, click timing and wrap, timer cancellation, all six sources,
GEM key encoding, signed geometry, optional outputs, copy failures, rate sharing
and teardown. GEMINP.TOS exercises normal shared-library GEM source in ring 3,
including immediate button/rectangle predicates, simultaneous message/input/
timer results and key timeouts. Hardware key delivery and delayed pointer
transitions are tested against the production CUIS core on the host.


GEM mouse-control ownership (#743)
---------------------------------
wind_update/mt_wind_update now implement BEG_MCTRL (3), END_MCTRL (2), and
NO_BLOCK (0x100) on begin. They return GEM 1 on success, 0 on error/busy.
Both standard and mt_* calls share nesting per registered session, independent
of their global array. The final matching end releases the mouse; unmatched
or foreign ends and NO_BLOCK on end fail without changing ownership.

Mouse ownership is independent of the drawing semaphore. BEG_MCTRL captures
pointer input across the entire screen, including outside owned windows and
for windowless dialogs. It does not grant drawing permission or change
keyboard focus, window stacking, or geometry. Applications use BEG_UPDATE
separately when they need to protect drawing. Ordinary message/timer/input
waits remain available during a mouse grab; whole-screen screenshot reads
retain their existing permissions. No additional appl_getinfo bits are
advertised by this slice.

During a grab, new pointer packets reach only the owning session's predicates
and private button history. Native pointer queues can follow an owned visible
window when present; no window is required by the standard GEM event bindings.
Clicks over foreign windows do not change focus, start another client's drag,
or send WM_TOPPED. A keyboard focus change or hiding the owner's last window
does not cancel modal mouse ownership or discard its new button history.
Previously routed input remains valid historical input for its original owner.

A begin blocks cooperatively until the mouse semaphore is free and any
foreign held drag ends. NO_BLOCK returns immediately with 0 instead. A caller
may acquire its own normal captured drag without deadlocking; activation
requests and legacy/foreign held gestures cannot be stolen. Nesting an already
owned grab succeeds immediately, even while buttons are down. Depth overflow
fails without wrapping. A wait blocked by contention retains IRQ exclusion
through scheduler publication, avoiding a lost wakeup. As with existing CUIS
waits use the same generic scheduler blocking mechanism.
The global standard update semaphore remains independent.

Final release and normal/raw/fault process exit release every nesting level.
If the mouse is still down, delivery remains suppressed until the matching
release; another application never receives an orphan release as new routed
input. No new grab can steal that held gesture. Once released, ordinary hit
routing resumes. Session handles are checked on every operation, so reopening
an application cannot inherit an exited client's grab.

Native call 47, MOUSE_LOCK(session, acquire, block), returns E_OK or a negative
error. All arguments are flat scalar registers: session is a nonnegative
31-bit owned handle; acquire/block are canonical 0/1, and block must be zero
on release. It is compiled and dispatched only under CONF_WITH_CUIS, selected
by external libaes on the supported backend. Native EAGAIN maps to GEM 0;
no native handles or errors escape through public wind_update bindings.

Production-core tests cover windowless input, focus and visible-window changes,
independent draw permissions, keyboard routing, nesting, malformed/foreign
requests, overflow, foreign-drag contention, owner exit, and held-button final
release suppression. Public binding tests cover mt forms, NO_BLOCK and failure
retention. GEMMCTL.TOS uses normal GEM source in isolated shared-library apps:
a windowless parent holds two levels, a windowed child remains blocked until
the final end, then raw-exits with a nested grab so the parent can continue.
Session exit/re-registration also proves cleanup. Resource snapshots and the
boot suite check that no mouse owner, window, session or allocation remains.


Userspace classic object drawing (#745, #748)
--------------------------------------------
objc_draw/mt_objc_draw and objc_change/mt_objc_change use their standard GEM
signatures and Boolean results. OBJECT arrays, INDIRECT specs, strings,
TEDINFO and USERBLK records remain in the calling application's address
space. The shared library reuses the original aes/ object painter,
traversal, state changes and GSX text/border/layout routines as separately
compiled C units in aes/shared/. Shared resource loaders and object-tree
helpers live there too. The same drawing sources build into native AES and
libaes; internal headers declare their interfaces and bind libaes to a
private drawing context. Only the low-level VDI transport and drawing
context have userspace bindings; the kernel receives only existing bounded
VDI primitive requests and never an object-tree or callback pointer. No new
production kernel service or configuration option is needed.

This first drawing slice supports classic G_BOX, G_IBOX, G_BOXCHAR,
G_BUTTON, G_STRING, G_TITLE, G_TEXT, G_BOXTEXT, G_FTEXT, G_FBOXTEXT and
G_USERDEF objects. It implements signed border thickness, box color/pattern
words, default/exit button borders, IBM/small fonts, text justification,
formatted underscores, and
SELECTED/CROSSED/CHECKED/DISABLED/OUTLINED/SHADOWED states. The original
text routines use bounded buffers: free text is limited to 127 characters,
and formatted text and templates to 80 characters in this slice. Formatting
recognizes the '@' empty-text marker without modifying caller text. G_IMAGE
and monochrome G_ICON are also supported: the original icon painter in
shared/gemicon.c preserves mask/data layering, labels and character overlays,
WHITEBAK and selected colour swapping. Native 3D flags and objc_sysvar are
also supported (see below). A preflight
checks the requested visible subtree before painting, so an unsupported
visible descendant does not leave a partly drawn tree; HIDETREE descendants
are ignored. Each visible payload is checked again immediately before painting,
since USERDEF can mutate later siblings. An oversized callback-mutated payload
fails with GEM 0 before buffer copies.

Bitmap words remain in userspace. The GSX adapter clips the destination and
source bounds before reading, and submits only horizontal runs of set bits
as existing solid VDI fills. Zero bits leave previous pixels untouched,
including holes in icon masks; mask and image passes retain their original
order and colours. BITBLK row widths must be positive even byte counts, no
more than 4094 bytes (so their bit width fits WORD); source offsets must lie
inside the form. Icon widths are positive multiples of 16. Each form is
limited to the existing 1 MB bitmap bound. Invalid descriptors fail with GEM
0 before painting, and visible descriptors/labels are revalidated after
USERDEF callbacks. Icon labels use the same 127-character bound as other
free text. Translated icon bitmap, label and character origins must fit
WORD before the shared legacy painter stores them; nonempty label rectangles
must also retain representable extents for text layout. Unrepresentable sums
return GEM 0 before painting, including geometry changed by USERDEF. This
check uses the actual traversal coordinates immediately before painting.
Subtree preflight resolves the starting offset once and carries parent
coordinates through its linear walk; it does not scan ancestors per node.
Nonzero image source offsets restrict reads to the remaining
source rows/columns; no trailing source storage is inferred.

Drawing starts at the requested object using its absolute tree offset,
visits children in sibling order through the requested depth (0..MAX_DEPTH),
skips hidden subtrees, and clips to the supplied GEM rectangle and screen
bounds. Child objects are not implicitly clipped to their parent's logical
rectangle. Hidden objects are rejected before reading their payload or
INDIRECT pointer. Fills and oversized border segments are intersected with
the painter clip before VDI submission, preserving the original edges rather
than drawing new edges along the clip boundary. Userspace fill endpoints,
expanded object bounds and box/outline border coordinates remain LONG until
clipped, including maximum-WORD widths and heights. The shared border loop
retains the WORD calling convention in native builds. Fully clipped text is
culled before VDI submission. Partially clipped runs drop complete off-
screen cells while preserving the original positions of the remaining
glyphs. An empty clip succeeds without painting. objc_find applies native 3D
hit expansion.

Drawing obtains a nested standard display update section and releases its
own nesting level after rendering.
Each draw opens a private virtual VDI workstation, preserving application
workstation attributes. The kernel's existing CUIS draw policy still
enforces display ownership; applications use FIRST/NEXT visible-region clips
when drawing their windows. Screenshots remain readable across the whole
screen. The private workstation and implicit update level are released on
normal/error returns. A captured session handle releases the update even if
USERDEF changes the GEM global array. Process-exit cleanup reclaims
workstations and ownership after a user fault. A headless kernel without the
VDI service returns GEM 0 cleanly. The VDI service removes a visible cursor
before each framebuffer write and recomposes it afterward using a non-
resetting show. Already-hidden cursor nesting is preserved. This also
protects USERDEF VDI drawing; the shared GSX cursor hooks need no
application-controlled global cursor commands.

objc_change ignores its reserved argument, updates caller-local state, and
redraws only that object when requested. No-redraw and hidden-object state
changes require no VDI access. The original classic AES state-change routine
repaints icons to swap their foreground/background colours. Other classic
objects use a clipped XOR of the interior whenever SELECTED changes, including
combined state transitions; otherwise it repaints the object. Deselection
restores preceding pixels, including transparent objects. A failed redraw
restores the old state; drawing errors cannot undo pixels that were already
painted. Unchanged state is a successful no-op.

USERDEF runs as an ordinary user-mode call with the standard PARMBLK tree,
object, previous/current state, absolute geometry, clipped rectangle and
ub_parm. Its returned remaining-state mask controls AES overlays. Nested
object drawing uses a separate local painter/workstation and nests the
update lock. objc_draw skips callbacks outside the visual clip; objc_change
follows the original direct callback behavior with the current clip in
PARMBLK. Hidden callbacks are not invoked. Invalid caller pointers or
callback faults are ordinary user faults, with kernel process cleanup; no
in-kernel object validation or callback trampoline is added.

Host tests use a pixel oracle for clipping, traversal/depth, hidden and indirect
objects, selection round trips, formatted text, callback parameters, mutated
globals, unsupported types and VDI error cleanup. GEMDRAW.TOS validates actual
VDI pixels in ring 3, nested USERDEF drawing, and a child callback fault followed
by successful update acquisition. It also paints a classic GEM demo panel.
The main fixture builds against unmodified GEMlib headers; a separate typed
pixel-probe object keeps private VDI headers out of the GEM application source.
The kernel harness also runs repainting beneath a visible software cursor,
then moves it through the normal cursor/VBL path and checks the restored
pixels. A second pass preserves a nested hide count of two. Resource
snapshots verify workstation/session/update/process reclamation.

To capture the actual QEMU framebuffer, enable external libaes, X32_VDI and
X86_64_MEMTEST, build the kernel and x32test/import fixtures, then run the boot
script with MMAP_BOOT_SCREENSHOT=/tmp/ptos-libaes-objects.png. The optional QMP
helper waits for the demo-ready marker and writes a PNG directly from QEMU;
no generated or reconstructed UI is used. The checked-in example is in
doc/screenshots/libaes-objects.png. Window decorations and extended menus remain subsequent slices. Forms, resources,
bitmap/icon drawing and 3D objects are now supported.


Userspace resource and form geometry (#752)
-----------------------------------------
rsrc_obfix/mt_rsrc_obfix convert a single OBJECT's encoded resource x/y/w/h
coordinates to pixels using the system font's cell size. The original
fix_chpos algorithm is shared in aes/shared/gemlayout.c with native AES and
the standalone desktop resource loader. Low bytes count character cells;
high bytes provide the original GEM pixel adjustment, including the native

width before applying its pixel adjustment. Applications fix each object
once; this operation does not load resources or relocate their pointers.

form_center/mt_form_center move the root object to the original GEM center,
using the screen area below the menu bar (system font cell height plus

unchanged. Child geometry is not moved or traversed.

workstation without display or mouse ownership. They close the workstation
before committing caller geometry, preserve application workstation state,

subsequent migration work.

Standard GEM forms

requests exceeding one MiB of actual device storage are rejected. Reads are
allowed across the screen and omit the software cursor. Restores obey the
current CUIS and workstation clips. All native raster storage is kernel-private
bounded staging memory, freed before return. Library snapshots are limited to
one MiB of worst-case storage, allocated and freed through GEMDOS.

native return behavior, rather than returning the alert button number.

Classic resource files
----------------------

libaes exports standard rsrc_load/free/gaddr/saddr and mt_* bindings. It compiles
the existing aes/shared/rsload_portable.c big-endian parser/materializer and the
original shared gemrsaddr.c lookup routines. Resource trees, TEDINFOs, strings,

native order; loading does not convert images into device format. On-disk

their own USERBLK functions after loading, as with other portable resources.

in native AES: saved copies of the resource globals can select an earlier live

redirect it, and later chdir calls do not change it. The CRT supplies a private

resource handles or negotiation are introduced. Input paths are bounded to
127 bytes, and lookup leaves the application's DTA untouched.

application-directory lookup after chdir with misleading extended ARGV[0],
and PATH-only lookup. The same fixture compiles with unmodified GEMlib headers.


Caller-owned native resources
----------------------------

rsrc_rcfix/mt_rsrc_rcfix implement the standard in-place resource API, not the
big-endian disk decoder. AES_PROCESS output 4 now reports this binding. The
caller supplies writable contiguous storage beginning with a classic RSHDR
(version 0 or 1), followed by the native C structures, tables and data. Header
offsets and rsh_rssize count bytes from that header; all fields use native byte
order and normal ABI alignment/padding. Pointers needing relocation contain
image-relative offsets in native pointer-sized slots. Use offsetof/sizeof of
the compiled structures rather than packed Atari disk-record sizes.

On x32, RSHDR is 36 bytes, OBJECT 24, TEDINFO 28, ICONBLK 36, BITBLK 16 and
USERBLK 8. Pointer slots are four bytes; align pointer-bearing records/tables
to four bytes, bitmap words to two, and the image itself to pointer alignment.
Tree entries point by offset into the object array; string/image tables and
object specifications likewise reference image data or the corresponding
native record. INDIRECT slots contain an offset specification and may be
shared. Direct box specifications remain immediate values. USERDEF object
specifications reference a native USERBLK by offset, while its callback and
parameter already contain application-native values and are preserved. Image
words are already native endian; no device-format conversion is claimed.

As required by GEM, release the selected resource before calling rcfix. A live
image cannot be fixed twice, including through another saved global array.
Indirect pointer writes cannot overlap strings (including TEDINFO capacity),
bitmap data or USERBLK records. Shared slots must have compatible specification
interpretations; unchanged payloads can still share storage.
Coordinates use the original shared character-to-pixel scaling. Fixup first
stages and validates relocation and tree topology without changing caller
storage; only after allocations, metrics and session checks succeed does it
commit the result to the original image. All resulting addresses point into
that original image, and a failure leaves data and resource globals unchanged.
The staging buffer and byte-range classification workspace are discarded after
the call, with failed frees retained for later cleanup in the same way as
disk-loader temporary buffers.

Keep the image writable and alive until rsrc_free or session cleanup detaches
it. rsrc_free clears the resource globals and frees only library bookkeeping;
it never Mfree's the caller's image. Session cleanup also detaches caller-owned
images without reading or freeing their contents. Reusing the image for a new
fixup requires restoring its original offset/character-coordinate form first;
free does not undo relocation, application edits or scaling. Saved globals
select registered native images through the same lookup/address bindings as
disk resources, and become stale when that registration is freed or reset.

This slice accepts classic native resources up to 65535 bytes. Colour-icon
extension blocks, RSX/large-resource headers and packed big-endian disk images
are rejected by rcfix; use rsrc_load for disk decoding. No kernel code, CUIS
opcode or configuration option is added. Native AES builds retain their
existing resource paths. Tests compile a native-offset fixture with normal
GEMlib headers, verify pointer identity, aliased specifications, scaling,
USERDEF callbacks, saved globals and caller ownership, and exercise malformed
input, headless metrics, allocation failures and failed cleanup retries.


Colour-icon drawing
-------------------

G_CICON now uses the original shared gr_gicon painter for the icon mask,
selected artwork, selected-without-artwork dithering, character and label.
The native best-match routine is shared as gemcicon.c: exact plane counts win,
otherwise the largest lower count wins, with original resource order breaking
ties. Drawing never rewrites the caller's CICON list, data, masks or ICONBLK.
The library queries screen planes through the existing read-only VDI inquiry;
its initial backend covers x32 packed 16/32-bit screens with the standard
256-entry GEM palette. Native planar AES keeps its existing transform/blit path.

The library colour blit decodes standard plane-major words to palette-index
runs and submits existing VDI fills, matching native packed-screen icon
conversion (including palette-index zero outside coloured shapes). Palette
pen ordering is shared with native VDI initialization. Explicit selected data
and masks override ordinary artwork; when absent, the original alternating
5555/aaaa mask darkens selection. Empty colour lists draw the original mono
icon. Selection changes redraw colour icons rather than using an XOR shortcut.

Visible-subtree preflight validates all variants, rejects cyclic lists and
invalid counts/pointers, and bounds each colour bitmap to 1 MiB. Native icon
coordinate/label checks and clipped destinations also apply. Dither allocation
uses tracked temporary storage, with later cleanup retries after failed frees;
allocation failure preserves the native undarkened-icon fallback. No kernel
service or colour protocol is added.

Colour-icon regressions include an eight-plane 16x16 pattern covering every
raw index 0..255 and its selected complement. Independent one-pixel G_IMAGE
swatches check all mappings, including index 255 to BLACK, in both the host
oracle and disk-loaded GEM256.RSC through the real x32 loader and VDI.


Userspace 3D objects (#772)

libaes compiles the original aes/shared/gemrender.c 3D painter with caller-local
bindings. FL3DIND, FL3DACT and FL3DBAK retain the native bevels, fill colours,
selected text movement and colour changes. Form watch rectangles include the
same expansion, and alerts use the original 3D button layout. No native kernel
behaviour or ROM object list changes.

objc_sysvar and mt_objc_sysvar expose the standard SV_INQUIRE/SV_SET interface
for LK3DIND, LK3DACT, INDBUTCOL, ACTBUTCOL, BACKGRCOL and read-only AD3DVAL.
Preferences are local to the calling process, including saved-global calls;
they do not change other applications' appearance. Defaults come from native
init_3d using the current workstation palette. Invalid modes, selectors and
colour indices fail without modifying output arguments. AES_OBJECT reports
3D flags and basic objc_sysvar support, without claiming GDOS object fonts.

The original painter uses WORD intermediates for 3D outlines and shadows.
Preflight rejects 3D objects whose expanded geometry cannot fit those
intermediates before painting or changing state. Existing wide-coordinate 2D
rendering remains available. Shared bounds calculations use LONG intermediates.
Drawing preflight and the libaes tree walker also keep accumulated ancestor
and descendant positions in LONG until validated, including callback-mutated
siblings. Icon bitmap, label and character offsets are checked against the
actual 3D-adjusted origin. Native traversal keeps its original WORD layout.

Regression coverage includes native bevel/selection pixels, configurable
colours, saved-global sysvar calls, invalid arguments, expanded and shadowed
hit rectangles, and overflowing geometry. The same ordinary GEM source runs
in the host sanitizer suite and in x32 QEMU against unmodified GEMlib headers.


Menu item APIs (#774)

menu_icheck, menu_ienable, menu_tnormal and menu_text (and their mt forms)
operate on the application's own menu tree. State changes compile the native
do_chg routine from aes/shared/gemmenuchange.c with library draw bindings.
Checking an item changes only CHECKED. Enabling changes only DISABLED, and
setting bit 15 of the item number requests immediate redraw, as in native GEM.
menu_tnormal changes SELECTED and redraws the title, but refuses disabled
items. Other state bits are preserved. Redraw uses the existing objc_change
adapter, full-screen clipping and nested display ownership; draw failures
retain the previous state. Saved-global calls use that registered application.

menu_text copies the supplied NUL-terminated text into the existing menu
string buffer without drawing or changing its address. As in native AES, the
caller must provide writable storage large enough for the new text and NUL;
the object width is not a buffer capacity. Text buffers remain caller-owned.

These item calls do not install a menu bar; use menu_bar, described below.
Extended-menu capabilities remain unadvertised. No kernel ABI or configuration
changes were introduced by the item-state slice.


Standalone popup menus (#776)

menu_popup and mt_menu_popup use the standard MENU descriptor and return 1 for
a selection or 0 for cancellation/failure. The output descriptor retains the
original tree and menu object IDs and reports the selected item and modifier
state. On cancellation/failure only mn_keystate is cleared. Input and output
may be the same descriptor; saved globals select the registered application.

This initial adapter accepts a G_BOX/G_IBOX with immediate G_STRING/G_TITLE
leaves, including disabled/hidden entries and indirect specifications. It
supports up to 4096 entries. Scrolling/listboxes, attached submenus, nested
item trees and other item types return 0. Extended-menu capability bits stay
unadvertised. Standard menu bars are described below; scrolling and submenus
remain later extensions.

The library makes a bounded private copy of the popup objects, preserving the
caller's links, coordinates, state and string ownership. The requested point
locates the starting item; placement retains native font-row adjustment and
keeps the box below the menu bar. Oversized menus and snapshots above one MiB
fail. Drawing uses the original shared AES object painter and existing VDI
operations, clipped to the snapshot rectangle including borders/3D effects.

The separately compiled tracker in aes/shared/gemmenupopup.c is derived from
the native popup loop. Explicit input/drawing/geometry operations keep it
independent of kernel globals. It tests click coordinates even without a
separate motion event, refuses disabled/hidden/root selections, tracks moves
out of background padding, and cleans transient selection after errors or
outside cancellation. Native AES retains its existing popup implementation;
its public MENU layout is shared through include/gemmenu.h. No kernel services
or new configuration options are added by this slice.

A popup holds nested display and mouse ownership, waits for the opening
button release, saves the background, tracks the click and waits for release
before restoring the screen and releasing ownership. Keyboard/messages stay
queued. Screen snapshots exclude the mouse cursor through the existing VDI
service. Temporary tree/snapshot frees use the resource allocator's failed-free
retry list. Selection is published only after restoration and cleanup succeed.

Regressions cover scripted tracking and host ASan/UBSan binding/failure paths.
The ordinary GEM fixture is also built against unmodified GEMlib headers;
opt-in QEMU input tests drive the real PS/2 mouse to select, cancel outside,
click a disabled item and select from a non-root menu with aliased descriptors.


Standard menu bars (#779)

menu_bar/mt_menu_bar implement MENU_INSTALL and MENU_REMOVE with ordinary GEM
OBJECT trees. The first three objects retain the standard screen/bar/active
roles; the root's last child contains dropdown boxes. Arrays must end with
LASTOB. The shared gemmenubar.c pairs titles and dropdowns by sibling order,
including non-contiguous object IDs. Bounded bitset admission rejects cyclic,
shared or malformed lists and unsupported visible payloads before painting.
Classic string/title items, hidden/disabled entries and indirect strings are
supported. Attached submenus, accessory registration and extended menu modes
remain separate slices; extended-menu capability queries remain unsupported.

Installation extends object 1 to the right screen edge, as in native AES,
and uses the original shared object painter plus the native black separator.
The caller keeps the tree and strings alive until removal. States, labels
and topology are rechecked before later painting/interaction; unsupported
caller edits fail without invoking USERDEF. The library owns only a temporary
index, not the caller's resource. Removal and session cleanup discard index
storage without dereferencing a possibly retired caller tree.

Each process registers a generic top strip with CUIS. Focus changes choose
the focused window's registered surface; explicit installation activates the
caller's surface. When its owner exits/removes it, a focused registered client
wins, otherwise the most recently registered surviving surface is restored.
Focus-driven ownership changes defer while display/update or surface drag ownership is
held. Native window regions exclude the strip. Other clients' full-screen
writes are clipped below it, while screen reads/copies may still read the
entire screen, including for screenshot applications. Windowless surface
owners receive keyboard input when no window has focus. Modal mouse control
suppresses surface handling; menu activation gestures do not enter ordinary
application button history.

Normal evnt_* and blocking appl_read calls pump menu work in libaes. Hovering
a title opens its dropdown, moving across titles switches menus, and
click/drag release selects an enabled item or cancels outside. Existing display
and mouse locks protect exact background snapshots, including borders and 3D
margins. Highlight sampling uses one-pixel motion predicates. Successful
selection queues a standard eight-WORD MN_SELECTED: sender 0, title/item in
words 3/4, tree pointer in words 5/6, and dropdown root in word 7. The selected
title stays highlighted until menu_tnormal. A full stream retains one pending
selection and defers further menu handling or replacement until it can be
published; it never blocks writing to its own full stream. APR_NOWAIT reads
flush pending messages without entering a blocking menu interaction.

An unfinished multi-click wait retains its count, snapshot and original click
deadline in the kernel. Surface-only work waits until click completion or a
requested application event; menu tracking cannot discard the first click.
Internal wakes re-arm application predicates and preserve original timer
expiry across the 200 Hz partial-tick guard and clock wrap. Event results are
snapshotted before recursive menu tracking can replace input filters/results.
Failed painting restores the saved pixels; staged installation preserves the
previous owner and registration order until painting and workstation cleanup
succeed. Fresh mouse acquisition (MOUSE_LOCK mode 2) suspends application
button history, tracks only new input, and restores that history on release.
Failed temporary frees stay on the resource allocator's retry list.

CUIS additions (all arguments flat in registers, under CONF_WITH_CUIS):
- 50 SURFACE_REGISTER(session,height): zero removes, positive reserves a top
  strip and activates it; returns E_OK or a negative error.
- 51 SURFACE_STATUS(session,action): action 0 queries OWNED/DIRTY/POINTER bits,
  action 1 acknowledges pending work, action 2 invalidates an owned surface.
  Acknowledge does not discard work during modal mouse control.
- 53 SURFACE_BEGIN(session,height): under the display lock, stages a positive
  strip height and grants painting without changing ownership or fallback order.
- 54 SURFACE_END(session,commit): commits with 1 or cancels with 0 under the
  display lock. Releasing the display lock also cancels an unfinished stage.
READY_SURFACE is bit 128 in SESSION_WAIT. READY_DISPLAY is bit 256: it
reports when a display acquisition can succeed (including an already-owned
display scope). It does not acquire ownership. Frame notice pumps try the
display lock nonblockingly and wait for display availability alongside queued
messages, so a lock holder blocked writing to the receiver can still progress. CUIS does not interpret GEM object
pointers, AES opcodes or message formats. It has no feature/version negotiation
or drawing commands; ordinary streams carry opaque application message bytes.

Validation covers host sanitizer ownership/clipping/exit/input tests, source
admission and caller mutations, paint-failure restoration, timer wakes/wrap,
and ordinary GEM source compiled against unmodified GEMlib headers. Real
QEMU mouse tests select across titles, and isolated clients exercise focus
handoff, separate menu colours and owner exit. Headless, legacy-AES desktop,
native ROM and contract configurations are also checked.

Decorated window geometry (#781)

wind_calc/mt_wind_calc also accept the classic NAME, CLOSER, FULLER, MOVER,
INFO, SIZER, arrow and slider bits, plus PC-GEM HOTCLOSE. Unknown extension
bits fail. The separately compiled aes/shared/gemframegeom.c derives margins
from native wm_calc, including its 3D title, info and sizer placement rules.
External libaes uses the native 3D frame layout. Decorations do not accumulate
when several gadgets occupy the same row or column.

Decorated calculations require an application session and obtain system font
cell and pixel aspect metrics from a private workstation. Box height is the
cell height plus three; width uses the native pixel-aspect calculation with
its character-width-plus-four minimum. Native TOS4 narrows the adjusted 3D
box width by one below 640 screen pixels, plus another at 400 or more lines;
these mode-dependent adjustments affect the vertical bar width. The kind-zero
calculation remains independent of workstation/session access. Workstation errors leave outputs
unchanged. Wide intermediate arithmetic rejects results outside signed WORD
range. Small rectangles retain negative work extents as in native AES, and
representable frame/work conversions round-trip exactly.

This slice adds calculation only; title/info frames follow in #787 below.
Capability queries continue to leave unsupported window behavior unadvertised.

Native title and info frames (#787)

wind_create accepts NAME, INFO and their combination, retaining the original
kind in WF_KIND. The native 3D frame builder is separately compiled from
aes/shared/gemframe.c by both native AES and libaes. Object indices live in
aes/shared/gemframeids.h. Native 2D small-ROM construction stays unchanged.
The shared builder retains native layout, glyphs, colours, title activation
and shadow appearance for all classic gadgets; this public slice enables only
those frames that do not require additional gadget actions.

wind_set_str/mt_wind_set_str set WF_NAME and WF_INFO using ordinary GEMlib
signatures. The traditional wind_set/mt_wind_set high-WORD/low-WORD pointer
form works too. Labels remain caller-owned and must stay alive until replaced
or the window is deleted. The bounded object painter supports labels of up to
127 bytes. NULL labels fail, while an empty string is valid.

Opening and changing a decorated window draw its frame. Redraw notices publish WM_REDRAW
for the work area and repaint owned frames under the same display lock. The
notice is acknowledged before drawing, so focus/damage during painting stays
pending for the next pass. Event waits and
timers service internal frame notices while preserving user timer deadlines,
queued messages and unfinished multi-click waits. A full message stream
suppresses repeated internal wakes until capacity can be freed. APR_NOWAIT
uses a nonblocking display acquisition and leaves repaint work pending if a
peer owns the display. Topping/bottoming
repaints the caller's frame; affected peers receive their normal redraw notices.
WF_WORKXYWH, visible work rectangles and WM_REDRAW use the registered kind,
matching wind_calc. WF_FIRSTXYWH copies its complete region snapshot into
caller-owned storage; WF_NEXTXYWH consumes that copy, so intervening frame
painting cannot replace an active public traversal. Snapshot allocation failure
returns GEM 0 without changing outputs or the previous traversal. Remaining
rectangles are freed on restart, close, deletion, geometry change or application
reset. The painter uses CUIS visible-region snapshots under the
display lock and the original object renderer, preserving work pixels and
occluding clients. A drawing failure leaves the notice available for retry;
failed opening hides the window and restores local rectangles when cleanup
succeeds. Failed configuration attempts restore the previous geometry when
the rollback succeeds; if rollback itself fails, metadata retains the last
successful CUIS geometry. Text replacement restores its previous label on
painting failure. Painting failures invalidate the affected display rectangle
for later redraw. Cleanup attempts release temporary display locks and workstations; errors
are reported as GEM 0.

Decorated borders must admit a positive work area, title inset and drop shadow
without WORD overflow. Tiny/overflowing rectangles fail before configuration.
Kind-zero window behavior is retained. Arrows,
sliders, HOTCLOSE and other creation flags remain rejected until their actions
are implemented. No further capability bits are advertised. CUIS gains no GEM
frame flags, object pointers, drawing commands or architecture-specific code.

Frame painting is suspended throughout caller-local overlay scopes: alerts,
form_do and watch-box input, FMD_START through matching FMD_FINISH, popup menus
and menu-bar tracking. Nested scopes resume only after the outer overlay is
removed or its saved pixels are restored. Redraw notices stay pending and do
not wake internal waits during suspension. Ordinary stream messages remain
readable. The event timer's remaining interval is computed immediately before
the kernel wait, after pre-wait frame painting has consumed its share of the
original deadline.

Close and fuller window controls (#790)
--------------------------------------

External libaes accepts CLOSER and FULLER, independently or together with
NAME/INFO. Native shared frame objects, glyphs and SELECTED rendering provide
watch-box feedback. A left press selects the original gadget, leaving it
unselects it, and returning selects it again. Release inside that same gadget
appends WM_CLOSED (22) or WM_FULLED (23). Words 1/2 are zero, word 3 is the GEM
window handle, and words 4-7 contain its current border rectangle, matching
native AES. Neither request closes, destroys, maximizes or otherwise changes
the window: the application remains responsible for its response. An activation
click on a background window requests WM_TOPPED only. Other buttons, release
outside, lost input, geometry/visibility/focus changes and mouse grabs cancel
the gesture. Scrollbar interactions and HOTCLOSE remain unsupported.

CUIS adds three generic scalar operations under CONF_WITH_CUIS:

- 55 WINDOW_CONTENT(window,left,top,right,bottom): set nonnegative content
  insets (0..32767), relative to the border. Defaults are zero. Insets may be
  configured while hidden; sums exceeding an extent leave content empty.
  Changing them cancels pending border gestures. The same topology/display
  ownership rules as WINDOW_CONFIGURE apply.
- 56 CONTROL_READ(window,out_x,out_y,out_buttons,out_changed): read one trusted
  border-pointer record, returning 1, empty 0, or a negative error. All outputs
  are LONGs, coordinates are screen-relative, and changed uses bit 0 for left and bit 1
  for right button transitions. The caller must own the window. Failed output copies
  do not pop the record. ERANGE cancels tracking after queue overflow or a
  target invalidation; no GEM gadget IDs, trees or messages enter the kernel.

- 57 WINDOW_CORNER(window,width,height): reserve a bottom-right control
  rectangle independently of content insets (each dimension 0..32767).
  Either zero disables it; both default to zero. Hidden windows may be
  configured before sizing. Changes cancel pending gestures and follow the
  same ownership rules as WINDOW_CONTENT. Libaes reserves the complete
  expanded SIZER corner, including its bevel and low-resolution overlap;
  WF_WORKXYWH and work-area drawing remain unchanged.

READY_CONTROL (512) wakes SESSION_WAIT for these records or cancellation.
Each window has a bounded 16-record border queue, with adjacent motion records
coalesced. A press on the border captures that routing until release, keeping
all gesture edges out of ordinary window pointer queues and session button
history, even when it crosses the content area. Earlier work-area clicks are
preserved. As with READY_SURFACE, internal readiness does not interrupt an
unfinished multi-click accumulation. Modal scopes defer control servicing and
mouse grabs invalidate pending border gestures. Nonblocking display acquisition
and a retained completed message prevent drawing or full-stream backpressure
from blocking ordinary message reads. All public calls remain standard GEM;
there is no new exported libaes API or feature negotiation.

Control readiness servicing drains records/cancellation for every live GEM
handle, including plain, title/info-only and hidden windows. Only open windows
with a supported gadget interpret those records or paint feedback. Border hover
suppresses live button predicates while focused MU_M1/MU_M2 rectangle predicates
remain active. Changing the selected top-strip surface or its height invalidates
queued and captured border gestures even if window focus and stacking stay the
same. Completed requests retain a release-time rectangle separately from the
watch box; a later geometry change, close or release-feedback drawing failure
cannot retract that request while its message waits for stream capacity.

Plain and hidden live windows also participate in control servicing. Nonzero
GEM timers retain their original deadline across control-only and display-ready
wakes, including when no decorated window or menu exists. Window show/raise/
lower/hide operations cancel background border gestures under the topology IRQ
lock independently of focus; a temporary unmanaged occluder cannot restore an
old queued release's eligibility by disappearing before CONTROL_READ.

Window move gestures (#793)
--------------------------

External libaes accepts MOVER, including MOVER without NAME. Dragging the native
name/title object selects it and draws the original gsx_xbox dotted XOR outline
from aes/shared/gemgraphutil.c. The window and its work pixels remain fixed.
Releasing the left button appends standard WM_MOVED (28): sender/extra length
zero, handle in word 3, proposed x/y and unchanged border width/height in words
4-7. The application chooses whether to call wind_set(WF_CURRXYWH). Background
activation still requests only WM_TOPPED. NAME without MOVER is not draggable;
CLOSER/FULLER retain their existing watch-box semantics.

The press-to-border offset is retained, even when a press and release were
queued before servicing. Wide-intermediate constraints match native
hctl_window()/gr_dragbox()/rc_constrain: left edge 0, top at hbox, rightmost
origin screen_width-wbox-6-2*ADJ3DSTD and the native MAX_COORDINATE vertical
constraint. WORD outline endpoints cannot wrap for oversized windows. Shared
geometry lives in aes/shared/gemmovegeom.c; native frame/title/glyph and GSX
outline drawing sources remain shared without .inc files.

The display lock spans outline drawing, input waits and XOR erasure, as native
GEM's update scope does. No mouse grab replaces the existing border capture;
no ordinary button history, key queue, event filters or completed input result
is consumed by tracking. Other mouse buttons, lost border records, ownership
cancellation or drawing/input failure abort without WM_MOVED. Successful and
cancelled outlines are erased before leaving the display scope. A rendering
failure invalidates the display for application redraw. Completed move requests
retain proposed geometry independently of later application geometry changes
and full-stream retries. Modal scopes defer servicing before a drag starts.

CUIS_EVENT_CONTROL (16) extends the existing EVENT_WAIT window-event mask; it
waits on that owned window's border queue/cancellation rather than all session
windows. It uses the existing scalar window/events/timeout arguments (0 poll,
-1 indefinite, positive milliseconds), and never consumes records or changes
session input predicates/results. Another window's queued records cannot make
this wait spin. Cancellation remains readable and wakes both window and session
control waits while a peer owns the mouse, allowing the outline owner to release
its display lock even if that peer is waiting for display access. These generic
kernel changes remain compiled only with CONF_WITH_CUIS. There is no new syscall
opcode or public libaes entry point. Arrows/sliders and HOTCLOSE remain
subsequent work.

APR_NOWAIT reads and explicit zero-duration event polls never start a blocking
mover wait. A polled title press retains its original anchor privately, leaving
held-motion records queued until a blocking event/message service can
track it. Poll-only applications can finish a released drag without drawing an
outline or waiting for further input. Queued application messages remain readable while the title is held.
Move proposals reserve the same two-pixel shadow margin as frame admission, so
wind_set can apply boundary proposals. Move outlines select VDI line type 7 as
well as the original shared GSX dotted patterns.

Window sizing gestures (#795)
----------------------------

External libaes accepts SIZER with the existing NAME/INFO/CLOSER/FULLER/MOVER
flags, including a lone SIZER without a title. Initial hit testing uses the
native shared OBJECT tree and its sibling priority. The original corner glyph
and SELECTED feedback come from aes/shared/gemframe.c. No in-kernel AES or ROM
frame source is changed for this slice.

Sizing holds the border origin fixed and uses native gr_rubwind's mouse-minus-
origin-plus-one dimensions. A dotted XOR border box and a second work-area box
reuse gsx_xbox from aes/shared/gemgraphutil.c, under one display scope. The
work-area offsets follow the window kind. Release sends standard WM_SIZED (27),
with sender/extra length zero, handle in word 3, and the proposed border x/y/w/h
in words 4-7. The application decides whether to apply it with WF_CURRXYWH;
current, previous and work geometry are not changed by the request itself.

Shared geometry in aes/shared/gemsizegeom.c retains native minimum character
width/height, four box widths for title/horizontal gadgets, and six box heights
for explicit vertical gadgets. Additional frame-admission minima keep work and
title extents positive and the sizing glyph inside its data area. TOS4's lone
SIZER reserves a vertical bar, rather than both bars. The low-resolution adjusted
box metric, INFO line, aspect ratio, and two-pixel shadow/WORD limits are retained.
An impossible minimum/maximum combination cancels instead of producing a
rectangle the application cannot apply.

Sizing reuses mover border capture and per-window waits without new kernel
operations or public libaes entry points. It preserves ordinary button history,
keys and input-result snapshots. Background activation remains WM_TOPPED only;
other buttons, invalidated ownership or overflow cancel the gesture. Outlines
erase on completion/cancellation; drawing failures request display redraw.
APR_NOWAIT and explicit zero-time polls retain held sizing presses without
waiting, and can complete released sizing requests entirely through polling.
Completed requests retain their proposed dimensions under stream backpressure
and later application geometry changes. Slider/page interactions and
HOTCLOSE remain subsequent work.

Frame admission and sizing now share WM_FRAME_LIMITS. Corner minima include
both 3D bevel margins, so the full SIZER stays inside its data area rather than
expanding into the title or above an untitled border. Size maxima include both
the renderer's padded object dimensions and its absolute WORD scratch endpoints,
using the same padding calculation as the object renderer. This includes the
low-resolution FULLER offset. Boundary WM_SIZED proposals therefore remain
admissible and paintable, rather than relying only on the outer shadow margin.

Window scroll-arrow controls (#797)
----------------------------------

External libaes accepts UPARROW, DNARROW, LFARROW and RTARROW, separately
or in combination with the existing title, information and sizing controls.
The original native aes/shared/gemframe.c builds the bars and glyphs, including
aspect and low-resolution adjustments and selected appearance. Admission and
move/size proposals share limits for the actual padded arrow positions, valid
work/bar extents and opposing glyphs; no kernel frame code is changed.

Pressing an arrow sends standard WM_ARROWED (24), sender/extra length zero,
window handle in word 3, WA_UPLINE (2), WA_DNLINE (3), WA_LFLINE (6) or
WA_RTLINE (7) in word 4, and zero words 5-7. The application owns scrolling
and redraw. Like native handle_arrow_msg(), press sends immediately and the
original action repeats while held, including outside the arrow rectangle;
release ends tracking without another action. The selected glyph stays active
throughout that capture. Background activation, topology/ownership changes,
queue overflow and mixed-button cancellation use the existing generic CUIS
control path. Earlier ordinary work-area button edges remain independent.

Repeats are cooperative: each service pass can emit at most one due repeat,
with a two-tick minimum between repeats and no initial key-repeat delay.
Blocking GEM reads and event waits request internal service wakeups when a
held arrow needs service without pointer motion, including calls configured
for double-click detection with no multi-click currently in progress. The display
lock is released before waiting. Internal service wakes never return MU_TIMER unless
the application's own original timer deadline has expired. Unfinished
multi-click accumulation is not interrupted by repeat timers. APR_NOWAIT and
zero-time timer polls never wait for input. Stream writes remain nonblocking;
a full stream retains one pending action and lets the application drain data,
rather than waiting while holding display ownership or growing a repeat list.
Release/cancellation records are processed before generating another repeat.

GEMDRAW.TOS and the QEMU input driver exercise all four actions, multiple held
repeats, dragging outside, release suppression, polling-only completion, normal
button-history isolation and unchanged window geometry. The source builds
against unmodified GEMlib headers. Host sanitizer tests also cover full-stream
progress, batched reads, clock wrap, original timer deadlines, rendering and
cancellation/failure cleanup, every arrow combination, low-resolution modes,
minimum geometry and the production painter's positive WORD endpoints.
VSLIDE/HSLIDE, thumb tracking and WA_*PAGE actions are covered by #801
below; other unsupported creation flags/fields still return GEM failure.

CUIS READY_SERVICE (1024) adds a generic maintenance wake to SESSION_WAIT,
without new syscall arguments or GEM-specific kernel state. It becomes ready
after two native ticks, independently of the requested TIMER deadline. Like
other internal readiness, it is deferred during unfinished multi-click
accumulation until a requested public event is ready; that accumulation stays
resident with its original count and deadline. Libaes consumes SERVICE
internally, services due controls, then re-arms the public event wait.

Window sliders and page actions (#801)
-------------------------------------

External libaes accepts HSLIDE and VSLIDE with the existing frame flags.
The native shared frame builder supplies the bars, tracks and elevators;
caller-local aes/shared/gemslidegeom.c derives their actual rectangles from
that same tree. No parallel hand-drawn slider or new public AES API is used.
WF_HSLIDE/WF_VSLIDE query stored positions, initially 0. WF_HSLSIZE/WF_VSLSIZE
(and the historic WF_HSLSIZ/WF_VSLSIZ spellings) query thumb sizes, initially
-1 for the native one-box default. Setters retain native wm_set clamping:
positions and explicit sizes below 1 become 1, values above 1000 become 1000,
and -1 remains valid for the default size. Fractions use the original shared
builder's box minimum, proportional sizing and position arithmetic. Fields
remain queryable while closed or without the associated gadget; successful
open/close operations retain them. Painting failures restore the old field.

Clicking an uncovered track sends WM_ARROWED with WA_LFPAGE (4), WA_RTPAGE
(5), WA_UPPAGE (0) or WA_DNPAGE (1), chosen relative to the elevator's logical
origin just as native hctl_window does. Page holds retain their original action
while held, even outside the track or after the application updates a slider.
They share the bounded repeat/cancellation/service-wake path with line arrows,
and do not select the track.

Dragging a thumb uses the original patterned XOR gr_dragbox outline and
native gr_slidebox constraints, including its 3D expansion, low-resolution
cross-axis adjustment, rounded fraction and one-pixel full-thumb travel.
Release proposes WM_HSLID (25) or WM_VSLID (26), sender/extra length zero,
window handle in word 3, position 0..1000 in word 4, and zero words 5-7.
Stored positions and application content remain unchanged until the owner
applies its chosen update. Initial hits use native OBJECT-tree sibling
priority. Blocking drags wait only on their own trusted control queue; held
APR_NOWAIT/zero-time polls retain the original geometry and remain nonblocking.
Polling-only clients can complete released drags without drawing an outline.
Replacing slider geometry during a deferred thumb drag cancels that local
proposal; an already accepted pending message retains its original value
under stream backpressure or later field updates.

Admission reserves enough track space for the native default thumb and
bounds full-sized selected elevators against the production painter's padded
WORD dimensions/endpoints. The same limits constrain move/size proposals.
Host sanitizer tests compare proposal math to native rc_constrain and
mul_div_round across orientations, arrow combinations, default/explicit sizes,
positions, aspect metrics, low-resolution modes and extreme input coordinates.
Production painter tests cover minimum/default/full thumbs, hit priority,
outline restoration/cancellation, positive endpoints and maximum padded
sizes. Standard GEM clients built against unmodified GEMlib headers exercise
field semantics, page holds and both orientations in blocking/polling drags.
The expanded combined QEMU forms/window suite has a 90-second CI budget.
HOTCLOSE and the remaining unimplemented window extensions are still rejected.

Graphics handle and cursor bindings (#803)
-----------------------------------------

External libaes provides standard graf_handle/mt_graf_handle and
graf_mouse/mt_graf_mouse. The graphics handle is a persistent, process-owned
screen workstation, usable in the ordinary graf_handle/v_opnvwk startup
sequence. Character and box metrics use the same system-font/aspect calculation
as resource, form and window layout. Repeated calls retain the handle;
closing an application's separate virtual workstation does not close it.
Invalidated handles are reopened, transient checks fail without dropping the
cached handle, and appl_exit/reset closes the private workstation. Failure
returns GEM 0 without changing caller metric outputs; optional output pointers
may be NULL. Headless clients retain the existing failure behavior when typed
VDI is unavailable.

Cursor forms are generated from the original aes/mform.rsc/.def data with the
existing mrd tool, rather than copied or redrawn. The eight native forms,
USER_DEF, counted M_OFF/M_ON, M_SAVE/M_RESTORE and M_LAST/M_PREVIOUS are
implemented. Form arguments for modes that do not use them are ignored.
Native invalid-low-mode fallback and unknown-high-mode no-op behavior remain.
Current, previous and saved forms and the hide depth are private to each
application; USER_DEF copies caller data before returning. Failed transport
calls do not replace that state. The public MFORM spelling, colour-field
order and signed WORD arrays match GEMlib. Native VDI words remain unchanged:
the internal mask/data colour names differ historically from GEMlib's public
names. Resource data and custom records pass through in their original word
order. The native kernel's MFORM view is unchanged.

CUIS_POINTER_STYLE (58) takes (owned_session, form_address, hide_depth), with
one fixed 74-byte VDI pointer bitmap and depth 0..32767. It returns E_OK or a
negative native error. It never retains the supplied address, interprets GEM
mode numbers, or negotiates a protocol. CUIS stores a bounded form copy and
selects the mouse-grab/capture owner, the input owner of a top strip under the pointer,
the focused window's client, or the active windowless fallback. Background
updates remain pending. Focus/strip crossings, grab release, application exit
and physical display reinitialization restore the appropriate client's form
and visibility. VDI performs the actual cursor drawing using its original
form conversion, hide/show and save/restore routines. CUIS contributes one
balanced visibility overlay, independent of temporary VDI drawing hides;
nested client hides do not wrap the hardware hide count. No cursor becomes
visible solely because an old client opens a workstation. The first explicit
cursor request enters normal pointer display behavior. Ending the last cursor
owner restores the default form and releases its hide contribution.

All kernel storage, routing and VDI hooks are CONF_WITH_CUIS-gated. Native
non-CUIS cursor code, resource forms and ROM object lists retain their prior
behavior. Host sanitizer tests cover metric/handle failures and caching,
public/native record layouts, copied/saved/previous forms, counted visibility,
failed mutations, session initialization, foreign ownership, top-strip
crossings, normal/fresh grabs and teardown. The real x32 GEM fixture builds
against unmodified GEMlib headers, uses standard graphics/virtual-workstation
startup signatures over the existing VDI transport, compares cursor pixels
with native pen swatches, checks background restoration and nested visibility,
and verifies restoration after an isolated child exits with outstanding hides
and an open window. The existing input/window/forms/menu/pixel tests continue
with the application's cursor hidden. Public drag/rubber/slide helper APIs and
additional graphics extensions remain subsequent work.

Interactive graphics tracking
-----------------------------

External libaes implements graf_rubberbox, graf_dragbox and graf_slidebox,
including their mt variants and ordinary GEMlib source signatures. Native AES
and libaes compile the same tracking loops from aes/shared/gemgrtrack.c, using
the original patterned XOR outlines. Rubber dimensions use inclusive pointer
coordinates and the supplied minima. Dragging retains the native pointer offset
and rectangle constraints. Sliding applies native 3D expansion and rounding to
0..1000, returning zero for a track with no travel. The object tree is not moved.

The adapter holds whole-screen display and mouse ownership across tracking,
suspends automatic frame painting, and balances nested caller grabs. A held
gesture must belong to the application (for example through window content
capture); a fullscreen application can acquire BEG_MCTRL before waiting for
its press. Acquisition does not wait on a foreign gesture while excluding its
drawing. Past release history cannot end a tracker while the button remains
held. The adapter waits directly for pointer changes and release, without
recursively dispatching menus or window controls.

Coordinates and caller-local slider trees are checked before tracking. Parent
relationships are indexed in one bounded pass, with cycle and duplicate-parent
rejection. Failures leave rubber/drag output pointers unchanged and release
acquired ownership; a failed XOR operation requests redraw. As in GEM, zero is
both a valid slider position and its failure return. No new kernel operation
or public pTOS-specific tracking API is required.

External libaes exports standard graf_mbox, graf_growbox and graf_shrinkbox,

Whole-screen display ownership and frame suspension span each public animation

Failures request window and owned-menu-surface repaint before the outer display

Window lookup by screen coordinates (#816)
-----------------------------------------

External libaes exports standard wind_find(x,y) and mt_wind_find(x,y,global).
They return the identifier of the frontmost open window containing the point,
including its border, regardless of application ownership. A point not covered
by an open window returns desktop identifier 0. Window bounds include their
left/top edge and exclude their right/bottom edge; visual shadows do not count.
Hidden or destroyed windows cannot be returned. Invalid registration and native
query failures return -1, without leaking a CUIS error or narrowing a bad ID.

CUIS_WINDOW_AT (59) takes two flat, sign-extended LONG coordinates and returns a
non-negative global window identifier, or a negative GEMDOS error. Unused
registers are ignored. A registered caller can query any visible window; the

focus, stacking, input queues nor pointer state. Full-width noncanonical LONG
arguments return EINVAL. The scan uses the same half-open window bounds as
pointer routing, under the same short IRQ exclusion as topology changes.
There are no user buffer arguments and no additional capability claims.

Host regressions cover registration, signed LONG extremes and malformed wide
arguments, cross-session lookup, stack transitions, hidden/destroyed windows,
shadow exclusion and lookup while another session holds the display lock. GEM
adapter tests check signed WORD arguments, mt_* globals and result validation.
GEMFOC.TOS builds against normal GEM headers and checks borders, half-open edges,
foreign windows, raising/lowering, closing/reopening and process-exit cleanup in
isolated x32 clients. It emits "x32 GEM window lookup: PASS" on success.

Classic window/desktop completion (#818)
----------------------------------------

External libaes supplies wind_new/mt_wind_new, desktop handle 0 queries,
WF_NEWDESK, WF_SCREEN, WF_COLOR/WF_DCOLOR and the standard GEMlib int, pointer
and GRECT window bindings. Kernel changes remain CONF_WITH_CUIS gated; native
in-kernel AES drawing and ROM objects are unchanged.

wind_new closes/deletes only the calling application's windows, releases all
of its update/mouse/keyboard nesting and resets the cursor hide count. Other
applications' windows, locks and sessions survive. The caller remains
registered, keeps its graphics workstation and may create new windows. Its
installed desktop also survives this window-manager reset.

Handle 0 has full-screen current/previous geometry and work/full geometry
below the active menu strip. FIRSTXYWH/NEXTXYWH return an independent desktop
work-region iterator, excluding every visible window and its shadow. FIRST
captures the complete list under an update section before replacing the local
iterator; failures leave the old iterator intact. A caller can interleave this
with window rectangle lists and automatic desktop painting.

WF_NEWDESK installs a caller-owned tree/root through wind_set or the standard
wind_set_ptr[_int] bindings. The library validates its visible subtree before
publishing ownership; it does not alter the tree's layout. NULL selects the
original AES default background pattern. No tree or callback pointer enters
the kernel. The most recently installed background owns the bottom surface;
removal or process exit falls back to the previous live registrant. Global
window identifiers continue to exclude the background: wind_find returns 0
there. Background clicks and mouse predicates belong to its owner, with drag
capture preserved across windows/menu strips and sampled before release.
Replacing the active background discards its outgoing owner's unread ordinary
keys as well as the incoming owner's stale keys. Explicit keyboard-grab queues
are preserved; modal display ownership continues to exclude foreign transfers.

Rendering runs in the owner's ordinary GEM event/message dispatch, using the
original AES object painter over the desktop visible regions. Display
contention is deferred, overlays suspend painting, and failed painting retains
damage for retry. Damage is acknowledged before calling application USERDEFs,
so reentrant invalidation is not lost. A sleeping owner wakes on background
damage using ordinary native notice readiness. WF_NEWDESK queries return a
pointer only to the caller's current tree; foreign process addresses are never
exposed. Desktop owner and geometry metadata remain queryable across clients.

WF_COLOR accepts gadget numbers W_BOX through W_HELEV. Top/bottom colour words
use the native GEM frame format; -1 setters preserve that word. WF_DCOLOR is
shared across clients and affects subsequently created windows; existing
windows retain their own colour arrays. A default pair changes atomically.
Invalid gadgets and failed repaints do not replace per-window colours. Colour
getters take the gadget through the first output word, as GEMlib requires.
WF_NAME/WF_INFO setters retain the caller's local string pointer. Their scalar
wind_get/mt_wind_get getters return that address as high/low WORDs through the
first two outputs, which must both be non-NULL. Output adjacency never selects
a string copy. wind_get_ptr/mt_wind_get_ptr provide the explicit pointer helper.

WF_SCREEN returns a private compatibility scratch buffer and byte length in
high/low WORD pairs. It reserves 640 character cells at four bytes per pixel
for true-colour capacity, subject to the existing bounded allocation limit.
The buffer is retained until application exit/reinitialization; applications
must not free it. It is not a kernel address or shared application memory.
Menus and forms retain their independent exact screen-save storage.

Additional scalar native services, all requiring a registered caller:

  60 BACKGROUND(session,action): action 0 withdraws this registration, 1
     installs/reasserts it, 2 reads ownership/damage bits (1/2), 3 acknowledges
     damage, and 4 invalidates. Mutations require display ownership; replacing
     a foreign captured background returns EAGAIN.
  61 BACKGROUND_REGION(session,index,x,y,width,height): four separate LONG
     output pointers, result 1 for a rectangle or 0 at end, matching the window
     snapshot/copyout and failure/lifetime rules.
  62 DISPLAY_INFO(selector): scalar width (0), height (1), reserved top-strip
     height (2) or active background owner's process ID (3).
  63 WINDOWS_RESET(session): resets this caller's windows and coordination
     scopes, acquiring display ownership cooperatively before changing Z-order.
  64 SETTING(slot,value,other_slot,other_value,mask): bounded generic shared UI
     preference words. Mask 0 reads the first slot (EFILNF if unset); bits 1/2
     atomically write the selected slots. Writes require display ownership.
     The kernel stores 64 uninterpreted UWORD slots; GEM colour interpretation
     and native fallback defaults remain entirely in libaes.

The host service, adapter and pixel suites cover peer isolation, ownership
fallback, clipping/menu/shadow bounds, copy/allocation/drawing failures,
reinitialization and reset. GEMFOC.TOS additionally exercises unmodified
GEMlib headers, cross-process colour defaults, background pixels and raw-exit
fallback, pointer buffers and nested wind_new cleanup. Its completion marker
is "x32 GEM window/desktop APIs: PASS". Iconification, shading, toolbars and
other extended-window compatibility remain separate work; no additional
appl_getinfo capability bits are advertised by this slice.

Classic file selectors (#822)

External libaes implements fsel_input and fsel_exinput, including the standard
mt_ variants. The public signatures match GEMlib: a writable path/mask buffer
(at least 128 bytes), a writable 8.3 selection buffer (at least 13 bytes), and

Success returns 1, with button 1 for OK or 0 for Cancel; failure returns 0.
Caller buffers are committed only after successful dialog cleanup.

The implementation shares aes/shared/gemfslib.c and the generated native AES

The modal selector nests display, mouse and keyboard ownership, suspends frame

restores the pixels, closes its private workstation, releases only its own
ownership depths and frees temporary storage on success, cancellation or an

Shell startup, environment and file queries (#826)
------------------------------------------------

External libaes implements shel_read, shel_envrn and shel_find, with their
standard mt_* counterparts and GEMlib signatures. Shell launching and shared
shell/desktop context are separate work; these queries add no kernel service.
They require the caller's registered GEM global array.

shel_read writes the complete startup executable specification and the original
128-byte GEMDOS command tail, including its leading length byte. The command
buffer must have at least 260 bytes. With CONF_WITH_LIBAES, the startup stack
builder saves the original tail in an optional AT_PTOS_LAUNCH record. LD.SO
qualifies AT_EXECFN in that record before executable preinitializers or any
dependency constructor. The library consumes the saved command and tail in
DT_INIT; preinitializer cwd changes or default-DTA searches cannot alter them.
The resource loader consumes the same captured command with a 260-byte bound.
Extended ARGV[0] remains independent of the supplied executable pathname.
Missing or invalid startup metadata returns 0 without changing either output.

shel_envrn performs the native AES prefix search in the process's startup
GEMDOS environment block. It returns 1 for a completed lookup and writes the
address immediately following the prefix, or NULL when absent. The result is
an ordinary process-local pointer into that environment. Lookup stops before
the ARGV= marker and argument payload, matching the startup envp boundary;
variable-looking arguments never supply environment values. Empty values remain
empty; PATH parsing does not treat the next environment variable as a path.
The snapshot retains the original environment address and actual allocation
extent, so validation does not scan a short block up to the 32 KB ABI maximum.
NULL arguments, invalid globals or a malformed unterminated environment return
0 without changing the output pointer.

shel_find uses the original native AES search core in aes/shared/gemshquery.c:
first the basename in the launch application directory, then the supplied
specification in the current directory, then the basename in the current
drive's root, and finally the semicolon/comma-separated PATH components.
Drive-relative PATH components retain their colon semantics. Like native TOS,
a current-directory match leaves the supplied specification unchanged; other
matches replace it with the successful candidate, retaining wildcard masks.
The caller provides a writable buffer of at least 260 bytes. Success returns 1;
missing files, invalid inputs or operational failures return 0 with the input
buffer unchanged. Overlong PATH candidates are skipped within private bounded
workspace. Ordinary EFILNF/EPTHNF/ENMFIL results continue the search; other
Fsfirst errors stop further probes and fail without committing a later match.
The search uses one stable private DTA address across calls, so lookups at
different stack depths do not accumulate hidden kernel search-cache entries
and evict an outstanding caller search. Cleanup restores the original DTA
pointer without changing its bytes, current drive or current directory.

Native AES uses the same separately compiled query source with its existing
state and bindings. Startup directory discovery is also shared with libaes's
resource loader. The shell query fixture exercises native search precedence,
prefix/missing/empty environment lookup, long paths and DTA failure cleanup
under host sanitizers. The isolated x32 GEM client covers both short and ARGV
launches, lookup after cwd changes, wildcard searches and caller DTA protection;
its completion marker is "x32 GEM shell queries: PASS". No additional shell
capability bits are advertised until their corresponding operations exist.

Persistent GEM shell buffers (#838)
----------------------------------

External libaes supplies shel_get/shel_put and mt_* using the standard GEMlib
char-buffer and signed-WORD length signatures. The initial shell buffer has
4192 zero bytes. Successful puts replace the specified prefix, preserve the
remaining bytes and grow storage when necessary, up to 32767 bytes. Shorter
puts never shrink it. Values belong to the GUI context and survive normal,
raw and final application/session exits, so a restarted desktop can recall
its saved context. Native in-kernel AES retains its existing shell storage.

shel_get copies at most the current shell size; excess caller bytes remain
unchanged. Unwritten bytes inside the initial buffer read as zero. Ordinary
successful gets/puts return 1, and invalid arguments or operation failures
return 0. Length zero is a successful no-op, including with a NULL buffer.
SHEL_BUFSIZE (-1) is the standard getter size inquiry and returns the current
size without touching the buffer; other negative lengths are unsupported.
AES_INQUIRE output 2 advertises this size inquiry. No default-desktop, launch
or clipboard capability is advertised by this slice.

Transfers nest display ownership around their context operation. Getter data
is staged privately until the operation and ownership cleanup succeed, so a
failed query/read/release leaves caller output unchanged. Allocation and
source-copy failures do not replace shared data; temporary storage is released
or handed to the existing deferred resource cleanup. An enclosing application
wind_update scope remains owned by the caller.

The generic native primitive is CUIS_CONTEXT (65), with flat registers:

  CONTEXT(session,slot,action,address,length,offset)

Slots 0..3 each hold up to 32767 opaque bytes; libaes uses slot 0 for its shell
buffer. Action 0 reads a snapshot, 1 writes a range while preserving bytes
outside it, and 2 returns the stored extent. Read/write return E_OK or a
negative GEMDOS error. Size returns a nonnegative byte count or a negative
error and requires address/length/offset all zero. Zero-length transfers are
no-ops; reads zero-fill unwritten portions of the requested bounded range.
All calls require the caller's own registered session. Read/write also require
its display ownership; a size query needs no display grab. These shared slots
are intentionally accessible to registered GUI clients, not private mailboxes.
Kernel code never interprets the bytes as GEM structures or pointers.

Read snapshots and write publication use short IRQ exclusion; allocation and
user copies happen outside that exclusion. A write publishes only after its
complete source copy and registration/display revalidation, and rejects an
intervening reentrant update rather than overwriting it with stale data. All
kernel storage and dispatch remain under CONF_WITH_CUIS, selected by external
libaes. Persistent values are bounded independently of the number of clients.

Host tests cover maximum extents, zero filling, partial updates, malformed
calls, allocation/copy failures, peer mutation during a copy and owner exit.
Library tests check size inquiry, growth, unchanged failed-read outputs and
nested display cleanup. The isolated GEM client passes a 6000-byte buffer
between parent and children, checks prefix preservation after normal/_Exit
termination and validates AES_INQUIRE. Its marker is
"x32 GEM shared shell buffer: PASS". The boot memory fixture checks that the
buffer survives the last GUI exit, then explicitly reclaims this intentional
persistent test state before its ordinary allocator leak comparison.

Shared default desktop and clipboard paths (#840)
------------------------------------------------

shel_rdef/shel_wdef and their mt_* forms use the standard GEMlib void
signatures. They read/write the default application filename (up to 12 bytes
plus NUL) and its directory (up to 113 bytes plus NUL). Both fields are one
opaque CUIS context record in slot 1, so a reader sees one complete update.
Until configured, both fields are empty; the upcoming shell/desktop launch
integration supplies the startup default and consumes this state. This slice
stores the metadata; it does not yet launch the configured application.
AES_PCGEM reports out4=1 for these functions; its other fields remain zero.

scrp_read/scrp_write and their mt_* forms read/write an opaque clipboard path
(up to 127 bytes plus NUL) in slot 2. They follow Atari TOS behavior: no path
normalization, directory existence check, file enumeration or file deletion.
A successful read returns 1 even when the path is empty (the initial state).
The desktop can configure its clipboard directory at startup. This is not
the PC-GEM scrap-format bitmap extension; scrp_clear is not provided.

All calls require normal AES registration. Setters reject NULL or oversized
strings without changing shared state. Void functions have no error result;
on a failed read or malformed shared record they leave both caller buffers
unchanged. scrp_* return 0 on failure. Writes publish complete staged records;
a transport failure while releasing ownership can follow a committed write.
Getters validate bounded NUL termination before committing output, and accept
a valid fixed prefix in a larger context (CUIS storage does not shrink).
Nested display ownership is preserved. The records persist across application
and session exit independently of the shell buffer in slot 0. No new kernel
services or feature-independent kernel changes are needed.

Host tests cover maximum bounds, shorter replacement, malformed/truncated
records, transport failures and display nesting. The normal-header GEM test
checks both API forms, capability reporting, independent shell/default/scrap
state and updates surviving normal and abrupt child process exit.

Parallel GEM shell launching (#842)
-----------------------------------

shel_write/mt_shel_write have the standard GEMlib signature (the command is
const void *, the tail is const char *, and the result is short). Initially
only SWM_LAUNCHNOW (1), GEMAPP (1), SHW_PARALLEL (100) is supported. This is the
MagiC parallel execution mode: it returns the new AES/process ID immediately
and sends no CH_EXIT message when that child exits. The parent can continue
using ordinary GEM events while its child runs cooperatively. Standard MiNT
Pwaitpid can collect the child's termination status; this call does not reap
other children or consume the application's messages.

The command is resolved through the existing classic shel_find search, with
its private persistent DTA and original PATH rules. The caller's command/tail,
DTA/search continuation, working directory and display-lock nesting are
preserved. The library stages a bounded command string and an ordinary tail
(length byte 0..126, then that many bytes); it reads only those tail bytes and
zeroes the rest of its private 128-byte tail. Byte 127 and larger are rejected:
ARGV/extended argument passing needs separate implementation. Pexec mode 100
receives a null environment argument to inherit the calling process's GEMDOS
environment and standard files. Its fourth argument uses the ordinary x32
syscall register, with no new kernel service or legacy AES shell bridge.

Invalid registration, malformed/oversized parameters, search or launch failure
return zero. Unsupported selectors are rejected before interpreting their
mode-dependent pointer arguments. The ordinary AES4 SWM_LAUNCH mode 0,
chain/default-shell execution, console applications, accessory launch, ARGV
parsing, extended option structures, shutdown and resolution changes remain
unsupported. AES_SHELL is not advertised until its ordinary launch modes and
reported semantics are implemented. In particular, this API does not yet
replace the desktop's classic shell-launch adapter.

Host sanitizer tests cover short/minimum/maximum tails, bounds and selectors,
search/restore/launch failures and unchanged inputs/DTA. The normal GEM-header
client launches two isolated children with ordinary and 126-byte tails. It
checks inherited environment, captured startup command/tail, concurrent GEM
message exchange, PID/status results, absence of CH_EXIT, balanced display
nesting, working-directory preservation and resumed Fsnext searches.

AES4 GEM launch and child-exit messages (#844)
--------------------------------------------

shel_write/mt_shel_write now also accept SWM_LAUNCH (0), CL_NORMAL (0).
The graphical selector is ignored for this mode. After classic shel_find
resolution, .PRG/.APP (case insensitive) are recognized as GEM applications;
other executable kinds remain unsupported until their console/accessory
ownership semantics are implemented. Ordinary tails retain the 0..126 bound.
The call returns the new AES/process ID or zero. SHW_PARALLEL retains its
separate documented no-CH_EXIT semantics.

For an ordinary mode-0 child, libaes supplies exactly one CH_EXIT message
when the process actually finishes: words are {90,0,0,child_id,exit_code,0,0,0}.
appl_exit alone is not process completion. A normal Pterm result keeps its
full WORD (e.g. 0x1234); faults use the existing native MiNT signal word
(signal << 8). Children that exit or fault without ever registering with AES
are included. AES_MESSAGE out1 bit 5 advertises CH_EXIT; other fields are zero.
AES_SHELL remains unadvertised until its ordinary mode-1/chain semantics are
implemented. No console, accessory, ARGV, chain/default-shell, shutdown or
resolution-change support is implied by this slice.

CUIS retains bounded, opaque process completion records, without interpreting
GEM headers. All kernel additions are selected only by CONF_WITH_CUIS:

  CUIS_CHILD_WATCH(session, action, token, image)
    RESERVE (0), token=image=0: reserve one of 16 records; return a positive,
    never-reused token or a negative error. No allocation is needed.
    BIND (1): associate the reservation with an owned, live, unlaunched
    Pexec(3) basepage. Kernel image metadata supplies its PID; no allocation
    is needed. Started, freed/replaced, duplicate or foreign images fail.
    Completion is recorded for synchronous Pexec(4/6) as well as asynchronous
    starts; the ordinary retained/freeing ownership of those modes is kept.
    Bound synchronous children retain their first fault signal even without
    a scheduler task slot. CH_EXIT reports signal << 8 for a crash, while an
    ordinary Pterm(-1) remains the full 0xffff termination result.
    CANCEL (2), image=0: drop an owned reservation/notice, without killing or
    reaping a child. Tokens from another session or an earlier lifetime fail.
  CUIS_CHILD_LAUNCH(session, token, path, tail, environment)
    Validate ordinary Pexec(100) arguments and load at the executable's link
    address in private child pages, using the existing GEMDOS loader. Bind
    the reserved observer inside spawn, before the child can execute. Return
    its positive PID or a negative error; failures cancel the reservation.
    The observer is an explicit kernel call argument, never a global latch.
    Fixed-address ET_EXEC programs need no retained relocation tables.
  CUIS_CHILD_RESULT(session)
    Non-consuming FIFO peek. Zero means no completion; a positive scalar has
    PID in its high WORD and exit status in its low WORD; errors are negative.
  CUIS_CHILD_PUBLISH(session, expected_result, bytes_address, byte_count)
    Append 1..32 opaque bytes to the caller's existing application pipe, only
    if the same completion is still at its head. Failed copies, allocation,
    or pipe capacity leave it pending; reentrant reservation changes cannot
    publish or consume a replacement notice. Only a successful publication
    consumes the record and nonblockingly reaps that specific child if it is still a native zombie. No unrelated child is read.

Capacity is reserved before CUIS_CHILD_LAUNCH, which runs the standard
asynchronous load-and-go path with a stack-scoped observer. The observer is
bound before the child can start. Early native waits cannot erase a notice or
reorder completions through delayed binding. Validation/load/start failures
cancel the reservation; the GEMDOS loader retains its ordinary image cleanup
and fixed-address loading behavior. The optional BIND operation remains for
callers explicitly using editable Pexec(3) images. Completed
notices survive an explicit application Pwaitpid, and hold their PID identity until publication/cancellation/session
teardown even if the native zombie was already reaped. A session close drops
its records, releasing PID reservations; it neither kills nor reaps live
children. Subsequent registrations do not inherit old notifications.

CUIS_READY_CHILD is a public readiness source in CUIS_SESSION_WAIT, alongside
stream/notice/input/timer readiness. It wakes MU_MESAG immediately, including
during unfinished multi-click accumulation. The interrupted button predicate
retains its original count/deadline in session-owned state and continues
sampling trusted pointer edges while the message is handled; a compatible
subsequent button wait resumes it. Changing the button filter starts a new
predicate. Intervening pointer edges are retained in a bounded private
history: compatible resumption consumes them once; abandonment restores them
ahead of later normal history for the new filter. Stream, key and timer
wakeups preserve a resumed predicate too. A child-publication failure, before
or after the native wait, does not mask ready keys, buttons or timer events. There is no maintenance polling
and no replacement of the application's independent timer. Libaes converts
notices before/after waits and in blocking/nonblocking appl_read; pipe
backpressure preserves existing queued bytes ahead of the new message.

Tests cover bounded reservations/tokens, ownership, completion order, early
completion, copy/allocation/backpressure failures, explicit native waits,
reentrant cancellation/replacement/session exit, PID retention, a completion
interrupting a two-click predicate and unchanged caller output on failure.
Normal-header x32 clients cover full-word exits, exit/fault before appl_init,
exactly-once messages, automatic selective reaping, explicit Pwaitpid retaining
a notice, unrelated Pexec children and unchanged SHW_PARALLEL behavior.

The transitional native AES binding calls its 16-byte message type
AES_CLIENT_MESSAGE, avoiding a collision with GEMlib's standard AES_MESSAGE
capability selector. Legacy-only clients also retain the AES_MESSAGE typedef
when that macro has not been defined. Its binary layout and service ABI are
unchanged; tests cover legacy-only source and both public-header orders.

Deferred classic GEM handoff (#853)
----------------------------------

shel_write/mt_shel_write now accept SWM_LAUNCHNOW (1), GEMAPP (1),
SHW_CHAIN (1). This is the classic TOS/MagiC deferred handoff: return 1 after
preparing the requested executable, then start it only when the calling
process terminates. A failed request returns 0 and keeps the earlier pending
handoff. Subsequent successful calls replace it. The graphical selector is
explicit; filenames are not restricted to .PRG/.APP suffixes in this mode.
Ordinary command tails remain bounded to 0..126 bytes.

This first chain slice supplies the successor handoff. Configured desktop
restoration/startup policy follows separately; this slice does not yet reload
the default desktop after the successor ends. TOS/console mode, ARGV/extended
options and SHW_SINGLE remain unsupported. AES_SHELL remains unadvertised
until the complete launch/default-shell semantics are in place. Existing
ordinary AES4 launches and SHW_PARALLEL keep their behavior.

CUIS_PROCESS_DEFER(session, path, tail, environment) uses flat scalar/pointer
arguments and the ordinary GEMDOS Pexec(100) validation/loader. The caller
must own the live session and run in a managed native group. The loader keeps
fixed-address executables at their link address and prepares a separate
address space, command/environment snapshot, inherited standard files and
working directory before returning. Native success is E_OK, errors negative;
libaes translates those into the standard Boolean GEM result. A null path
with null tail/environment cancels the caller's pending request, idempotently
within the managed group; it does not add a new public GEM function.

The native scheduler owns at most one dormant successor per requesting
process. It uses an ordinary bounded task slot/kernel stack; preparation
finishes before replacing the previous request. Resource exhaustion, invalid
paths and loading/preparation errors preserve the old request. Replacement
and cancellation release the unused image, inherited file/directory refs and
kernel stacks, using the existing kernel close wrapper for disk-error-safe
handle cleanup. No public basepage is dereferenced after the caller's borrowed
mapping has been revoked.

CUIS process cleanup snapshots all live standard-handle aliases before closing
files. An SFT slot can retain its original owner after that owner's explicit
handle has been closed; only a reference beyond the aliases is an explicit
handle for the owner sweep to release. This preserves redirected standard
files in a staged successor, including shared stdout/stderr references.

Dormant tasks never run on yield, delay or appl_exit. Actual normal, raw or
fault termination activates the successor only after process teardown has
finished, including file/directory cleanup of unlaunched owned children.
CUIS process cleanup uses the kernel close wrapper so an interrupted disk
close cannot return to the exiting caller. Nested synchronous callers also
use that process-lifetime trigger. The handoff is detached: its PPID names
the group's stable controller, not the former process. It holds no pointer
to the dead caller and sends no child-exit notification to it. AES session
teardown and re-registration do not remove the process-owned request. All
kernel additions remain under CONF_WITH_CUIS; there is no kernel GEM shell
policy, format negotiation or AES request block.

Host tests cover native ownership/argument validation, cancellation and GEM
Boolean/error translation. Real loader, termination and scheduler host tests
inject interrupted/returned close errors during rejection and exit, checking
resource release and successor activation after complete owner/child cleanup.
Isolated standard GEM clients exercise yield and
AES deregistration before real exit, successful/failed replacement, native
cancellation, normal/_Exit/fault and nested synchronous callers, copied
environment/CWD, redirected stdout with the explicit handle open or closed,
shared stdout/stderr, an executable unlinked after staging, and a full native task
set rejecting replacement while retaining the old request. Full boot memory
accounting verifies that successor images and their replaced/cancelled state
are reclaimed.

Resident external EmuDesk (#855)
-------------------------------
With CONF_WITH_LIBAES and CONF_EXTERNAL_DESK, the BIOS starts EmuDesk as an
ordinary ELF application in a native managed group, without starting the
legacy kernel AES shell. Missing desktops retain the configured EmuCON
fallback. The kernel startup change and keymap lookup are gated by CUIS.

EmuDesk's local historical binding arrays now call standard libaes mt_*
functions. No AESPB or typed legacy AES service handles cross the boundary.
The local wrappers/globals have hidden visibility so they cannot interpose
libaes's own functions and private globals. Existing desktop resources and
drawing remain in the shared AES implementation. Traditional configurations
keep their existing adapters and shell loop.

Normal GEM application launches use AES4 shel_write mode 0. Launch success
no longer means that the desktop should exit: its windows, menus, state and
event loop remain live while children execute. The busy cursor is cleared
on return from launch. Standard CH_EXIT messages refresh directory listings
without restarting the desktop. Both normal termination and faults use the
existing libaes child-completion path. Classic SHW_CHAIN remains separate
compatibility support; it is not EmuDesk's normal launch policy.

Window zero's work/full area reserves the normal GEM menu strip even before
the first menu_bar call. The physical/current rectangle remains the complete
screen. This lets a desktop place its initial objects below the menu bar.

CUIS_KEYMAP_LOOKUP(scancode, table), opcode 71, returns the current unsigned
byte for a hardware scan code 0..127, using table 0 (normal), 1 (shifted), or
2 (caps). Invalid full-width scalar arguments return EINVAL; an unavailable
table returns EINVFN. This read-only hardware-map lookup exposes no pointers
or queued keystrokes. EmuDesk uses it for Alt-letter drive shortcuts, replacing
the old AES-shell query. Tests cover all map entries, changed maps, missing
maps and wide/invalid arguments.

The libaes desktop integration boot opens a real directory window, launches
two independent dynamically linked standard GEM applications, and keeps the
desktop active while both wait for input. It checks exactly one CH_EXIT for
normal and fault exits, preserves the original window and desktop registration,
and opens another directory window afterward. Screenshots are captured with
both applications and after their exits. The same runner retains legacy desktop
coverage when libaes is disabled, and missing-desktop fallback coverage.

At this slice, console/ARGV/accessory launch, shutdown and resolution-changing
shell policies were deferred. Classic console launch is added below; shutdown
and resolution menu actions remain disabled. AES_SHELL stays unadvertised.

Resident console children (#859)
-------------------------------
Standard shel_write/mt_shel_write mode 0 classifies PRG/APP/GTP as graphical
and TOS/TTP as text applications, without treating isgem as authoritative in
that AES4 mode. It returns the child's ID immediately, retains the launcher's
registration and delivers the existing single full-word-status CH_EXIT on
normal/fault exit. Tails still use the ordinary 0..126-byte convention; ARGV,
accessory and mode-1 text execution are not implied.

CUIS_CHILD_LAUNCH(session, token, path, tail, environment, console) adds a flat
sixth scalar: 0 keeps graphical behavior, 1 requests the physical text console.
Other values fail with EINVAL. A second console, foreign drawing ownership or
modal mouse/keyboard capture rejects launch with EAGAIN and cancels the child
reservation. The launcher's own update nesting remains balanced. Loader and
spawn errors cancel the reservation without entering text mode. The existing
spawn observer retains the new child's identity before user execution; the
current cooperative scheduler cannot run it before launch setup returns.

The full-screen lease belongs to the child process, independently of the
launcher's session and of the child's optional AES registration. Native VDI
screen writes and new GUI display/mouse ownership wait or fail during the
lease. Keyboard input goes to the existing BIOS console queue; pointer input
is suppressed for GUI clients and the graphical cursor stays hidden. VDI uses
its original alpha/graphics escape transitions, including recovery from a
trailing incomplete console escape. Actual process teardown releases the lease,
restores cursor policy, invalidates the active menu/background/windows and
queues ordinary redraw work. Closing an AES session does not release it.

BIOS console reads use the generic CONF_WITH_NATIVE_SCHED wait helper to let
other managed tasks run while input is unavailable. Legacy configurations keep
their previous input loop. This does not add preemption or Pfork (#713).

EmuDesk keeps its event loop and directory state while TOS/TTP children run.
File/Show EmuCON (Ctrl-Z) launches EMUCON.TOS when external CLI support is
configured, and returns to the same desktop on exit. The embedded-console
configuration keeps that menu item disabled; exporting an embedded CLI as a
loadable child is outside this slice. Missing external consoles fail normally.

Host/sanitizer tests cover failed/busy launches, invalid flags, retained update
nesting, VDI/input exclusion, launcher's exit, child's AES deregistration and
process cleanup. Real desktop tests launch TOS and TTP programs that use only
GEMDOS console I/O, send keyboard input/parameters, exercise normal and fault
exit, run the external EmuCON, and verify one CH_EXIT without restarting EmuDesk.

Standard ARGV and launch environments (#861)
------------------------------------------
AES4 shel_write/mt_shel_write mode 0 accepts CL_PARSE as well as CL_NORMAL.
CL_PARSE converts the command text into a private ARGV environment: ordinary
tails retain their counted 0..126-byte format; byte 127 selects a NUL-terminated
long string at tail+1. Space/tab delimit arguments, matching single/double
quotes group them, doubled matching quotes represent literal quotes, and
backslashes remain literal. Unmatched quotes and embedded NULs in counted
text fail before launch. Empty quoted arguments use the standard ARGV=NULL:
index list with nonempty placeholders; LD.SO validates that list and restores
empty strings on the child's private initial stack. Indices include argv[0],
and may be repeated or unordered. AT_EXECFN retains the executable identity.

SW_ENVIRON (0x0800) combines with the implemented mode 0/1 calls. Command then
points to the standard GEMlib SHELW layout; newcmd names the executable and
env supplies its ordinary double-NUL environment. NULL means inherit, while
an empty double-NUL block supplies no variables. Other upper-byte flags fail
before the overloaded command is dereferenced. Default-directory, memory/
priority, UID/GID and MagiC flags are not silently accepted. SWM_ENVIRON, the
separate AES environment-management mode, is not implemented by this slice.

CL_PARSE retains ordinary inherited/explicit variables up to the ARGV marker,
replaces an old argument payload and supplies argv[0] from the shel_find result.
It does not expand variables, interpret redirection or run another shell.
CL_NORMAL with byte 127 instead copies an existing ARGV environment unchanged,
without reading command text beyond that marker byte. The MagiC byte-255 tail
shorthand remains unsupported. Mode 1 keeps its existing SHW_PARALLEL/SHW_CHAIN
meaning; CL_PARSE is a mode-0 selector, not a replacement for MagiC's modes.

Preparation uses bounded caller-local allocations. The total encoded block,
including filename, empty-index list and terminators, must fit the existing
32766-byte GEMDOS environment limit. Copies include padding for the loader's
even-size read. Temporary storage is released after immediate or deferred
loading and on failure, without changing parent buffers, DTA, CWD, environment
or descriptors. Console ownership and full-word CH_EXIT remain the existing
launch policies; there is no new CUIS syscall or request structure.

Host/sanitizer cases cover quoting/empty arguments, long tails, explicit/raw
ARGV, empty and maximum-size environments, allocation and launch failures and
cleanup. Ordinary GEM source compiled against unmodified GEMlib headers runs
in isolated children, checking inherited/explicit environments, 400-byte
arguments, spaces/quotes/backslashes, empty strings, raw argv[0], console launch
and exactly one CH_EXIT. ELF tests exercise valid/malformed NULL index lists;
the combined boot retains final memory accounting and the desktop regressions.

Resident accessories and Desk registration (#863)
------------------------------------------------
The external desktop starts up to six .ACC programs from the root of its
initial drive after installing its own menu bar. It uses ordinary independent
AES4 shell launches, preserves the parent's DTA, honours the boot skip flag,
and does not relaunch accessories when reloading desktop preferences. These
are native x32 ELF programs linked with libaes and the shared runtime, not
legacy kernel-AES accessory images. dynacccrt.o uses the same shared startup
as dyncrt.o and initializes the standard GEM _app variable to zero in the
image, so preinitializers and constructors already see accessory state.
The ordinary dynamic CRT supplies a weak _app=1 definition for applications.

menu_register/mt_menu_register register the caller's application ID and copy a
nonempty title of up to 127 bytes. The six classic Desk slots return IDs 0..5;
full registration, an invalid ID/global array, or an invalid title returns -1.
Several entries may belong to one session. REG_NEWNAME (-1) instead updates
the eight-character appl_find label, consumes no Desk slot and returns zero
on success. A registration disappears at appl_exit or process teardown.

Each application's libaes reads the current directory when tracking a menu.
It constructs a private Desk dropdown from the caller's About item, a disabled
separator, and registered titles. The original menu_fixup child linking is
shared as aes/shared/gemdesk.h; caller resource objects remain unchanged.
Registered items send AC_OPEN to the original, non-recycled native session:
word 1 is the sender's AES ID, word 2 is zero and word 4 is the menu ID.
They do not generate MN_SELECTED for the application displaying the menu.
The library deselects the Desk title itself. Message delivery happens after
releasing display/mouse ownership and may wait for a different recipient's
stream space. Self-directed AC_OPEN stays nonblocking: the event loop drains
earlier messages before retrying the pending write, just as for MN_SELECTED.
A vanished recipient is discarded without selecting a replacement process
that subsequently occupies the same menu slot. APR_NOWAIT flushes do not block.

Three new flat native calls publish opaque session-owned data, not GEM trees
or messages. All are under CONF_WITH_CUIS, including trap dispatch:
  CUIS_ENTRY_PUBLISH (72): session, slot, zero, data, byte count -> slot
  CUIS_ENTRY_OWNER   (73): session, slot -> owner's session handle
  CUIS_ENTRY_READ    (74): session, slot, expected owner, data, capacity -> bytes
The bounded directory has 64 slots of at most 128 bytes. libaes uses slots
0..5 and includes its terminating NUL; other native slots remain available.
Publishing an occupied slot returns EAGAIN; reading an owner that changed
since lookup returns EAGAIN; an empty slot returns EFILNF. Short read buffers
return ERANGE. Data passes through kernel stack snapshots around user copies,
with ownership rechecked after copying publication input. Session teardown
removes every entry before freeing its owner. No GUI server is introduced.
Opaque entries that are empty or lack one nonempty NUL-terminated label are
ignored when building GEM menus, including embedded-NUL payloads. Genuine
directory read failures still propagate; unrelated binary entries cannot
abort another application's File or Desk menu tracking.

In this multitasking AES, launching, switching or terminating another program
neither resets accessory windows nor sends AC_CLOSE. An accessory's window
closer can close its UI while the process remains resident for another
AC_OPEN. Standard AC_CLOSE is declared and can travel through appl_write;
a system-generated reset accompanies partial/complete shutdown as described
below. Live resolution switching and single-tasking DA cleanup remain
unavailable.

Host regressions cover registration bounds, caller identity, REG_NEWNAME,
all directory slots, ownership and teardown, expected-owner stale reads,
Desk slot-to-message mapping, backpressure and disappeared recipients, and
unchanged caller menu objects. The native desktop regression starts a shared
accessory, checks _app, closes/reopens it, keeps its window alive across GUI
and console child success/fault exits, and exits it without restarting the
desktop or leaving its registration in the next Desk popup.


Application discovery and activation (#865)
------------------------------------------

Applications use standard appl_search(APP_FIRST/APP_NEXT/APP_DESK). Successful
calls write an eight-character padded executable/REG_NEWNAME label plus NUL,
the GEM application ID, and APP_APPLICATION or APP_ACCESSORY. The currently
registered desktop additionally has APP_SHELL. APP_DESK does not disturb the
FIRST/NEXT cursor. Enumeration uses monotonically increasing native handles;
closed sessions disappear and no old handle names a new session. Negative
extended-description modes fail without changing caller outputs.

appl_control(APC_TOP) raises all the selected client's open windows while
preserving their relative order. A windowless client can receive keyboard
focus, including a menu-only application. APC_INFO returns APCI_HASMBAR and
APCI_HASDESK; ID -1 queries the active application. Hiding/showing applications,
remote menu pointers, widget/configuration and signal modes are not supported.
These modes fail without reading or writing the mode-specific output pointer.
AES_PROCESS advertises appl_search. AES_MESSAGE advertises AP_TERM and CH_EXIT;
AES_SHELL and the combined shutdown/resolution capability remain unadvertised.

Native metadata calls use flat arguments after the CUIS opcode:

  75 PEER_NEXT: session, after -> next live handle; -1 starts, EFILNF ends
  76 PEER_QUERY: session, peer, field, address, capacity -> scalar or byte count
  77 SESSION_TAG: session, opaque nonnegative 31-bit tag -> E_OK
  78 PEER_RAISE: session, peer -> E_OK

PEER_QUERY LABEL copies up to 32 opaque bytes without adding a terminator;
TAG returns the tag, STATE returns HAS_SURFACE/HAS_BACKGROUND flags. BACKGROUND
and ACTIVE return those peers' handles and require peer/address/capacity zero.
IDENTITY (field 5) copies exactly 16 bytes of CUIS_PEER_IDENTITY_DATA:
client_id, process_low, process_high, reserved=0. The positive short client ID
belongs to the GUI endpoint; the non-recycled PROCESS number is generic KPROC
identity, not a PID/TID or pointer. The client retains KPROC identity until
final reclamation, without extending live PD/resources. This reference also
reserves its PROCESS PID, so retirement must release it promptly after the
last operation lease ends. The descriptor is
snapshotted under the GUI lock before copyout, so no peer pointer survives
user access. Several client descriptors may share one PROCESS number.
Wrong descriptor size is EINVAL; stale endpoint is EFILNF; failed copyout is
EIMBA with no consumption. Private slots 28 and 29 are retired (EINVFN).
The existing caller binding is not a promise of one client per PID; future
THREAD/client bindings remain #896/#915 work.
LABEL requires enough buffer space. The library publishes eight-byte labels
and stores its GEM type and NM_APTERM consent in the opaque tag. Native code
does not interpret the tag or impose GEM naming/type policy. Raising rejects
conflicting grabs, pointer captures, console ownership and foreign rendering
locks rather than breaking a live GUI interaction.


Shutdown lifecycle (#865)
-------------------------

Standard shel_write uses flat GEM arguments, including the normal third
argument wiscr for SD_ABORT (0), SD_PARTIAL (1) or SD_COMPLETE (2):

  shel_write(SWM_NEWMSG, NM_APTERM, 0, NULL, NULL)
  shel_write(SWM_SHUTDOWN, 0, SD_COMPLETE, NULL, NULL)
  shel_write(SWM_AESMSG, 0, 0, failure_message, NULL)

Consent is per live AES session and resets on appl_exit/reinitialization.
Shutdown first captures the registered clients and validates every participant
before publishing requests. Ordinary applications must opt into AP_TERM;
complete shutdown also requires accessories to opt in. Unsupported/raw clients
and accessories still registering their Desk entries cause immediate failure,
with no termination messages. New AES registrations fail while coordination
is active; existing sessions remain usable for cleanup and rendering.

Partial shutdown terminates applications and closes accessory UIs, leaving
the accessory processes resident. Complete shutdown terminates both classes.
Each registered accessory entry receives AC_CLOSE with its ID in word 3;
libaes resets that accessory's windows before delivering the first AC_CLOSE.
AP_TERM has sender word 1 equal to -1 and reason word 5 equal to AP_TERM.
Applications finish normal cleanup and leave AES. An application can refuse
through shel_write(SWM_AESMSG) with an AP_TFAIL message; its opaque error word
is preserved for the initiating program. A refusal is accepted only after
that participant has read at least one message from the current request.
A non-exiting accessory acknowledges after consuming all its AC_CLOSE messages
and entering its next library wait/read, allowing it to report refusal first.

The initiator receives exactly one SHUT_COMPLETED when all required clients
have left AES or acknowledged. Success retains the registration barrier until
the initiator leaves AES or calls SD_ABORT. Refusal clears the barrier when its
result is published. Only the initiator can abort; its exit also cancels the
operation. Cancellation cannot retract messages already read by applications.
No kernel code decodes AP_TERM, AC_CLOSE or any other GEM message.

The resident desktop opts in, starts complete shutdown from its menu, remains
alive through preparation and completion, and calls GEMDOS Shutdown(SHUT_POWER)
only after its own native operation has completed and desktop cleanup finishes.
Escape cancels pending coordination. The menu remains unavailable when the
configuration or machine lacks poweroff support. Live resolution changes
currently return GEM failure before starting coordination or affecting clients;
the desktop resolution command remains disabled on this x32 backend.

The native closed-cohort transport is bounded to 128 opaque request/result
bytes per client. Calls 79..87 take the following flat arguments:

  BEGIN: session -> positive token; fails if a cohort or GUI grab/lock is active
  STAGE: session, token, peer, address, bytes, wait_exit -> E_OK
  COMMIT: session, token, completion_address, completion_bytes -> E_OK
  QUERY: session, selector -> ID, WORK, owner-only STATE or read provenance
  READ: session, token, address, capacity -> request/result bytes
  PUBLISH: session, token, optional rejection_address, rejection_bytes -> E_OK
  ACK: session, token -> acknowledge an entirely consumed non-exiting request
  REJECT: session, token, address, bytes, consumed_bytes -> E_OK
  CANCEL: session, token -> E_OK (owner only)

STAGE and COMMIT snapshot bounded data with identities rechecked after user
copies. COMMIT requires every remaining captured participant to be staged;
exiting participants leave the cohort automatically. WORK returns REQUEST,
ACCEPT or RESULT only when actionable, and zero otherwise; CUIS_READY_COHORT
wakes ordinary native waits for that internal work. Publication never blocks
and waits for sufficient caller stream space. Reads preserve normal byte-stream
ordering and track request consumption across preexisting data and split reads.
REJECT with consumed_bytes zero allows rejecting unknown opaque requests before
publication. A nonzero value requires that many request bytes already consumed;
libaes uses 16 for AP_TFAIL to reject premature/stale replies. Tokens never
recycle. Successful result publication sets owner STATE to FINISHED (4), which
the desktop checks before accepting a queued SHUT_COMPLETED notification.
READ_OFFSET and READ_BYTES authenticate the last successful stream read wholly
inside a current participant request. Prefix/overlapping ordinary messages,
failed reads and cancelled generations do not gain request provenance. Native
CUIS still treats the payload as opaque bytes. RESULT_ID, RESULT_OFFSET and
RESULT_BYTES identify a read wholly inside a published result, including after
a refusal has cleared the cohort. That identity retains the producing token
when a new operation starts. Ordinary writes and overlapping reads have no
result provenance. libaes matches shutdown completion/refusal to its initiating
token; the desktop also checks that token before clearing pending shutdown and
does not cancel another operation on receipt of a refusal.

libaes preflights the complete request against its private accessory status,
NM_APTERM consent and registered entry IDs before publication. A malformed
suffix cannot cause an earlier AC_CLOSE to reset windows. Standard 16-byte
message reads ignore AP_TERM/AC_CLOSE without current native request provenance;
unframed appl_read transfers retain their byte-stream semantics. The desktop
also checks native delivery provenance before honoring AP_TERM. Window reset
happens immediately before returning the first authenticated AC_CLOSE, after
any queued AC_OPEN and earlier window messages have been processed. The
remaining AC_CLOSE messages do not repeat that reset. Peer activation defers menu ownership and clipping changes until the caller
releases its display lock. Cohort maintenance does
not interrupt an accumulating multi-click or restart a public timer deadline.

Host tests cover metadata, stable enumeration/activation and opaque cohort
ownership, staging, split consumption, cancellation, refusal, teardown and copy
failures. Native GEM tests cover unaware, accepting and refusing applications,
an accessory with two entries, partial/complete requests and abort. Desktop
integration opens a real application and accessory and verifies both leave
before actual emulated poweroff. The combined boot also verifies final memory
accounting and existing message/event/window regressions.


Lifecycle delivery ordering and polls
------------------------------------

CUIS_STREAM_PEEK (88) has the STREAM_READ arguments and copies/provides native
provenance without consuming bytes or acknowledging the request. It validates
the entire user destination just as READ does. CUIS_STREAM_PENDING (89) takes
only the owned session, with other arguments zero, and returns the byte count.
These remain opaque native stream operations; the kernel decodes no GEM data.

libaes flushes pending window notices before appending a lifecycle request.
At the first AC_CLOSE it resets the accessory immediately before delivery and
records the already-queued byte range. Window messages for positive handles
inside that old range are discarded after reset, even if a new window reuses
an old GEM ID. Other messages, window-zero redraws and subsequent notices keep
their normal order.

Nonblocking appl_read and evnt_multi polls do not consume AC_CLOSE when its
reset cannot acquire the display lock. Combined event waits also use a
nonblocking reset, preserving independent input and timer deadlines. Internal
waiting switches from the queued stream head to display availability until
reset can proceed; cancellation clears that deferred state. The generation is
checked again after acquiring a contended lock. Raw transfers of lengths other
than 16 retain their byte-stream contract.

A result's token authenticates its origin, not its meaning. SHUT_COMPLETED is
accepted only in native FINISHED state; a native rejection carrying that opcode
is reported as generic AP_TFAIL. Repeated APC_TOP on the already-active
windowless client preserves its queued keyboard input.


Malformed rejection adaptation and pending menus
-----------------------------------------------

An initiating adapter may pass replacement opaque rejection bytes to PUBLISH
while it owns a refused cohort. Native code bounds/copies those bytes,
rechecks the owner/token after the user copy, and uses the replacement length
for stream backpressure and provenance. A failed copy preserves the original;
insufficient stream space retains the replacement for a later publication.
Participants cannot replace their requests or another owner's result. No GEM
message is interpreted in the kernel.

Before publishing a refused shutdown, libaes accepts only one 16-byte AP_TFAIL
with no extended payload. Other opcodes, lengths and extended headers become
a single AP_TFAIL with generic error 1. This preserves message alignment and
ensures the initiating desktop receives a refusal after the native barrier is
released. Ordinary valid AP_TFAIL errors retain their original value.

While the desktop waits for shutdown, ignored MN_SELECTED actions still call
menu_tnormal so their titles do not remain selected after refusal/cancellation.
The desktop UI regression selects an ignored View action while an accessory
is delaying termination, checks title normalization, then completes poweroff.
Native lifecycle tests exercise unknown, short, odd, oversized and extended
rejection payloads and verify ordinary operation/launches afterward.


Explicit immediate and parallel shell launches (#867)
----------------------------------------------------

SWM_LAUNCHNOW (1) accepts SHW_IMMED (0) and SHW_PARALLEL (100) with either
GEMAPP (1) or TOSAPP (0). This explicit kind overrides the filename extension:
a .TOS image may run as a GEM client, and a .PRG image may own the console.
SHW_IMMED launches concurrently and reports its standard CH_EXIT completion;
SHW_PARALLEL sends no CH_EXIT and leaves ordinary MiNT child waits/reaping to
the parent. Both return the positive child ID or GEM failure zero.

TOS launches use the existing exclusive native console lease, including before
the child's first timeslice. The desktop and GUI peers remain resident. Normal
exit and faults restore their drawing/input access. No single-task scheduler
freeze or normal desktop chain load is introduced. ARGV and SW_ENVIRON use the
same launch snapshots and caller ownership as the existing shell modes.

CUIS_CHILD_LAUNCH keeps its flat session, observer-token, path, tail,
environment, console arguments. A zero token is permitted only for a console
launch: the scheduler's spawn hook attaches the console identity without an
AES child observation, queue entry or automatic reap. Other owned reserved
observations remain intact, even when that table is full. Normal mode 0 and
SHW_IMMED still reserve/bind their completion before execution. All kernel
changes remain gated by CONF_WITH_CUIS.

SHW_CHAIN retains the existing deferred GEM handoff. Explicit TOSAPP chain
handoff, SHW_DOS, SHW_SINGLE and further extended launch flags remain
unsupported; these selectors fail before touching overloaded command/tail
arguments. CL_PARSE remains the mode 0 argument policy, not a reinterpretation
of the numeric SHW_CHAIN selector. AES_SHELL remains conservatively
unadvertised while its other modes and flags are incomplete.

Host tests cover explicit launch selection, empty/full observation tables,
errors, lease restoration, retained observations and interrupted-launch
cleanup. Isolated GEM tests use both public bindings, override both filename
classes, check immediate notifications and the absence of parallel notices,
reap normal/fault console children through Pwaitpid and verify display access
before and after each launch. The combined boot checks its pass marker and
final process/memory accounting; the resident desktop launch/return regression
continues to exercise ordinary mode 0 behavior.

Shell launch directories (#869)
--------------------------------

libaes accepts standard SW_DEFDIR (0x0400) on the implemented mode 0/1
launches. SHELW.defdir is read only with that bit set; SHELW.env is read
only with SW_ENVIRON. Both flags may be combined. A non-NULL defdir is
resolved against the caller's drive and per-drive directories. NULL
selects the executable directory. Mode 0 and SHW_IMMED default to the
executable directory; SHW_PARALLEL and deferred SHW_CHAIN otherwise retain
the inherited paths. No temporary Dsetpath/Dsetdrv is performed in the
caller. Empty, invalid, missing or oversized directories fail the launch.

For directory-changing launches libaes first makes the executable name
absolute. The loader opens that executable relative to the caller, then
sets only the child's current directory/default drive after taking its
inherited directory references, before scheduler publication or any
executable preinitializer. Startup command/resource metadata therefore
still identifies the executable when defdir differs from its directory.
A failed directory setup releases the child image, environment, handles
and inherited directory references; a previous deferred successor survives.
Console failure also releases its tentative lease and child observation.

Native calls remain flat and carry no GEM flags or SHELW structures:

  CUIS_CHILD_LAUNCH_DIRECTORY (90)
      (session, token, path, tail, environment, directory) -> child PID/error
  CUIS_CONSOLE_LAUNCH_DIRECTORY (91)
      (session, token, path, tail, environment, directory) -> child PID/error
  CUIS_PROCESS_DEFER_DIRECTORY (92)
      (session, path, tail, environment, directory) -> zero/error

The directory address must name a nonempty terminated string of at most
259 bytes, copied before loader I/O. Filesystem path limits still apply.
A zero observation token is allowed on either directory-aware immediate
call; such children remain available to Pwait/Pwaitpid without CH_EXIT.
The console opcode acquires the existing exclusive display/input lease.
The original calls 69/70 keep their argument counts and inherited-directory
behavior; unused registers never become implicit arguments. All native
loader/directory support is guarded by CONF_WITH_CUIS, currently available
only on x32 with the built-in FAT filesystem.

Host regressions exercise flag isolation, absolute/drive-relative directory
resolution, caller drive/path isolation, directory-reference replacement,
failed setup disposal and retention of a pending deferred successor.
Native boot tests check the directory in executable preinitializers for
GEM/console immediate and parallel launches, custom environments and NULL
or relative defdir, caller isolation, invalid-directory console recovery,
and explicit/NULL-directory deferred handoffs.

Shell compatibility scope audit (#871)
-------------------------------------

The complete mode/flag/tail inventory is in doc/libaes-shell-compatibility.md.
It distinguishes existing .ACC startup from forced SWM_LAUNCHACC (mode 3),
which remains unavailable. Missing launch/classification/tail forms are
tracked by #873; broadcast/shared shell environment by #874; child resource,
priority and identity flags by #875; vendor execution/thread/lifecycle
profiles by #876; live x32 mode switching by #877. These are explicit
follow-ups after the initial x32 cutover. The other API-family audit and
kernel-AES configuration/removal gates remain open in #661.

Public standard selector constants do not establish runtime capabilities.
AES_SHELL remains unadvertised. Unsupported modes and launch flags return
GEM failure before their overloaded command/tail/output pointers are read.
Unknown supported-mode message payloads are inspected only according to the
implemented mode's contract; this does not validate arbitrary user pointers.
The host shell regression checks rejected modes/flags/tails without launch,
search/DTA, current-directory, allocation or native-service side effects.

External desktop without kernel AES (#878)
------------------------------------------

pc-x86_64-libaes-desktop_defconfig builds the resident shared desktop with
CONF_WITH_AES=n, CONF_WITH_X32_AES=n, CONF_WITH_LIBAES=y and the native VDI
service. Shared GEM rendering/resource and desktop options are available
without linking the kernel AES; its stack and loadable-cursor configuration
remain legacy-only. Normal non-GUI and ARM/m68k legacy defaults are preserved.

The desktop links only its resource/layout helpers and standard GEM adapter,
libaes.so and libptos.so, alongside the VDI client. It neither links the typed
AES client archive nor compiles unused local legacy AES resource/form/object
adapters. The existing BIOS CUIS desktop path starts it directly. Missing
external desktop files fall back to external or embedded EmuCON, according
to configuration. No single-task desktop handoff is introduced.

The shared-consumer CI configurations explicitly disable both kernel AES
implementations, assert CUIS is present and legacy AES service symbols are
absent, then run desktop/accessory/GEM/console, shutdown and CLI fallback
checks. Kconfig tests cover resource defaults, unavailable desktop without
VDI/libaes, legacy ARM/m68k defaults and the independent desktop preset.
Final AES/CUIS exclusion, address-space constraints and old service/client
removal remain separate #661 gates; this slice enables the independent path
needed to validate that cutover.

Private native helper boundary (#880)
-------------------------------------

libaes exports only standard GEM bindings, their mt_* forms, standard binding
state and the documented local rectangle helpers. Native aes_* session/window/
input/message helpers remain inside the library; include/libaes.h is removed
and internal declarations live in lib/aes/native_bindings.h. Applications must
include gem.h or normal GEMlib headers, without CUIS setup or private imports.

The native CUIS ownership/buffer/scalar/fault/scheduler probes retain direct
syscall coverage through tests/cuis/native_probe.h. Their test-local helpers
are not shared-library exports. GEM object/drawing checks keep standard GEM
headers and bindings; native transport probes are explicitly separate from
claims about GEM semantics. Kernel exit remains authoritative for native
session/window cleanup, including faults and _Exit.

The compatibility inventory rejects any private aes_* export except standard
aes_global state, with a regression for attempted reintroduction. Dynamic
fixture links and full native boots verify no private helper imports remain.
This does not remove the older typed kernel AES service or its legacy tests;
that migration and final configuration/service removal remain #661 gates.

Kernel AES cutover (#882)
------------------------

Kernel AES is selectable only without per-process address spaces and without
CUIS. The old typed x32 AES service, its native client/import namespace and
kernel-owned object snapshot/validation machinery are retired. Standard GEM
clients use libaes; native CUIS/VDI syscall ownership and buffer validation,
raw malformed-input probes and generic callback protections remain in place.
The generic ring-3 GEM trap and retired typed AES class reject calls without
inspecting supplied pointers. ARM/m68k single-address-space kernel AES remains.

Non-shell extension follow-ups are #884 (events, replay and application
control), #885 (menus, objects and windowed forms), #886 (window and clipboard
extensions), and #836/#849 (extended resource formats). They do not advertise
unimplemented capabilities or prevent the scoped initial cutover.

Complete the desktop/accessory, standard GEM, RCS, callback/fault/cleanup,
CLI/fallback, legacy architecture and release matrix before integration. Merge
current master into the epic and resolve conflicts before marking #681 ready.

Generic timer clock source (#907)
--------------------------------
libaes deadline and arrow-repeat calculations read the authoritative hz_200
through GEMDOS Ssystem(S_GETLVAL,0x4ba,0). The userspace adapter retains the
low-31-bit tick ring and original timer deadline across internal GUI wakes.
This clock requires neither a CUIS session nor GUI registration. The maximum
supported 32-bit millisecond timeout remains shorter than its wrap.

Executable identity (#907)
-------------------------
libaes reads the current loaded-image basename from generic
Ssystem(S_PROCNAME=-7), independently of CUIS registration. PROCESS metadata
is copied from a retained identity into kernel-local storage before copyout;
its bounded name survives PROCESS retirement without retaining the PD. AES
label folding, eight-character naming and .ACC classification remain libaes
policy. Private CUIS slot 25 is retired and returns EINVFN.
