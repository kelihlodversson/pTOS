pTOS - userspace AES and kernel CUIS (#661)
==========================================

Migration boundary
------------------

The target is an ordinary per-process libaes.so over native Core User
Interface Services (CUIS). There is no userspace AES daemon. Kernel CUIS
owns shared authoritative GUI state; VDI owns drawing/hardware services.
The initial #675 slice implements sessions and application-local rectangle
helpers. #679 adds caller-local object-tree editing and coordinate calculation. It does not yet supply a complete GEM AES API or replace the
existing kernel AES. Existing x32 import clients remain available while
operations migrate; they are not the native CUIS protocol.

GEM source compatibility is the public contract. Applications use standard
GEM headers, function names, signatures, structures, constants and return
conventions (appl_*, evnt_*, wind_*, menu_*, form_*, objc_*, graf_*, rsrc_*,
shel_* and scrp_*). The aes_session_*, aes_window_*, aes_message_* and similar
CUIS wrappers currently exported for migration tests are transitional
implementation helpers, not a replacement application API. Move these behind
the library boundary as the standard adapters migrate; applications must not
need CUIS handles, sender grants or other pTOS-specific setup calls.

Preserve GEM behavior as well as syntax: application IDs and discovery,
message layouts/lengths/ordering, blocking and nonblocking reads, event masks
and multi-event results, click/rectangle/timer predicates, focus and window
messages, redraw iteration/update locking, and resource/object ownership.
Map private CUIS handles/errors to the documented GEM IDs/results; do not
truncate native handles into WORD application IDs or leak negative CUIS
errors through APIs whose GEM convention is Boolean. The initial four-word
transport is a foundation, not a permanent 16-byte limit on appl_write/read.

Inventory meaningful MultiAES, MagiC and XaAES extensions against tos.hyp and
GEMlib headers, with a per-feature support/semantics/test matrix. Implement
applicable extensions through the familiar API, including mt_* entry points
where provided by the chosen GEM binding. Report unsupported features using
the documented AES conventions and capability queries; never claim support
through appl_getinfo before it exists. These GEM compatibility queries are
library behavior, not version negotiation in the CUIS syscall protocol.
Compile representative existing GEM source against the normal headers and
link to libaes, then exercise its behavior in isolated x32 clients before
claiming the migration complete. Kernel primitives must permit these
semantics; hiding a conflicting protocol behind a renamed wrapper is not
sufficient.

Inventory of the current implementation and intended ownership:

                                                bounded authorized delivery

Current sources expose the migration points: gemaplib/gemevlib/gemasync and
aes_service.c combine registration, scheduling, GEM messages and waits;
gemwmlib/gemwrect and aes_window.c combine authoritative windows with
GEM decorations; gemoblib/gemobjop/gemobed, aes_tree.c and
aes_objects_kernel.c implement tree operations; gemrslib/rsload_portable
load resources; gemfmlib/gemmnlib/gemgraf implement local interaction and
rendering with scheduler dependencies. These dependencies must be split,
not copied wholesale into the shared library. Native CUIS must never expose
AESPD, EVB, WINDOW, GEM message arrays or kernel pointers.

Initial implementation and deployment
------------------------------------

CONF_WITH_LIBAES is off by default and initially depends on x32 and
CONF_WITH_ELF_SHARED. It selects the internal CONF_WITH_CUIS kernel support.
It does not require the old AES service or a desktop just to use sessions
and local geometry. Other architectures await their isolated address spaces
and shared-linker support. Native m68k trap compatibility is a later slice.

The build produces obj/libaes/libaes.so (SONAME libaes.so, SysV hash,
ordinary PIC ELF32/x32), installed with the LD.SO runtime at:

    obj/ldso/runtime/GEMSYS/LIB/X32/LIBAES.SO

A native executable links to -laes and the dynamic CRT, and records an
ordinary DT_NEEDED for libaes.so. No PT_PTOS_IMPORTS, fixed client image or
kernel symbol resolution is used. The transitional test interface is
include/libaes.h: aes_session_open/query/close and the existing local
inside/rc_constrain/rc_equal/rc_intersect/rc_union geometry helpers.
The library remembers its session in private writable data for normal
finalization. Kernel process teardown is authoritative on faults, _Exit
and any skipped library cleanup. Starting a session is idempotent for one
process. Handles never recycle during a boot, including end/restart by the
same process.

Native scalar session syscalls
------------------------------

include/cuis.h defines the x32 syscall class 0x103 and individual function
numbers. RAX contains (0x103ULL << 32) | function. Arguments are passed
flat in registers using the normal native RDI/RSI/RDX/R10/R8/R9 convention;
the result is returned in RAX. The session calls use only RDI, for a handle,
or no arguments at all. Unused registers are ignored. Kernel-mode calls and
builds without CUIS return EINVFN.

    Function  Call                    Success result
    --------  ----                    --------------
    0         session_start()         Non-negative session handle
    1         session_query(handle)   0 if the caller owns this live handle
    2         session_end(handle)     0 after revoking the caller's session

All calls return a negative GEMDOS error code on failure. The corresponding
libaes.so functions are aes_session_open(), aes_session_query(handle) and
aes_session_close(handle), with the same scalar results. There are no
parameter blocks, reply structures, version fields or feature negotiation.

Handles range from 0 through 0x7fffffff; zero is a valid handle. Session
start returns an existing handle if the caller is already registered, or
allocates one session. The allocator stops at the signed 32-bit limit so
success can never be mistaken for a negative error. Sessions are bounded
to one per process; no session call yields or waits.

The kernel validates the full-width handle slot before narrowing it.
Out-of-range handles return EINVAL; foreign, stale or missing handles
return EACCDN. Unknown function numbers return EINVFN, and allocation or
handle-space exhaustion returns ENSMEM. A failed allocation publishes no
session and consumes no handle. The current kernel process establishes
ownership; a handle grants no authority over another process's session.

Caller-local GEM object operations (#679)
----------------------------------------

libaes.so exports objc_add(), objc_delete(), objc_order() and objc_offset()
over the application's own native OBJECT array (24-byte entries on x32).
These are ordinary C functions and need no CUIS session. No tree, object
specification or output pointer crosses a syscall boundary. Resource loading,
rendering and hit testing with display metrics are subsequent slices.

The #730 slice adds objc_find() and mt_objc_find(), plus mt_* forms of the
editing/offset calls above, with standard GEM signatures. Hit testing uses
logical object rectangles in screen coordinates, includes the starting object
at depth zero, excludes hidden subtrees, and gives later siblings precedence.
Each child list is scanned once before descending into its last matching
child, keeping traversal linear without recursion or temporary arrays.
Right/bottom edges are exclusive. A non-root start includes its ancestor
offsets. No hit (or a negative start/depth) returns -1. The search is iterative
and does not invoke USERDEF callbacks or dereference object specifications.
These local mt_* calls ignore the global array and need no registration.
Trees must have valid GEM parent/sibling links; invalid pointers fault in
userspace. Render-dependent 3D enlargement is not included yet, so 3D hit
areas will be completed with the object rendering migration.

With CONF_WITH_LIBAES enabled, the algorithms in aes/gemobjtree.c are
also used by kernel AES. With the feature disabled, the original kernel
implementations and object list are retained unchanged.
Parent/sibling links retain GEM conventions: a parent's head and tail name
its first/last child, the last child's next points to the parent, the root's
next is NIL, and an empty child list has head/tail NIL. Deleting an object
unlinks its subtree without destroying its contents; adding attaches it at
the end of the destination parent's children. A detached object's next field
is not reset by deletion; objc_add assigns its new parent link.

objc_order uses zero-based sibling positions; NIL (-1) means the end.
Invalid positions return zero before modifying links. Reordering an only
child preserves both the parent's head/tail and the child's parent link.
Root deletion/reordering fails. objc_offset accumulates the object's and
its ancestors' relative coordinates into the caller's WORD outputs. These
functions return one on success, zero on rejected operations, following the
GEM C API rather than the CUIS syscall error convention.

As with ordinary GEM C functions, the caller supplies a valid array and tree
links. Local routines do not copy or register it in the kernel. An invalid
pointer faults in user mode, and process teardown releases that client's
CUIS session. The kernel diagnostic wrapper for legacy ob_delete remains
outside the pure shared core.

The host and real ring-3 tests share tests/cuis/objects.c. They cover nested
coordinates, subtree relocation, head/middle/tail deletion and ordering,
invalid positions without mutation, single-child ordering and preservation
of object specifications. The dynamic client also calls objc_offset with
an unmapped pointer: only that child faults, and its parent continues.

When CONF_WITH_DYNAMIC_DESK and CONF_WITH_LIBAES are enabled together,
EmuDesk links its public objc_add/objc_order/objc_offset calls through
DT_NEEDED libaes.so, rather than defining GEM trap wrappers for them.
Internal desktop geometry helpers use the same extracted core. Other
AES operations continue through the existing adapters during migration.
Static desktops and builds without libaes retain their existing bindings.

Native window metadata (external libaes only)
-------------------------------------------
CUIS class 0x103 now reserves these flat-register calls:

  3 CREATE     RDI=x, RSI=y, RDX=width, R10=height
  4 CONFIGURE  RDI=window, RSI=x, RDX=y, R10=width, R8=height
  5 DESTROY    RDI=window

CREATE returns a non-negative window handle or a negative GEMDOS error.
CONFIGURE and DESTROY return zero or a negative GEMDOS error. Unused slots
are ignored. The current process must have an open CUIS session; a session
handle is not repeated in these calls. Window and session handles occupy
separate namespaces. libaes exports aes_window_create/configure/destroy;
these native calls do not yet implement the GEM wind_* API.

Window handles are never recycled during a boot. Only the owning process
may configure or destroy a window. A missing session, unknown/stale handle
or foreign window returns EACCDN; malformed active register slots return
EINVAL. A maximum of 64 windows per session bounds kernel allocations;
quota, allocation and handle exhaustion return ENSMEM without consuming a
handle. Closing a session or exiting/faulting frees all its windows.

Geometry arguments are sign-extended 32-bit integers. Origins may be negative;
extents must be positive and the exclusive right/bottom edges must fit in a
signed 32-bit integer. Invalid configuration leaves the old geometry intact.
These windows are metadata only: creation does not show a window, draw or
change focus. Visibility, Z-order and redraw polling are described below;
clipping, rendering coordination and event delivery remain subsequent work. No legacy AES window state is changed by these calls.
All new kernel paths compile only with CONF_WITH_CUIS, selected by the
external CONF_WITH_LIBAES feature.

Visibility, stacking and redraw polling
--------------------------------------
Additional calls in CUIS class 0x103 each take the window handle in RDI:

  6 SHOW     insert a hidden window at the front
  7 HIDE     remove a visible window
  8 RAISE    move a visible window to the front
  9 LOWER    move a visible window to the back
 10 REDRAW   consume a pending redraw indication (1 pending, 0 none)

All return a negative GEMDOS error on failure. SHOW/HIDE/RAISE/LOWER return
zero on success. libaes exports aes_window_show/hide/raise/lower/redraw.
Unused registers are ignored; ownership and full-width handle validation
are identical to the earlier window calls. SHOW on an already-visible
window and HIDE on a hidden one are no-ops. RAISE/LOWER on a hidden window
return EINVAL. Raising the front window or lowering the back window is a
no-op. CONFIGURE with identical validated geometry is also a no-op and
preserves pending redraws. New windows start hidden with no pending redraw.

CUIS maintains one front-to-back list across registered processes, separate
from the legacy AES window manager. Showing, hiding, moving, resizing,
reordering or destroying a visible window conservatively marks every
remaining visible CUIS window for a full redraw. Showing also marks the
newly visible window. Hidden windows retain no redraw indication; their
next SHOW schedules one. Repeated changes coalesce. Invalid operations
leave both order and pending redraws intact. Closing a session or exiting
removes all its visible windows and marks surviving windows for redraw.

REDRAW is owner-local, nonblocking polling, not an event wait. It clears
only that window's pending indication; subsequent changes set it again.
The syscall runs synchronously in the existing serialized kernel service
path, without allocating queue entries. It does not authorize framebuffer
writes. The snapshot/update calls below provide metadata coordination. Physical
display clipping, VDI enforcement and atomic event waits remain necessary
for complete concurrent rendering support. No pixels, legacy AES windows or input focus are changed
by this slice. A full GEM wind_* adapter also remains subsequent work.

Visible-region snapshots and update sections
-------------------------------------------
The next CUIS calls retain the flat scalar ABI:

 11 UPDATE_BEGIN  RDI=window
 12 UPDATE_END    RDI=window
 13 WINDOW_CLIP   RDI=window, RSI=index,
                  RDX=LONG *x, R10=LONG *y, R8=LONG *width, R9=LONG *height

libaes exports aes_update_begin(window), aes_update_end(window), and
aes_window_clip(window, index, x, y, width, height). BEGIN/END return zero
or a negative error. CLIP returns 1 for a rectangle, 0 at/past the end,
or a negative error. There is no cursor, request block or negotiation.

BEGIN requires an owned visible window and captures its rectangle minus
all visible windows above it. Output rectangles are disjoint, have positive
extents, and remain in the same native coordinate space. Touching edges do
not occlude. A fully covered window has an empty snapshot. The snapshot
uses at most 256 rectangles, with two bounded work buffers during capture;
allocation or intermediate fragmentation overflow returns ENSMEM without
acquiring the update section or altering window state/redraw flags.

There is one nonblocking update section across CUIS sessions. A successful
BEGIN freezes geometry/stacking operations until END. While held, all
window mutations (including creation and otherwise-idempotent operations)
return EAGAIN after the normal ownership checks. Another BEGIN, including
a nested BEGIN, also returns EAGAIN. REDRAW polling remains permitted. A
matching owner/window END releases the snapshot and update section;
wrong-owner/window END returns EACCDN. This is not a recursive lock or an
atomic event wait. Callers must finish promptly and retry busy operations.

CLIP requires the matching active owner and window. The index is an unsigned
32-bit scalar; full-width malformed handles/indices return EINVAL. Outputs
are native 32-bit LONGs, copied through the existing per-process memory
validation/copy facilities. Every output destination is validated before
any value is copied; invalid, supervisor, read-only or high-bit addresses
return EIMBA. Outputs are written in x,y,width,height order if they alias.
At/past the end, no output pointers are inspected or written. Copy failures
never advance a cursor: retry the same index. Output order is deterministic
for a held snapshot but callers should not depend on a particular tiling.

Session close and process exit/fault release an owned update section before
freeing windows. Other processes may still terminate: their windows are
removed and surviving windows marked for redraw. The held snapshot stays
immutable; removing an occluder can only make it a conservative subset of
the newly exposed area. Pending redraws survive END so that exposure is not
lost. Subsequent BEGIN captures the expanded region.

The snapshot/update calls provide the metadata used by the display/VDI
integration below. They do not lock the legacy AES window manager or grant
direct framebuffer access. Input/focus and atomic event waits remain later
epic work. The kernel source and dispatch paths are enabled only by
CONF_WITH_CUIS, selected by the external CONF_WITH_LIBAES feature.

Physical display and native VDI integration
-------------------------------------------
UPDATE_BEGIN now intersects the window with the current physical display
before subtracting higher windows. Native clip outputs therefore contain
only physical display coordinates, even for negative origins and windows
extending past an edge. A fully off-screen window has an empty snapshot.
An unavailable/zero-sized display returns EINVFN without acquiring an
update section. The VDI renderer additionally applies its signed-coordinate
limits and the optional workstation clip to every screen write.

Opening a CUIS session opts that process into region enforcement by the
existing checked x32 VDI service (when CONF_WITH_X32_VDI is enabled). Lines,
text, bars and filled rectangles require an active update section owned by
the process; without one they return EACCDN. Drawing intersects the snapshot
with the physical screen and workstation clip and renders once per disjoint
region. Empty intersections draw nothing. Workstation clipping state and
the associated Line-A globals are restored afterward. Attribute setters
remain usable without an update. Another process's update section causes
native screen writes to return EAGAIN, including writes by non-CUIS clients.

Whole-screen reads remain allowed for every app, including screenshot apps:
VDI pixel reads do not require a CUIS session/update and are not restricted
to a window or its unoccluded area. Normal physical-coordinate and output
memory validation still apply. A screenshot may read while another client
holds an update section. Screen-copy source pixels are likewise unrestricted.
Screen-to-screen copies by CUIS clients require an owned update and clip
only the destination. Rows and disjoint row segments are processed in
memmove order so overlapping copies do not overwrite later source pixels.
Workstation clipping still restricts destination writes and is restored.

Non-CUIS native VDI clients retain their previous drawing behavior when no
update section is active. These changes do not retrofit the legacy AES
service or its direct kernel drawing, and are not a sandbox for all legacy
interfaces. The external desktop still uses its legacy session path while
GEM window/form/menu migration continues. Screen-to-memory raster binding
coverage follows the existing VDI implementation; whole-screen read access
is permitted independently of that binding's supported operations.

All new VDI policy, clipping and copy paths are under CONF_WITH_CUIS. With
external libaes disabled, the original native VDI paths remain in use.

Native workstation lifetime under external libaes
------------------------------------------------
Native OPEN/CLOSE operate on process-owned virtual workstations. If native
VDI needs to initialize the physical workstation, it preserves the console
and framebuffer instead of implicitly entering graphics mode and clearing
the screen. Once initialized, that physical workstation stays available
when the last client closes, fails to open a virtual handle, exits or faults.
Client cleanup still frees every owned virtual workstation and callback.

The kernel display/legacy AES path retains responsibility for explicit
physical-workstation and console transitions. Before reopening an active
physical workstation, a production handoff closes the old workstation
without an intermediate console clear. This removes timer/mouse hooks and
invalidates old virtual handles before installing new hooks, preventing
the timer from chaining to itself. Native clients must reopen virtual
handles after a kernel physical-display reinitialization.

A native screenshot client can
open a virtual workstation and read the whole screen during another client's
update without clearing the display or switching console mode. Kernel-only
memtest fixtures can explicitly reset an idle service-owned physical
workstation when changing synthetic display dimensions; those resets also
preserve the console. With external libaes disabled, physical workstation
lifetime and console transitions retain their original behavior.

Focus ownership foundation
--------------------------
CUIS adds three flat calls, each taking an owned window handle in RDI:

 14 FOCUS_REQUEST  return zero on success or a negative GEMDOS error
 15 FOCUS_QUERY    return 1 if focused, 0 if not, or a negative error
 16 FOCUS_RELEASE  return zero on success or a negative error

libaes exports aes_window_focus, aes_window_focused and aes_window_unfocus.
Unused register slots are ignored. Malformed full-width handles return
EINVAL; absent sessions and unknown/stale/foreign handles return EACCDN.
A hidden window cannot request focus (EINVAL). Only the currently frontmost
visible CUIS window may claim focus; a request for another visible window returns
EACCDN. No foreign focus handle is exposed by QUERY.

Showing, raising and lowering windows do not automatically transfer focus.
Focus and stacking remain distinct: an already-focused visible window can
remain focused after being lowered. Repeating a focus request for the focused
front window is a no-op. Releasing a non-focused owned window is also a no-op;
releasing the focused window clears focus without selecting a fallback. Actual focus changes mark all visible CUIS
windows for redraw so future decorations can reflect the change.

Hiding/destroying a focused window transfers focus to the remaining front
visible window, or clears it if none remains. The same rule applies while
closing sessions and reclaiming normal, raw-exit or faulted processes. A
focus pointer is always removed before its window is freed. Removing an
unfocused window does not change focus.

Focus request/release are mutations and return EAGAIN while an update section
is held, including otherwise-idempotent requests. QUERY remains available.
New windows start without focus, and a boot with no focus stays that way
until a successful request. This slice establishes the authoritative target
for subsequent bounded input queues and atomic waits; it does not yet route
hardware input, change legacy AES focus or add event delivery. All kernel
focus state and paths remain under the external libaes CUIS configuration.

Focused keyboard queues and atomic waits
---------------------------------------
CUIS adds flat keyboard calls using only RDI and RSI:

 17 KEY_READ  RDI=owned window, RSI=ULONG *key
 18 KEY_WAIT  RDI=owned window, RSI=sign-extended LONG timeout_ms

libaes exports aes_key_read(window, key) and aes_key_wait(window, timeout_ms).
READ returns 1 after copying one key, 0 if empty, or a negative GEMDOS error.
WAIT returns 1 when a key is pending without consuming it, 0 on timeout, or
a negative error. Zero milliseconds polls; -1 waits indefinitely. Other
negative or noncanonical timeout values return EINVAL. Unused registers
are ignored. Unknown/stale/foreign handles and unfocused windows return
EACCDN; malformed full-width handles return EINVAL.

Each window has a fixed 16-key FIFO. The existing BIOS keyboard translation
feeds the focused window through an IRQ-safe, allocation-free producer.
Values retain the BIOS representation: translated character in the low
word, scan code in bits 16-23, modifier state in the high byte. Interpretation
belongs in libaes. There is no CUIS syscall for posting synthetic keyboard
input. Consumed keys do not also enter the legacy BIOS input queue. A full
focused queue drops the newest key and still consumes it, preventing overflow
from exposing another application's input to legacy consumers. With no CUIS
focus, normal BIOS input behavior is retained.

Focus transfer clears both the old and newly focused window's queues;
release, hide, destruction and exit cannot leave stale input for a later
focus owner. Repeating a request for the already-focused front window keeps
its queued input. Publication/removal of the focus pointer and queue updates
use the selected interrupt backend, so keyboard IRQs cannot retain a pointer
to a freed window. IRQ code neither traverses client lists nor allocates.

READ validates and backs writable output memory before its short queue
transaction, then rechecks focus. Copyout failure leaves the oldest key
queued for retry. Empty reads do not inspect the output pointer. WAIT checks
focus, queue and deadline with interrupts masked, then uses the x32 atomic
STI/HLT/CLI sequence to sleep and recheck. Pending input cannot land between
an empty check and sleep without waking the caller. Entry interrupt state
is restored on return. Positive timeouts use the 200 Hz monotonic tick with
a guard for the current partial tick, avoiding early expiry; deadlines use
unsigned differences so counter wraparound is supported. A queued key takes
priority over timeout at a wake boundary.

An empty blocking wait while the caller owns a display update returns
EACCDN; zero-time polls and already-pending input remain available. This
prevents sleeping indefinitely with the drawing update held. Focus loss
observed after wake returns EACCDN. Managed kernel tasks block only the caller and
let another runnable client execute. Outside a managed group, waits retain
the native IRQ sleep path. No legacy AES scheduler or userspace daemon is
added; asynchronous public process-launch integration remains later work.

All kernel input state, BIOS hooks and the selected interrupt/wait backend
compile only with CONF_WITH_CUIS, selected by external CONF_WITH_LIBAES.
Kernel memtests inject one translated key from a real timer IRQ after the
wait reaches its sleep path and verify it does not enter the BIOS queue;
no user-callable test injection interface is exposed.

Pointer routing and combined waits
----------------------------------
CUIS extends the flat register ABI with:

 19 POINTER_READ RDI=owned window, RSI=LONG *x, RDX=LONG *y,
                 R10=ULONG *buttons, R8=ULONG *state
 20 EVENT_WAIT   RDI=owned window, RSI=event mask,
                 RDX=sign-extended LONG timeout_ms

libaes exports aes_pointer_read(window, x, y, buttons, state) and
aes_event_wait(window, events, timeout_ms). POINTER_READ returns 1 for one
snapshot, 0 when empty, or a negative GEMDOS error. Coordinates are absolute
screen pixels. Buttons use bit 0 for left and bit 1 for right; state bits 0-1
identify changed buttons and CUIS_POINTER_INSIDE (bit 2) identifies the
window currently hit by the pointer. Capture can deliver outside snapshots.
All four outputs are validated before copying; failed copyout retains the
snapshot. Empty reads do not inspect output pointers.

A trusted relative mouse packet is clamped to the physical display and live
VDI viewport. Hit testing uses the topmost shown window and half-open bounds.
Pressing a CUIS window focuses it without raising it and implicitly captures
all pointer input until every button is released. A legacy drag begun outside
CUIS remains legacy through release. Hiding, destroying or exiting a capture
owner suppresses the remaining gesture until release, preventing orphan
button releases from reaching another recipient. Enter/leave snapshots also
track window visibility, geometry and Z-order changes. CUIS-owned input keeps
the visible VDI cursor moving without publishing legacy motion/button or
native VDI input callbacks. Input outside CUIS retains existing behavior.

Each window has a resident 16-snapshot FIFO. Consecutive pure motion snapshots
with matching buttons and inside state coalesce. Button edges and inside
transitions remain ordered. Overflow discards the old FIFO, reports ERANGE
once, and retains a current-state snapshot with no asserted button changes;
callers must resynchronize their gesture state after ERANGE. The per-session
64-window limit remains; a global 256-window limit bounds allocation-free IRQ
hit testing and focus redraw work. Creation beyond either limit returns
ENSMEM. No userspace synthetic-input entry point is added.

EVENT_WAIT accepts any nonempty combination of CUIS_EVENT_KEY (1),
CUIS_EVENT_POINTER (2), and CUIS_EVENT_REDRAW (4). It returns 1 if any requested
source is pending, 0 on timeout, or a negative error; it consumes nothing and
returns no event mask. Callers poll their requested sources after waking.
Pointer overflow counts as pending; redraw remains pending until REDRAW is
read. KEY-only waits require focus; mixed waits can observe pointer/redraw in
a background window, while keyboard readiness still requires focus. Windows
must be shown. Unknown mask bits and malformed timeouts return EINVAL.
Timeout and owned-update restrictions match KEY_WAIT. Predicate checks and
sleep use the same IRQ exclusion, avoiding lost wakeups between sources.

Host tests exercise ownership, capture, enter/leave, coalescing, overflow,
copyout failures, cancellation, legacy drags and global bounds. Kernel tests
inject press/release packets from a real timer IRQ after an empty mixed wait
has reached sleep, and check cursor movement, legacy callback isolation and
owner teardown in both display-backed and headless configurations. Guarded
show/hide/redefinition keeps logical coordinates synchronized and flushes
deferred cursor movement when the outer guard ends. CUIS packets invalidate
queued legacy motion/cursor notifications and advance a generation checked
before applying an in-flight native motion callback's result. IRQ fixtures
cover guarded motion and reject an older callback completion after CUIS input.

Bounded peer messages
---------------------
CUIS transports opaque peer data separately from trusted input and redraws:

 21 MESSAGE_SEND  RDI=destination session, RSI/RDX/R10/R8=ULONG words 0-3
 22 MESSAGE_READ  RDI=owned session, RSI=LONG *sender,
                  RDX/R10/R8/R9=ULONG *words 0-3 (four separate outputs)
 23 MESSAGE_WAIT  RDI=owned session, RSI=sign-extended LONG timeout_ms

Transitional libaes test wrappers are aes_message_send(destination, a, b,
c, d), aes_message_read(session, sender, a, b, c, d), and
aes_message_wait(session, timeout_ms). These are transport helpers, not the
GEM application API; normal applications use appl_write/read and
evnt_mesag/multi after their library adapters migrate. No request/reply
structure or receiver grant handshake is used. Any registered client can
send to another registered client, as normal GEM messaging requires.

Payload words are unsigned 32-bit values; send slots with upper bits set
return EINVAL. CUIS does not decode GEM message IDs or payloads. A peer
message cannot fabricate trusted CUIS keyboard, pointer, focus or redraw
notifications. Sender identity is assigned by the kernel, never supplied by
the sender. Session handles are never reused. Peer discovery, mapping to GEM
application IDs and GEM message adaptation remain later library work.

SEND returns E_OK on acceptance, EAGAIN when the destination's 16-message
FIFO is full, EACCDN for an absent destination or unregistered caller, or
EINVAL for malformed slots. It never blocks, allocates or evicts an accepted
message. Messages from all peers share FIFO acceptance order. These scalar
results are private transport conventions, not appl_write return values.

READ returns 1 after copying the kernel sender and all four payload words,
0 when empty, or a negative error. All outputs are validated/backed before
copyout, and a failed copy leaves the oldest message queued. Empty reads
ignore output pointers. Reading another session is forbidden. Sender exit
preserves accepted messages with the historical sender handle. Receiver exit
discards its queue; no message holds a process/window pointer or file reference.

CUIS_EVENT_MESSAGE (8) extends EVENT_WAIT: any queued message for the window
owner makes it ready, independently of focus. A successful wait returns 1 and
consumes nothing. MESSAGE_WAIT uses the same atomic predicate/sleep, timeout
and owned-update rules without requiring a window or focus. Existing event
masks retain their behavior. Managed tasks yield to the kernel scheduler; unmanaged callers retain the
IRQ sleep path. Public asynchronous launch integration remains later work.
Host tests model a peer posting at the sleep boundary; native boot tests
verify scalar transport, cross-process delivery without a handshake,
copyout recovery, queue bounds, ownership, readiness and timeouts.

Kernel-managed native task scheduling
-------------------------------------
CONF_WITH_CUIS selects the hidden CONF_WITH_NATIVE_SCHED option. Generic
process scheduling and MiNT process calls use that option, while GUI
services retain CONF_WITH_CUIS guards. Initially Kconfig limits the native
scheduler backend to x32 with separate address spaces. It reuses the
existing process-context save/restore implementation, without AESPD/EVB/UDA
state or the legacy AES dispatcher. No userspace daemon or application-facing
CUIS scheduling syscall is introduced. Standard asynchronous calls within
managed groups and ordinary launch integration are described below. Full
GEM appl_*/evnt_* adapters remain separate work.

The kernel-only ksched_run() accepts up to eight distinct, already prepared,
unlaunched processes and runs the group until all tasks finish. Allocation
failure before launch leaves all programs with the caller. A successful run
consumes them and returns each exit status. Every task gets a private kernel
bootstrap stack, separate from its process's syscall stack; both outlive
suspended continuations and are reclaimed only from another live stack.
The synchronous group launcher stays alive until every task exits, so its
children never retain a freed parent. Dynamic children use the standard
process calls described below; the kernel group controller stays alive until
every descendant finishes.

CUIS keyboard, combined event and session-message waits publish a bounded
kernel-state predicate while IRQs are masked and suspend the current task.
The scheduler scans at most eight predicates in round-robin order and runs
another ready task. Message/input/redraw readiness, focus or visibility loss,
and timeout expiry all resume the waiter, which rechecks its original
conditions. If every task is blocked, the root context uses STI/HLT/CLI after
the predicate scan, avoiding a lost IRQ between checking and sleeping.
Unmanaged waits keep the existing atomic IRQ sleep path. Pending events,
zero-time polls and owned-update restrictions keep their previous behavior.

Context transfer preserves the active process, page tables, syscall and IRQ
stacks, saved user RSP, GS syscall state, launch nesting, disk-error recovery
buffer, FPU/SSE state, IRQ state and managed-task identity. Legacy AES saves
and restores that identity with its coroutine contexts; new accessory
coroutines are unmanaged even while a foreground group is active. Their
Syield is a no-op and async launch is rejected, including from their nested
synchronous children. Returning to a managed foreground restores its task.
Identities are never reused across task slots or groups, so an obsolete
context cannot attach to a later task. Desktop boot tests exercise both the
unmanaged accessory path and managed launch/wait after AES returns.
A nested synchronous Pexec stays in the
same task and may itself block in CUIS; child exit/fault returns through its
normal launch continuation. Scheduling is cooperative at blocking CUIS
waits, child waits and explicit Syield calls. Busy clients are not preempted
and still require cooperative scheduling points.

Boot fixtures run two isolated standard-ELF/libaes clients through 64 message
exchanges, with private data/library state and SSE checks. They also exercise
focus-loss wakeup, all-blocked timeouts, a nested child's timed wait, normal
exit, _Exit, faults, group bounds/duplicate rejection, allocation failure
before launch and exact allocator/resource reclamation. Test-only kernel
bootstrap messages supply known peer handles until application discovery
migrates; no new application API is required.

Standard asynchronous process calls in managed groups
---------------------------------------------------
With CONF_WITH_NATIVE_SCHED, managed x32 clients use ordinary MiNT GEMDOS calls:

 Pexec(100, path, tail, env)  load and asynchronously launch; return child PID
 Pexec(106, name, bp, env)    asynchronously launch/free a caller-owned loaded
                            basepage; return child PID (name/env unused)
 Syield()            0x0ff  cooperatively run another ready task, return E_OK
 Pwait()             0x109  Pwaitpid(-1, 2, NULL)
 Pwait3(flags, usage) 0x11c  Pwaitpid(-1, flags, usage)
 Pwaitpid(pid, flags, usage) 0x13a

These are standard process interfaces, not new libaes APIs. Pexec modes
0/3/4/6 retain their synchronous/load behavior. Pexec(100/106) require a
managed caller; elsewhere they return EINVFN. Ordinary native Pexec(0/4/6)
starts a single-root group when none is active, so launched shells and
applications can use async calls without custom setup. ROM/kernel-code and
explicit accessory entry paths keep their existing launch behavior; nested
synchronous Pexec stays in the active task. Mode 104 is EINVFN: its
FreeMiNT shared-address-space/thread semantics must not be presented as an
isolated process launch. No fork, signals API, stopped jobs or preemption is
added. Syield outside a managed task is a successful no-op. Preemption,
Pfork and other architecture backends are follow-up #713.

Ordinary group startup allocates its task array and bootstrap stack before
transferring retained basepage/environment ownership or entering user mode.
Pexec(4) keeps caller ownership and its existing image-return semantics;
Pexec(6) transfers ownership only at task entry. A startup allocation failure
leaves retained blocks freeable, and Pexec(0) cleans up its failed launch.
The controller waits until every descendant exits, even if the root program
has already terminated. The original root's full synchronous exit status
is returned, independently of later orphan exits. Boot tests cover all three
entry modes, retained blocks and failures of both group allocations.

The original group slots stay reserved until group completion. Remaining
slots admit dynamic children, including zombies, up to the eight-slot group
bound. A full group returns EAGAIN; allocation failure returns ENSMEM. Mode
100 unwinds a failed load/launch completely. Mode 106 transfers ownership
only after successful preparation; pre-publication failure leaves its
basepage/environment with the caller. As with existing image-adoption
failures, a preparation failure may invalidate the loaded image, but retained
blocks remain freeable. A successful launch revokes the loader's mappings
of the child's basepage/environment before returning, so it cannot rewrite
those blocks or free them while the child runs.

Pwaitpid currently accepts a positive child PID or -1 for any direct child.
Process-group selectors (0 and values below -1) return EINVFN until process
groups exist. Flag bit 0 is WNOHANG: return 0 when matching children exist but
none has exited. Bit 1 is accepted; there are no stopped children to report.
Unknown flag bits return EINVAL. With no matching unreaped child, return
EFILNF, as documented for MiNT. A blocking wait suspends only this task.

On success, the PID occupies bits 16-31 and native MiNT status occupies bits
0-15: normal Pterm status is narrowed to its low eight bits; CPU/process
faults report the terminating signal number in bits 8-15. This is MiNT's raw
format, not the POSIX byte order used by a libc wrapper. Optional usage is
two 32-bit LONGs (user/kernel milliseconds), using the existing approximate
process-usage accounting, with system time zero. Invalid output returns
EIMBA without consuming the zombie, and successful copy/reaping happens once.
Reaped child usage is charged to the waiting parent. No pointer is inspected
when there is no status to return.

A child PID remains reserved after KPROC destruction until reaping or orphan
cleanup, preventing PID reuse from aliasing an unread status. Logical parent
identity is separate from its kernel launch continuation: Pgetppid reports
the spawning process while it lives, then the long-lived group controller.
Only a read-only ancestor snapshot retains historical parent information;
the child's supervisor exit mapping pins the controller, not the original
parent. Parent exit clears ownership of live children and zombies. Orphans
continue running and are automatically reclaimed on exit. The group returns
only after all runnable/blocked descendants finish; no freed parent basepage
is used as an exit continuation.

Boot fixtures exercise asynchronous return, Pgetppid, explicit yield,
blocking/nonblocking/any-child waits, one-time reaping, normal/raw/fault
status, invalid and read-only usage outputs, loaded-basepage ownership and
mapping revocation (Maccess), group exhaustion with freeable unlaunched
blocks, slot reuse, nested or raw-image launch, normal/raw/fault parent exit, and abandoned
zombies. With native VDI callbacks enabled, a parent invokes its blocked
child's callback, survives the child's UD2 fault, then reaps SIGILL after
the child's deferred termination. Every cycle checks process/task memory,
file/directory references and CUIS sessions.

Public GEM lifecycle and timer bindings (#717)
-----------------------------------------------
The ordinary shared library exports appl_init, appl_exit, appl_yield,
evnt_timer and appl_getinfo, with matching mt_* forms, aes_global[15],
gl_apid and gl_ap_version. include/gem.h declares this implemented subset;
the same application fixture also compiles against GEMlib's normal headers.
This is the first public adapter slice, not a complete GEM AES replacement.
Discovery and application pipes are described below. Message/timer combinations are described below; window/input event adapters
remain subsequent work. Existing aes_session_*/aes_window_*/aes_message_* exports
remain transitional test/migration interfaces, not application requirements.

appl_init implicitly opens the process's CUIS session and returns its kernel
PID as a positive short application ID (1..32767), or -1 on failure. Opaque
CUIS handles remain private and are never truncated to produce application
IDs. Repeated initialization reuses the process registration. The caller's
15-word global array is initialized with AES global-layout ABI 0x0400,
multitasking sentinel -1 and its application ID; other slots are
zero until their facilities migrate. This ABI value does not claim complete
AES 4 functionality. Unsupported appl_getinfo queries return 0 and clear their output words;
implemented discovery/polling queries are described below. Optional
MultiAES/MagiC/XaAES query results follow implementation and behavioral tests.

The mt_* forms use the supplied AES global array and the same process-owned
registration. Successful exit clears that array and the library's exported
globals, closes the session and returns 1. Invalid/stale state or transport
failure returns 0; negative transport errors never escape Boolean GEM APIs.
Ordinary finalization closes implicit sessions, while kernel teardown remains
authoritative for faults and _Exit. No new application setup is required.

CUIS_SESSION_DELAY (function 24) takes the owned session handle and an
unsigned 32-bit millisecond interval in flat registers; E_OK or a negative
error is its scalar result. It waits for time alone, without a window,
focus, or input/message consumption. A positive interval is rounded up to
200-Hz ticks with a guard tick, including tick-counter wrap; all intervals
through 0xffffffff ms are accepted. Zero yields once. Positive delays while
owning a display update return EACCDN, matching other blocking CUIS waits.
The library maps successful delay/yield to 1 and failure to 0. These native
calls add neither feature negotiation nor versioned request structures.

Host tests cover failure mapping, opaque-handle/application-ID separation,
caller globals, delay width/rounding/wrap, ownership, IRQ restoration and
queued messages. Real dynamic parent/child fixtures use the public GEM
calls, verify private globals, preserve a queued message across a timer,
and reclaim implicit sessions through finalization and _Exit.

GEM discovery and application byte pipes (#719)
-------------------------------------------------
libaes exports appl_find, appl_read, appl_write and evnt_mesag, including
mt_* forms with GEMlib-compatible prototypes. appl_init publishes the
executable basename as an eight-byte, space-padded label, folding ASCII
lowercase to uppercase and stopping at the first extension separator. The
kernel records only a bounded, unmodified basename (up to 32 bytes) and
opaque label bytes; GEM normalization remains in userspace. Anonymous
basepage-only programs need not have a name. Duplicate labels resolve to
the oldest still-registered session. Exit removes the label; reopening the
same process uses a fresh private handle and the same PID application ID.

appl_find accepts normal eight-character names (short NUL-terminated names
are padded), NULL/upper-word-zero self lookup, and the MultiTOS 0xffff/PID
and 0xfffe/application-ID pointer selectors. Only registered peers convert;
missing, exited or unregistered applications return -1. Handles are resolved
and checked before conversion to a positive short PID; they are not narrowed.
Standard appl_getinfo AES_PROCESS (4) returns 1 with outputs 0,1,0,0:
cooperative scheduling, PID conversion, no appl_search, no rsrc_rcfix.
AES_INQUIRE (6) returns 1 with outputs 1,0,0,0, advertising APR_NOWAIT only.
Other queries remain unsupported; no protocol negotiation is introduced.

appl_write accepts the complete nonnegative short byte-length range
0..32767 and waits for enough queue space for the whole write. Input bytes
are captured before waiting. appl_read accepts the same lengths and blocks
until exactly that many bytes are available; ap_id must be the caller's ID,
or APR_NOWAIT (-1) to poll without consuming an insufficient prefix. Zero
lengths succeed without inspecting the buffer. evnt_mesag reads exactly
16 bytes; appl_read can then retrieve the excess described by the caller's
message header. Reads may cross write boundaries. All supplied payload
bytes are preserved, including caller-defined header words; the kernel
neither interprets GEM message types nor rewrites opaque byte streams.
Boolean APIs return 1 on success and 0 on error, not native negative errors.

Each receiver has a lazy 65536-byte payload ring and a parallel 16-bit sender
PID ring (192 KiB total), independent of message/write boundaries. Partial
reads immediately free capacity. A transfer's 32767-byte maximum is below
half the byte capacity, avoiding metadata/packet fragmentation deadlocks
between exact reads and atomic writes. One pending write snapshot per
sender is bounded by the same transfer limit and is attached to its session
before user copying can fault. There are no unbounded packet lists. Native
sender metadata comes from the kernel and survives sender exit; it describes
the first byte read and is separate from peer-supplied GEM header contents.
Historical sender PIDs are not authentication of a currently live process.
Peer bytes do not manufacture trusted keyboard/pointer/redraw events.

All queued storage and pending snapshots are released on session/process
exit, including faults and _Exit. Failed input copies do not publish data;
failed read validation/copyout, including wrapped reads, consumes nothing.
Writer wait predicates retain only the non-reused receiver handle and
re-resolve it after every switch. Receiver close/exit wakes blocked writers
with an error; reopening, even under the same PID, cannot receive the old
pending write. Blocking operations which would sleep while owning a display
update fail with EACCDN. Ready/zero/poll operations retain their normal behavior.

Native CUIS calls use flat registers and scalar lengths/handles/errors:

 25 SESSION_NAME(handle, buffer, capacity) -> basename length (NUL appended)
 26 SESSION_LABEL(handle, bytes, length)   -> E_OK; opaque labels up to 32 bytes
 27 LABEL_FIND(bytes, length)             -> peer handle
 28 PEER_PID(handle)                      -> registered peer PID
 29 PEER_BY_PID(pid)                      -> registered peer handle
 30 STREAM_WRITE(peer, buffer, length, block) -> exact byte count
 31 STREAM_READ(own, buffer, length, block, optional_sender_pid) -> exact count

Invalid arguments/ownership and missing peers return ordinary negative
errors. block is 0 (EAGAIN when not ready) or 1 (wait). These services and
process-basename storage compile only with CONF_WITH_CUIS. The previous
four-word opaque queue remains transitional; the public GEM pipe does not
inherit its fixed size. Message/timer combined waits are described below; input/window integration
remains subsequent work.

Host tests cover lookup/ownership, capacity and allocation failures,
wrapped reads and copy failures, partial/cross-writer reads, captured input
mutation, historical sender metadata, update ownership and receiver exit.
Real dynamic GEM clients cover named and PID discovery, full-range and
split transfers, blocking backpressure, registration close/reopen, sender
exit and a receiver reopening while a pending write still targets its old
handle. Allocator/session/process snapshots verify complete reclamation.

GEM combined message/timer waits and state reads (#722)
-------------------------------------------------------
evnt_multi and mt_evnt_multi retain the complete standard GEM signatures.
This initially implemented MU_MESAG (0x10), MU_TIMER (0x20) and their
combination. The #741 input adapters below extend this to all six classic
GEM event sources. The following describes the original message/timer subset.
The result is the GEM mask of every ready requested source, including both
bits together; it is never a native negative error. Unsupported keyboard,
button, rectangle and extension masks, and an empty mask, return 0 before
waiting, consuming message bytes or changing caller outputs. Their proper
adapters follow window/input integration; requested events are not silently
dropped. Unrequested button/rectangle parameters and timer arguments are
ignored, as are message pointers when MU_MESAG was not requested.

A message requires at least 16 bytes in the application pipe. A partial
header cannot wake it, and the transitional four-word queue is a different
source. Native readiness consumes nothing; the library copies exactly the
16-byte GEM header only when ready, retaining any excess for appl_read.
Failed message copyout returns 0 and leaves all bytes unread. A timer-only
wait never consumes messages, including when its ignored message pointer is
invalid. Combined waits preserve one deadline across IRQs and scheduler
wakeups and use unsigned millisecond intervals through 0xffffffff, with
ceil-to-tick rounding, a guard tick and modulo tick-counter wrap.

With a zero timer, an already ready message returns both bits immediately.
Otherwise the zero poll yields once to cooperative peers, then checks all
requested sources again; a message produced during that yield is included
alongside MU_TIMER. A positive timer can expire alone, a message can arrive
first, or both can be ready at the same atomic kernel check. Blocking an
empty wait while owning a display update returns EACCDN; ready and zero
operations retain the existing behavior.

graf_mkstate and mt_graf_mkstate return a read-only logical mouse/button/
modifier snapshot for a registered caller. The same state fills successful
evnt_multi outputs, with key return and click count zero because those
input events are not implemented in this slice. Coordinates use signed
GEM shorts (saturated at their range), buttons are left/right bits 0..1,
and modifiers are the standard right-shift/left-shift/control/alt bits 0..3.
NULL scalar output pointers are accepted. No window/focus is required;
state reads neither invoke callbacks nor consume pointer/keyboard events.
Standard-vector snapshots follow synchronized Line-A state; custom-vector
snapshots use CUIS's initialized logical position/buttons, falling back to
Line-A before initialization. This includes packets consumed only by CUIS.
Invalid non-NULL scalar output pointers are ordinary userspace faults;
kernel teardown remains authoritative for cleanup.

CUIS_SESSION_WAIT (32) takes (owned_session, minimum_bytes, ready_mask,
unsigned_milliseconds) in flat registers and returns CUIS_READY_STREAM (1),
CUIS_READY_TIMER (2), their union, or a negative error. Masks must select
at least one source. minimum_bytes is 1..32767 when selecting the stream;
otherwise it is ignored. The interval is validated only when selecting the
timer. This is generic byte readiness/deadline handling, not a kernel GEM
mask or event parameter-block interpreter. CUIS_INPUT_STATE (33) takes the
owned session and four LONG output addresses for x, y, buttons and modifiers,
returning E_OK or a negative error. It backs all outputs before sampling one
logical state under IRQ exclusion. Kernel additions remain CUIS-configured;
there are no versioned blocks, feature negotiation or new public CUIS setup.

Host tests cover all source combinations, simultaneous/early readiness,
partial headers, opaque-queue separation, zero-yield arrival, full intervals,
wrap and unchanged deadlines, IRQ restoration, update ownership, snapshots,
mask/result mapping and copyout failures without consumption. Real dynamic
GEM clients cover ordinary and mt_* calls, header/excess reads, unsupported
masks, read-only message buffers, timed peer producers, zero-yield delivery
and scalar-output user faults with exact resource reclamation. Normal GEMlib
headers compile the same fixture; other AES/event families remain staged.

Final configuration cutover
---------------------------
Once external libaes is complete, Kconfig must make CUIS and in-kernel AES
mutually exclusive. In-kernel AES must also depend on !CONF_WITH_USER_ASPACE
on every architecture. Protected GUI kernels use libaes over CUIS; kernels
without separate address spaces can retain the traditional in-kernel AES.
Remove the superseded kernel AES entry paths and AES-specific user-object,
AESPB/tree validation and snapshot machinery at that cutover. Native CUIS
syscalls continue checking ownership, scalar arguments and user buffers.
Transitional combinations retain their validation until replacement libaes
behavior and boot/desktop coverage allow those entry paths to be disabled.


GEM plain-window lifecycle and geometry (#732)
--------------------------------------------

libaes exports wind_create/open/close/delete/get/set/calc and their standard
mt_* forms. This is the metadata/lifecycle foundation for kind == 0 windows;
nonzero decoration kinds fail explicitly. It does not yet draw even the plain
frame, paint decorations or adapt keyboard/button/rectangle events.
Window messages/focus and stack/owner queries are added by #738 below. Desktop handle 0, foreign-window
geometry queries, titles, sliders and other
fields remain unsupported (return 0 without changing outputs). Update locking and rectangle enumeration are added by #734 below. No additional
appl_getinfo capabilities are advertised by these slices.

Application code uses positive short GEM window identifiers, not CUIS handles.
CUIS_WINDOW_IDENTIFY (function 34) takes the owned native window handle in the
first scalar argument and returns a positive, globally unique live-window
identifier or a negative error. Identifiers range from 1 to the global window
quota (256); zero is reserved. They are stable while the window exists and may
be reused after destruction, as with ordinary GEM handles. Knowing an identifier
never confers ownership of its underlying CUIS window. Unused registers are
ignored; malformed/foreign/stale native handles fail ordinary ownership checks.
All kernel additions remain under CONF_WITH_CUIS.

Each library tracks up to 64 owned windows and maps the small identifier to the
full opaque native handle. Registration is required for window lifecycle and
queries. Repeated appl_init in the same session retains windows; successful
appl_exit or registration of a new session clears the local map. Kernel session
teardown reclaims all windows independently of library finalization, including
raw process exits. A failed close/delete preserves the map for retry.

wind_create returns -1 on failure, otherwise a positive GEM identifier. Its
rectangle is saved as WF_FULLXYWH; current and previous rectangles start zero.
Native hidden metadata uses an invisible positive-size placeholder because
CUIS geometry requires positive extents. wind_open configures then shows the
window and initializes both current and previous rectangles to the supplied
border rectangle. Opening an already open window and closing a closed window
return 0. A failed show leaves the window closed and its GEM rectangles intact;
its hidden native geometry may have been prepared for the attempted open.
wind_close saves the last current rectangle as previous and clears current.
wind_delete also accepts an open window, hiding and destroying it in CUIS.

wind_get supports WF_KIND (zero), WF_CURRXYWH, WF_PREVXYWH, WF_FULLXYWH and
WF_WORKXYWH. wind_set supports WF_CURRXYWH, even while closed; only a successful
configure advances previous/current. Open and configure require positive border
width/height. Full geometry is retained exactly as provided at creation.
All ordinary results are GEM 1/0, never negative CUIS error codes.

wind_calc is local and requires no registration. For kind zero, WC_WORK insets
the border by one pixel on each side, and WC_BORDER reverses that calculation,
matching classic GEM plain-window geometry. WF_WORKXYWH uses the same rule on
the current border rectangle. In particular, after wind_close the zero border
produces (1,1,-2,-2), matching the existing GEM AES close/draw_change/wm_calc
path; it is not clamped to an invented zero work rectangle. A closed window
can subsequently receive WF_CURRXYWH and reports the corresponding work area
without becoming visible. Arithmetic/results retain GEM short coordinate
semantics. Outputs are written only on success and may alias inputs; optional
NULL outputs are ignored. Non-NULL invalid pointers fault in userspace.

Host tests cover full native handle bits, transport errors, retry/state retention,
quota exhaustion, session invalidation and standard source signatures. The
GEMWIN.TOS fixture checks actual flat syscalls, shared-library state, isolated
identifiers and raw-exit cleanup. Its standard window contract also compiles
against unmodified GEMlib headers.


GEM update locking and visible work rectangles (#734)
----------------------------------------------------

wind_update/mt_wind_update support END_UPDATE (0), BEG_UPDATE (1), and the
standard NO_BLOCK (0x100) modifier on BEG_UPDATE. A successful begin returns
1, a busy nonblocking begin or other failure returns 0. Locks nest per
registered process, including across different mt_* global arrays: only the
final matching end releases ownership. Unmatched/foreign ends fail. Mouse
control (BEG_MCTRL/END_MCTRL) and unknown codes return 0 until the input-grab
slice; they are not treated as screen update locks.

The screen semaphore freezes competing native window mutations and screen
writes, rather than tying an application to a single window. Standard window
mutations acquire/release it internally and nest inside an explicit update
section, as GEM permits. Ordinary begins block cooperatively; NO_BLOCK does
not dispatch or sleep. Timer/input/message waits are allowed while owning the
GEM semaphore, as required for modal interaction; applications remain
responsible for avoiding circular waits between peers. The older native
per-window snapshot lock retains its stricter no-blocking-wait rule.
Session close, normal/raw/fault exits release all nesting levels. Preemption
and other architecture backends remain future work under #713.

An owner holds the whole-screen update section and may paint dialog/menu
areas outside its windows. Native VDI writes remain clipped to the captured
screen bounds; other processes cannot write until release. Read/copy access
to the entire screen remains available to all apps, including screenshot
apps. Existing per-window snapshot updates remain separate and mutually
exclusive with this global section; migration/test helpers must not mix the
two lock families. Traditional in-kernel AES migration remains incomplete;
its final exclusion from CUIS kernels is still required at the epic cutover.

wind_get(WF_FIRSTXYWH) restarts a per-window iterator, and WF_NEXTXYWH advances
it independently of iterators for other windows. Each successful result is
intersected with the window's GEM work area and the screen, excluding all
higher windows' visual footprints. Nonempty rectangles do not overlap. A
closed/offscreen/fully covered window, or the end of the list, returns GEM
success 1 with width and height zero; x/y at end are not a sentinel contract.
Native allocation/copy/ownership failures return GEM failure 0 without
advancing the cursor or changing caller outputs. A new FIRST can retry.
NEXT before FIRST or after exhaustion returns an empty rectangle. Hold
BEG_UPDATE through the FIRST/NEXT loop to prevent changes by other apps;
restart FIRST after changing window geometry/visibility/stacking yourself.

Plain GEM windows reserve a two-pixel right/bottom shadow, matching existing
AES w_getsize(WS_TRUE)/newrect behavior. This footprint participates in
occlusion even though frame/shadow painting is still a subsequent rendering
slice. Work/border geometry returned by wind_get/wind_calc and native pointer
hit bounds exclude this visual outset. The kernel interprets only generic
native geometry; libaes sets the GEM shadow policy when creating a window.

Additional flat CUIS calls (all under CONF_WITH_CUIS):

  35 DISPLAY_LOCK(session, acquire, block) -> E_OK / negative error.
     acquire and block are canonical 0/1; release requires block=0. Ownership
     is checked against the current process, depth overflow fails, and exit
     clears ownership before freeing windows. An owned legacy snapshot cannot
     be waited upon by its own process. Unused register arguments are ignored.

  36 WINDOW_REGION(native_window, index, x*, y*, width*, height*) -> 1/0/error.
     Produces indexed visible border/visual-footprint rectangles for owned
     windows. Validated output elements are LONGs, not a request structure.
     It also works without a global lock, but stability across calls requires
     the caller to hold DISPLAY_LOCK. Read-only enumeration remains available
     while another app owns an update section and never grants draw permission.
     While the caller owns DISPLAY_LOCK, index zero refreshes a per-window
     snapshot and later indices retain it even if an occluding peer exits.
     Empty lists retain no array while still being marked valid.
     Cached arrays are bounded by window/clip quotas and reclaimed on final
     unlock, window destruction or owner exit. Without the lock, temporary
     arrays are freed before any faulting output access. Cached arrays are
     attached to windows before output access, so a user fault reclaims them.
     A replacement snapshot commits only after successful output. Validation
     or copy failure discards its candidate and retains the old snapshot for
     the unchanged GEM cursor. Owner/session/window/candidate identities are
     rechecked after output access, which can tear down the process.
     No kernel-side iterator or unowned window metadata is exposed.

  37 WINDOW_OUTSET(native_window, right, bottom) -> E_OK / negative error.
     Sets generic unsigned 16-bit visual outsets, initially zero. Only the
     owner may change them; geometry/extent overflow is rejected before
     mutation. Outsets affect occlusion and VDI region clips, not pointer hit
     bounds or the stored window geometry. Unused scalar slots are ignored.

Host tests exercise nesting, contention, IRQ-safe blocking, exit handoff,
malformed arguments, VDI permission/clip bounds, region allocation/copy errors,
independent/restarted cursors and work clipping. GEMUPD.TOS checks rectangle
coverage against a pixel-grid oracle including shadows, complete coverage,
offscreen clipping, owner mutations during nested updates, blocking of another
process until the final end, and raw/session-exit cleanup. The fixture uses
standard GEM source calls and also builds against unmodified GEMlib headers.


GEM window messages, topping and focus (#738)
--------------------------------------------

Plain libaes windows now receive standard WM_REDRAW (20) and WM_TOPPED (21)
through appl_read/APR_NOWAIT, evnt_mesag and evnt_multi(MU_MESAG), including
mt_* forms. Messages contain eight GEM shorts: AES sender 0, extra length 0,
and the global short window identifier in word 3. Redraw bounds in words 4-7
conservatively cover the current work area (nonnegative extents); applications
still use wind_update and FIRST/NEXT to paint only visible rectangles. Topping
requests leave words 4-7 zero. Repeated notices for the same window/kind can
coalesce. Ordinary application pipe bytes keep their FIFO order and original
contents; converted system messages append to that same byte stream and can
be read in parts just like other GEM messages.

Opening a standard window makes it frontmost and gives it keyboard focus.
WF_TOP raises an owned open window and gives it focus, including an already
frontmost window; WF_BOTTOM lowers it and gives the new top window focus if
necessary. Hide/delete/normal/raw/fault exit of the focused window falls back
to the next visible window. Existing native test/migration windows keep their
previous explicit-focus behavior unless opted into client-managed activation.

Clicking a visible part of a background standard window sends WM_TOPPED; it
neither raises nor focuses the window automatically. Its application decides
whether to honor the request with wind_set(WF_TOP). The activating press and
matching release are consumed as a topping gesture rather than delivered as
ordinary button input. Existing pointer capture/release suppression remains
in force when that window hides or exits. Input is routed to the current focus
until the application actually tops the requested window.

wind_get(WF_TOP) ignores the input handle and returns top ID, owner AES/PID,
next ID below, and zero. WF_BOTTOM returns the bottom visible window ID,
excluding the desktop, with other outputs zero. An empty stack returns ID 0.
WF_OWNER accepts a live global ID (including another app's window) and returns
owner AES/PID, open status, ID above and ID below; closed windows report no
neighbors. Queries are read-only; they do not grant permission to mutate a
foreign window. Invalid/deleted IDs return GEM failure without changing
outputs. Native metadata is range-checked before conversion to GEM shorts;
invalid identifiers/PIDs or non-Boolean open status fail without truncation.
Foreign geometry and desktop handle-0 metadata remain later work.
No additional appl_getinfo extension bits are advertised in this slice.

Window close/move/size/full gadget requests, WM_NEWTOP and optional AES4
WM_ONTOP/WM_UNTOPPED notifications are not synthesized here. Decoration
interactions and their applicable GEM/MultiAES semantics migrate with the
renderer/input adapters. A programmatic geometry change or close does not
fabricate a user request to perform that same operation.

Native additions, all under CONF_WITH_CUIS:

  38 WINDOW_POLICY(native_window, managed_activation) -> E_OK / error.
     Canonical 0/1 enables generic coalesced window notices and application-
     managed activation requests. This is routing policy, not protocol
     version/feature negotiation. libaes enables it on its own plain windows.

  39 NOTICE_PEEK(session, native_window*, identifier*) -> kind / 0 / error.
     Generic kinds are REDRAW=1 and ACTIVATE=2; activation takes precedence
     over redraw for the same window. Outputs are LONGs. Peeking never pops.
     Hidden/destroyed windows retain no pending native notices.

  40 NOTICE_PUBLISH(session, native_window, kind, source, length) -> E_OK/error.
     Atomically appends 1-32 captured opaque bytes to the caller's own pipe
     and acknowledges the specified owned pending notice. No GEM header or
     format is interpreted in the kernel. Sender metadata remains the current
     process PID independently of user-generated payload fields. A full pipe
     returns EAGAIN without consuming the notice; source-copy/allocation or
     ownership failure likewise leaves it pending. Source access can fault,
     so client identity is checked again before publication. Notice flag
     updates and pipe publication use the same short IRQ exclusion.

  41 STACK_QUERY(position, id*, owner_pid*, below_id*) -> E_OK / error.
     Position 0 selects the front, 1 the back. Requires a registered caller;
     all three outputs are validated LONGs, with zero for an empty stack.

  42 WINDOW_INFO(identifier, owner_pid*, visible*, above_id*, below_id*)
     -> E_OK / error. Returns registered global window metadata as LONGs.
     Read-only stack/owner queries remain available during display updates.

SESSION_WAIT adds READY_NOTICE=4 to the existing stream/timer readiness bits.
This source is non-consuming and windowless. libaes pumps notices before a
message read and after a notice wakeup, constructing GEM payloads locally.
The native pipe append/ack keeps failed public copyout recoverable: converted
bytes remain queued until a successful read. A full pipe is already large
enough to satisfy every supported appl_read length, so callers can drain bytes
without dropping the pending notice. Blocking reads wait for either sufficient
stream bytes or notices; nonblocking reads pump once then return normally.
Timer-only waits never pump notices. Combined message/timer waits use one
native deadline and retain simultaneous readiness; an already pending notice
also prevents the unnecessary zero-timer yield.

Host tests cover high native handles, message layout, full-pipe backpressure,

lock ownership and focus fallback. GEMFOC.TOS exercises isolated apps using
standard GEM source: redraw delivery, top/bottom operations, foreign owner
queries and close/raw-exit fallback. Existing GEMWIN/GEMUPD fixtures now accept
real redraw messages while waiting for their application control messages.


GEM keyboard, button and mouse rectangle events (#741)
-----------------------------------------------------
evnt_keybd, evnt_button, evnt_mouse and evnt_dclick now have standard and
mt_* bindings. evnt_multi/mt_evnt_multi support every combination of the six
classic masks: MU_KEYBD, MU_BUTTON, MU_M1, MU_M2, MU_MESAG and MU_TIMER.
An empty mask or an unknown extension mask fails with GEM 0 before any wait
or consumption. Unrequested parameters remain ignored. No new appl_getinfo
extension bits are advertised. Wheel/extended-key event masks and mouse-control
grabs (wind_update BEG_MCTRL/END_MCTRL) remain separate work.

Keyboard waits belong to the application, following whichever of its windows
has focus; they can remain blocked while another application owns focus.
Native BIOS scan/ASCII keys become GEM words with scan code in bits 8-15 and
ASCII in bits 0-7. Keys are consumed only when requested and ready. Pointer
waits follow the focused application or existing pointer capture; background
activation gestures remain WM_TOPPED requests, not button input. No untrusted
application can inject hardware input. Applications without focused windows
can still use message/timer waits and graf_mkstate.

A rectangle is half-open on its right/bottom boundaries. MO_ENTER waits for
inside, MO_LEAVE for outside; the predicate is also tested immediately, so no
new movement is needed if it already holds. Zero/negative extents are empty.
Both rectangles are tested independently and can complete together. Trusted
packet processing latches a matching crossing during an active wait even
when another packet reverses it before userspace runs.

Button equality is ((buttons ^ state) & mask) == 0. Clicks' low byte limits
the returned count; bit 0x100 reverses equality, as in classic GEM. Other
high-byte extensions (including 0x200) are not advertised and fail with 0.
A matching current state or queued transition completes the quick check;
otherwise a pending multiple-click wait starts its click window on the first
matching transition. Additional matches extend the original window by three
200-Hz ticks, with a bounded count. The wait returns the actual count, capped
by the requested maximum, after the interval, including a single click when
a double click was requested. The matching position/button/modifier snapshot
is retained when a release follows. A bounded 16-edge per-session history
retains press/release pairs arriving between calls independently of the raw
native per-window pointer queues; overflow discards oldest edges. Ownership
loss/hide clears old history. Zero requested clicks return count zero.

evnt_dclick queries/sets the global standard rate index 0..4, corresponding
to 450, 330, 275, 220 and 165 ms; the initial rate is zero. A running click
window retains its original interval. Invalid set/rate parameters fail with
0 without changing it. All six event sources use a single native wait;
keyboard/message/timer completion cancels unfinished button accumulation.
Timer deadlines are never restarted by pointer traffic. Input already ready
also avoids the unnecessary zero-timer cooperative yield. Results include
all requested sources ready at completion; unrequested key/count outputs are
zero and optional scalar outputs may be NULL.

Native additions, all built only under CONF_WITH_CUIS:

  43 INPUT_RECT(session, slot_flags, x, y, width, height) -> E_OK / error.
     Flat signed LONG geometry. Slot_flags bit zero selects rectangle 0/1,
     bit one selects outside rather than inside. Other bits are rejected.

  44 INPUT_BUTTON(session, mask, state, maximum_count, invert, unused=0)
     -> E_OK / error. Mask/state are unsigned 16-bit, count 0..255, invert
     canonical 0/1. Configuration belongs to the calling session.

  45 INPUT_RESULT(session, key*, count*, x*, y*, state*) -> E_OK / error.
     Five separate validated LONG outputs from the latest input-enabled wait.
     Key retains native BIOS encoding; state contains button bits 0..15 and
     modifier bits 16..31. No request/reply structures cross the ABI. Re-reading
     is non-consuming, including after failed copyout; a later input wait
     replaces the snapshot. A completed wait transfers a ready key from its
     focused window queue into this session snapshot under IRQ exclusion.

  46 INPUT_INTERVAL(session, milliseconds, set, 0, 0, 0) -> interval / error.
     Generic global click interval, 1..5000 ms, canonical set=0/1. Query ignores
     the milliseconds argument. Public GEM rate indices remain in libaes.

SESSION_WAIT (32) additionally accepts native READY_KEY=8, READY_BUTTON=16,
READY_RECT1=32 and READY_RECT2=64. Stream minimum and timer interval validation
still apply only when selecting those sources. Configuration, initial checks,
IRQ event latching and the scheduler's test-and-sleep use IRQ exclusion; no
allocation or user-memory access occurs in that critical path. Active wait
pointers refer to resident syscall stacks and are cleared on completion/error;
process teardown removes the session before it can outlive that stack.
