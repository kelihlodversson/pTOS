Creation/ownership transition map
---------------------------------
xexec / xexec_observed / xexec_prepared (bdos/proc.c)
  -> alloc_env + alloc_tpa + init_pd_fields + kproc_create
     Ownership is child for0/100, caller for3. Existing std/CWD acquisition is
     init_pd_files; descriptors/runtime are not full fork inheritance.
  -> kpgmhdrld/kpgmld, ELF or PRG staging, kproc_set_image/load_begin/load_commit
     Loader owns layout, relocation, entry/stack/image metadata and error scope.
     It records pending KASPACE or caller-staged UH_LOADED grant, not runnable VM.
  -> synchronous ordinary managed: ksched_exec -> run_group(prepare=TRUE)
  -> async/observed/deferred: ksched_process_prepare -> kproc_prepare_async_thread
  -> both: kproc_prepare_user_thread(pd,parent,&thread)
     Scheduler task storage/continuation stack is already reserved. Loader
     builds/maps image/environment/TPA/controller/ancestors and syscall stack.
  -> proc_clone LOADED_PROCESS/PREPARED_VM (this first increment)
     Explicit loader construction KASPACE; source denotes the existing target
     PROCESS, not its parent's root. Uses existing transaction reference/THREAD
     preparation and rollback, returns owned non-runnable initial THREAD.
  -> move_loaded_image/layout_load and final KPROC active-space adoption
  -> existing scheduler adopts execution resource then publishes task
  -> proc_go sets parent/started and runs existing architecture launcher
  -> existing launcher leaves syscall stack; #893 finalizes PROCESS
  -> #909 public reap; observers retain separate canonical notification rights.

No extra PID, descriptor table, reaper, loader or scheduler is created by the
new policy. LOADED_PROCESS must use PREPARED_VM and a live unstarted target;
SAME_PROCESS/NEW_PROCESS public clone policies cannot select this internal VM
source. The transaction does not consume/adopt the loader's KASPACE, env, TPA,
image or kernel stack. It retains only its temporary references and constructed
THREAD. Its result has no owned_process disposal right. The loader remains
responsible for subsequent failed image preparation/disposal.

The old early already-prepared branch now uses the same helper with the active
KASPACE, instead of a direct kthread_create. Fresh-image preparation calls it
at the original kthread_prepare location before irreversible image transfer.
All added allocation/commit checks are before that transfer. Root/group/async
publication and stopped-stack reclamation are unchanged.

Paths deliberately not yet migrated
----------------------------------
- Managed direct nested proc_go now uses #966's authenticated initial THREAD
  and nested continuation association. Unmanaged ROM/accessory paths retain
  their documented THREAD-less behavior. Already-prepared scheduler groups
  call proc_clone_prepare_loaded_thread.
- KPROC/env/TPA allocation and image-specific KASPACE construction still originate
  in loader policy. This increment consolidates initial managed THREAD creation;
  it does not claim complete Pexec -> proc_clone convergence.
- PE_LOAD's source grant/UH_LOADED and isolated PE6/106 move ownership are not
  replaced with shared VM. Legacy supervisor PE4 give-back is compatibility
  only; do not build a new ring3 ownership subsystem around it.
- #931 prepared rights remain transport/observation. Their cancellation guard,
  pending cleanup, directory policy and irreversible replacement boundaries
  remain in the existing owners; no launch-right API is added here.

Fallible and irreversible boundaries
-----------------------------------
Image loading may allocate and perform I/O under the existing disk-error scope.
The ordinary scheduler reserves its slots/execution stack before image adoption.
The new clone transaction may fail allocating metadata/THREAD or retaining live
identity/space; it releases only its own prefix and returns failure to the same
loader cleanup path. It does not run the child or commit KPROC's active root.

A staged image move is already irreversible in the current loader. This change
adds no fallible operation after it. The existing standard-entry stack-bound
invariant check still follows loading; its old ordering needs separate review
before claiming a general no-fail executable-replacement transaction. Do not
reuse the isolated move-private mechanism on COW/shared pages for exec200.

Implemented default-off shared-VM consumer (4/104)
------------------------------------------------
The following policy is implemented behind CONF_WITH_SHARED_VM_PEXEC_TEST;
whole-consumer acceptance is pending. It does not authorize production use.
Use distinct PROCESS identities with the same retained KASPACE, not SAME_PROCESS.
A loaded-image policy must authenticate the caller's PE_LOAD grant, retain
image/stack/environment/basepage allocations and logical mappings through
existing #892/#893 owners, allocate fresh execution/syscall stacks and register
canonical completion before publication. The entry is the staged image entry,
not a fork-return frame. Sync/async waiting is selected by xexec, never a new
clone flag. Source-parent lifetime must not be borrowed through a stale PD.

Required before activation: source Mfree/unmap cannot invalidate child code or
stack, child finalization cannot release source mappings, ancestor death/orphan
execution, nested sync/async launch, both exit orders, late/early once-only wait,
all construction rollback and mode0/3/6/100/106 compatibility. Runtime ownership
of heap/image ledgers and controller mappings needs a reviewed shared-space
policy, not attachment of two KPROC records to one page-table pointer. Keep4/104
EINVFN until native x32/A32/m68k040 and owner gates pass. Non-MMU compatibility
continues its old path, without claiming new shared-VM parity.

Accepted direct nested MMU continuation contract (#966 / #713)
-------------------------------------------------------------
The integrated scheduler supplies ksched_nested_prepare/cancel/enter/leave.
Ordinary managed direct launch paths already call them. Preparation constructs
an authentic initial KTHREAD through the existing loader/factory. The carrier
retains its own PROCESS/THREAD anchor; the active nested frame owns the logical
PROCESS/THREAD, cleanup tickets and stack lifetime. Leave restores the enclosing
owner after stop and before final resource/observer publication.

Phase5 adds no redundant preparation, entry or leave calls. Its remaining
shared-Pexec admission/publication checks authenticate ksched_exit_thread(run)'s
logical PROCESS instead of comparing it with the suspended carrier anchor.
Supported nested execution is a sole-THREAD synchronous continuation; public
nested Pclone/Pthjoin/Ptermgrp restrictions, single CPU and cooperative admission
remain unchanged. This is independent of production dispatch/preemption/SMP.

Blocking ordinary-region consumer contract (#891 / #892 / #894)
-------------------------------------------------------------
MMAP_REGION and ordinary heap records currently belong to KASPACE. Generic
NEW_PROCESS/CLONE_VM retains that root and its own execution stack; it does not
acquire R2 lifetime attachments for every inherited region. Shared-Pexec does
capture current ordinary regions, but runtime DSOs created after its publication
have no PROCESS retirement owner. PROCESS teardown merely drops a root reference.
Repeated interpreted shared launches retain obsolete runtime reservations until
the surviving root dies and eventually exhaust the bounded consumer region set.

Final reclamation before surviving-root destruction requires an owner-reviewed
common attachment/retirement policy across all shared-root creators, including
allocations born after peers already exist. Preserve exact births, rights,
FILE_BACKING and split metadata, THREAD-vs-PROCESS completion and R1-R4 rollback.
Creator-only unmap can destroy a still-runnable generic peer's code/data.
Unmapping inside interpreter fini is also unsafe: it returns into DSO code and
post-fini checks still read DSO data; faults/raw termination bypass fini.
Do not increase bounds, omit maps from accounting, add another registry or
substitute another root. Accepted R1-R4 and #966 are not the missing contract.

Committed executable replacement design (200)
--------------------------------------------
A separate reusable replacement transaction must stage the complete new image,
independent KASPACE and initial user/kernel execution state while retaining the
old PROCESS/VM. The PROCESS identity/PID and vfork dependency remain attached to
that same PROCESS. Replacement cannot be represented by creating an unrelated
child whose completion masquerades as exec. All file/directory/environment and
startup preparation occurs before an irreversible commit.

Commit validates the exact execution owner and target generation, switches the
PROCESS image/root and new THREAD continuation at an owner-reviewed boundary,
and forbids returning through the old user image. Old syscall/scheduler stacks
and shared-space refs remain retained until the old execution has stopped and
existing root reclamation can release them. KPROC currently forbids attaching a
THREAD with another space while active_space differs; replacement needs an
explicit reviewed staging/commit contract with #892/#713, not bypassing that
check or copying a kernel continuation. No source/COW frame becomes privately
writable merely through move_private. No public200 implementation is claimed.

The child-specific vfork dependency is released only after successful replacement
commit, or final PROCESS completion from #893. Exec entry, failed preparation,
THREAD-only exit, unrelated launch and #909 wait consumption release nothing.
Replacement should expose a committed-detach notification at the policy layer;
it must not create another observer registry or executable loader.

Inheritance dependency
----------------------
Common creation/runtime inheritance consumes the checked #933 owner service for
PROCESS-local descriptors. No live acquire/expected-incarnation release API is
agreed yet. No direct f_use/incarnation/ticket mutation is introduced here.
CWD/environment/runtime and per-PROCESS local bindings must migrate coherently
for ordinary Pexec as well as fork. The irreversible retirement-admission latch
is not a reversible source snapshot guard. See the separate inheritance audit.
