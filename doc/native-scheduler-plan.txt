Native scheduler migration and interruption contract (#713)
===========================================================

Current architecture (source audit)
-----------------------------------
bdos/native_sched.c owns one policy for x32, ARM MMU and m68k MMU. Its CPU
backend header and native_sched_enter assembly only provide continuation entry,
context/root save/restore, local IRQ state and idle. Neither CUIS nor libaes is
required. NEW_PROCESS, SAME_PROCESS and ordinary async Pexec use the same private
reservation -> prepared ownership -> TASK_NEW publication and dispatcher.

A group is an activation lifetime, not a PROCESS group or a separate ready
queue. run_group()/ksched_exec()/ksched_clone_dispatch() attach a synchronous
waiter to the same kernel-owned persistent root. The compatibility controller
PD/launcher chain is still borrowed for that gated activation, not its stack.
Only one activation exists. All independently identified PROCESSes/THREADs in
it share one circular round-robin. Nested synchronous Pexec stays on its carrier
continuation: run may be a distinct child while the task's execution owner stays
unchanged. Its user return/launcher handoff must finish before carrier group
cancellation. No cancellation may reap that child by confusing these identities.

The synchronous waiter cannot return while any runnable/blocked/draining/
deferred continuation remains. The kernel root parks after drain and survives
that return; it does not return into a launcher's dispatcher frame. Ordinary async modes are admitted only inside this activation, so their
PID-returning call is asynchronous to its caller but they are not yet global
background tasks surviving release of the outer waiter. This restriction is a real
lifetime requirement, not a feature gate to remove. Original synchronous Pexec
status/return behavior remains intact. A never-returning child or unsupported
raw wait can deliberately defer group drain.

Storage increment
------------------
KSCHED_LIMIT now denotes the initial eight-record arena and maximum explicit
synchronous bootstrap batch, not maximum runnable concurrency. Active reservation
first reuses an unused asynchronous record, then allocates a stable linked record
on demand. No array realloc/copy: completion_owner, KTHREAD execution resource,
observer, reservation and root traversal references cannot be invalidated.
Memory exhaustion returns ENSMEM before identity consumption or publication;
caller-owned outputs/transactions retain their existing abort contract.

Initial batch slots stay reserved for their synchronous results and PROCESS
anchors. All task scans (wait/orphan/PID/context/deferred/cancel/reap/dispatch)
include grown slots. Reset/cancel preserves arena linkage. Slots are recycled
only after existing PROCESS wait/reap or root cleanup makes them unused. Extra
storage stays at its high-water mark until activation drains; only root frees
it, after all execution-resource reclamation. This trades bounded activation
high-water memory for stable pointer lifetimes; it is not unlimited memory or
persistent global scheduling. No new configuration option or public ABI.

Round-robin advances to the selected task's successor, wraps once across the
whole arena and skips private, stopped, zombie, draining and unready records.
Each runnable/yielding peer gets one turn per scan; predicates remain masked,
nonallocating and non-yielding. BLOCKED registers predicate/context before the
safe root jump. Current cooperative + IRQ exclusion prevents check/block races;
no SMP/lost-wakeup guarantee is inferred for preemptible producers.

Ownership and completion
-------------------------
A task owns one KTHREAD; its backend resource owns the scheduler stack and any
untransferred syscall stack. Launchers take the child syscall stack and free it
only after leaving that continuation. Root alone reaps the stopped task's other
stack/startup resources. The task retains a KPROC completion identity separately
from live execution resources/KASPACE references. SAME_PROCESS workers borrow a
stable PROCESS anchor record, including after its initial TID stops (DRAINING).
Last THREAD completion changes anchor state once; sibling stops are not separate
PROCESS completions. Async zombies retain PID/status until existing Pwait or
orphan disposal; #909 remains the wait consumer. Parent links are cleared before
PD retirement; retained KPROC parent/controller ownership remains the authority.
The root controller is borrowed only while its blocked continuation owns the
activation. CUIS observes completion but owns none of these generic lifetimes.

Migration plan
----------------
A1 (implemented here): stable growable storage + one RR across the activation,
production allocation-failure and deep-slot traversal tests, native >8 mixed
PROCESS/THREAD scheduling and repeat/reclaim tests on all three MMU targets.

A2a (implemented): kernel-owned persistent root/idle stack, a separate attached
waiter continuation and kernel-owned result copy. See the lifecycle below.

A2b (remaining): explicit persistent admission/drain/result ownership. Retain
logical parent separately from a durable controller and live launcher/waiter;
replace the single gated waiter with independently retained completion/result
handles and an abandonment contract.
Migrate ordinary async admission and explicit groups through that ONE root.
Allow a synchronous launcher to return when its own completion is ready while
other independent tasks remain admitted. Preserve nested launcher status and
safe-stack handoff. Separately retain zombie identities, with #909 consuming
completion; do not build a second waiter. Do not reuse/free an anchor with a
sibling, observer or reserved publication referencing it. This must precede
claiming global background execution. Neither dynamic slots nor a permanent
root stack alone proves independent controller/result lifetime.

B: add per-CPU current execution + nested launcher, pending-reschedule/quantum
accounting and architecture-owned user-interruption frames. Timer IRQ only
accounts/requests; no arbitrary kernel continuation switch. At the verified
outermost USER return boundary, transfer a complete frame to the THREAD backend,
acknowledge interrupt, leave the exception stack safely and dispatch through the
existing root. An outstanding request while kernel/BIOS/filesystem/GUI/callback
code runs stays pending until an eligible return. Mapping faults and kernel
error/termination callbacks remain non-preemptible. Masked/critical/foreign
callback/nested child checks must use execution identity, not only run or CS/SR.

C: enable controlled USER-only preemption after B and synchronization tests.
Require two CPU-bound peers without Syield, starvation bounds, a timer-woken
blocked peer while another is CPU-bound, CPU/FPU patterns after IRQ switches,
no kernel critical-section switching and exact resource baselines. A counter or
cooperative yield pass is not preemption evidence. No new preemption enabled.

Timer/return readiness by architecture
---------------------------------------
x32: PIT IRQ0 drives 200Hz accounting through irq.c. irqasm.S saves 15 GPRs,
FXSAVE image and iretq frame, acknowledges via dispatch, restores same frame.
Its user-callback return hook already distinguishes user CS, but does not own a
schedulable interruption. Need retained RIP/CS/RFLAGS/RSP/SS + all GPR/FPU state,
CR3/TSS syscall-stack identity and an off-IRQ-stack handoff to root. Current
setjmp scheduler state only represents cooperative kernel continuations.

ARM Cortex-A7: generic physical timer PPI30 calls vector_5ms; dispatch_irq saves
exception return state via SRS, caller-clobbered registers and FPU image on the
SVC stack and returns with RFE. Callee-saved registers survive the C call but are
NOT a complete stored preemption context. Need all R0-R12, user SP/LR, return
PC/CPSR/SPSR, FPU/FPSCR and banked SVC/IRQ stack/return ownership. Save/restore
currently serializes banked user SP/LR, TTBR root, launcher and disk-error state;
trap frames/setjmp carry the rest at cooperative boundaries. Cannot longjmp a
scheduler save from an IRQ and claim full interrupted-user register ownership.

m68k: virt goldfish RTC/PIC returns via RTE; Atari MFP timer C and Amiga timer
paths feed the classic 200Hz vectors. Ordinary ISR register saves + ABI are not
an owned complete context. Need D0-D7/A0-A6, USP, the exact CPU-specific SR/PC
exception frame, supervisor/exception stack, MMU root and complete FPU
frame/FP0-7/FPCR/FPSR/FPIAR. 030/040/060 exception/FPU frame shapes differ. Global
uenter staging and launcher/error state must become protected/per-execution
before asynchronous dispatch. Preserve 060 cache and nonzero-FPIAR probes;
QEMU 060 PFLUSHA remains separate #913, non-MMU scheduling #911.

Interruption and synchronization policy
----------------------------------------
For this increment all switches remain explicit cooperative handoffs with IRQ
state restored by existing backends. Interrupt handlers may produce events but
cannot mutate/reap task records or switch arbitrary kernel frames. No new IRQ
masking region, callback under a new lock, or permanent global IRQ mask is added.
IRQ exclusion is local interrupt control, not an SMP lock.

Future user-only preemption still needs serialization of membership/group-exit,
TID join/completion claims, clone no-fail publication, root/anchor lifetime,
ASPACE maps/faults/leases/copyout, current task and nested launch state. Timer
interrupts set a request; kernel-owned state changes defer dispatch. Do not hold
a lifecycle lock over copyin/out, allocation, I/O, callback or context handoff.

Required lock policy before B/C: the runqueue lock is a LEAF. No readiness
callback, last-reference destructor or PROCESS/CUIS notification runs under it.
Resource owners (completion, input/device, membership) register readiness under
their own lock, then briefly nest the runqueue lock to admit/block/wake; release
all owner locks before handoff. A wakeup must pair a generation/predicate
recheck with blocking so an event cannot be lost between check and sleep.
Multi-resource clone publication needs the audited order membership -> mapping/
lease -> runqueue, with fallible work outside and no callbacks after first
output store. Completion-claim locks must not nest inversely through PROCESS
teardown. CUIS/filesystem locks must not be acquired under runqueue; evaluate
existing arbitrary predicates outside it before making the dispatcher locked.
This is a migration constraint, NOT implemented SMP locking. All actual call
sites/interrupt priorities need lock-order validation before enabling B/C.

Filesystem/global watchdog and callback reentrancy remain non-preemptible;
errbuf restoration at cooperative switches does not make interrupted filesystem
operations reentrant. ARM banked LR/SP/FPSCR, m68k uenter and x32 TSS/current
launch state require per-CPU ownership. Generic PROCESS waiting stays #909;
TLS #908, non-MMU #911 and ARM/m68k GUI #898 are not scheduler prerequisites.
CUIS stream cancellation stays disabled under its existing #907 contract.


A2a persistent root lifecycle and validation
--------------------------------------------
Storage: one 16 KiB, 16-byte-aligned kernel BSS array and kernel scheduler CPU/
setjmp storage. No procmem owner, KPROC/PD allocation or ASPACE user mapping can
own/free it. It is a fixed kernel footprint, not an allocation left by a launch.
Feature-disabled/classic non-MMU builds do not compile this scheduler storage.
No new Kconfig flag. The existing CPU native_sched_enter hook bootstraps the root
once, with its existing x32 C-entry alignment or ARM/m68k supervisor ABI. CPU
backends and user entry/exit are otherwise unchanged.

Initial attachment: serialized dispatch saves the caller CPU/FPU/MMU/IRQ state
on the caller's STILL LIVE kernel stack, then captures the root's masked,
kernel-mapped execution state. A separate waiter_resume is the temporary return
route for that synchronous call. It is not scheduler.resume. Kernel-owned result
slots retain values; the root NEVER stores a caller result pointer/array.
All existing image/clone fallible preparation still precedes dispatch/publication.
The static root requires no fallible allocation or user resource acquisition.

RUNNING/IDLE-ACTIVE: scheduler.resume always points into the permanent root frame.
Root dispatch and reclamation assert their current SP lies inside that stack and
check its low guard. BLOCKED/deferred/draining work keeps the task arena alive.
When no task is ready, existing backend idle services interrupts and rechecks
predicates on the SAME root stack. IRQs do not switch arbitrary continuations.
Task/sibling ownership and one RR runqueue are unchanged. Syscall stacks remain
launcher-owned after transfer; task stacks remain KTHREAD/root-reap-owned.

Root owns its disk-error boundary as well. An escaping cleanup disk error must
panic on root, never jump into the waiter's saved errbuf, retry partial cleanup
or publish a duplicate result. Recoverable kdos_fclose retries remain local;
this is fail-stop, not transactional recovery. Private callback longjmps remain
unsupported. No allocation/callback/user copy is added to the no-fail publication
section; the boundary is installed before pending clone commit and root cleanup.

PARKED: after all tasks drain and normal root-safe reaping, copy initial results
to kernel slots and free the whole activation arena/high-water storage. Clear
root CPU state, including PD, launcher, syscall/IRQ stack and disk-error pointers.
Mark inactive/parked and jump to the attached waiter's continuation. Only that
live waiter copies results to its destination, clears the kernel result slots
and its waiter_resume/attachment, then restores its own CPU/FPU/MMU/IRQ state and
returns. Admission rejects an attached waiter even if active is already false,
so result consumption cannot be overwritten by a reentrant activation. The
permanent root frame/stack survive. A subsequent attachment installs
fresh root CPU/controller state BEFORE resuming that same root frame. Old PD
address reuse cannot resurrect an idle root reference. Mutable root locals are
assigned after setjmp; no modified automatic state is relied on after longjmp.

Shutdown: permanent root storage is never freed, especially not while executing
or idle. Existing shutdown/reset ends kernel execution; cold startup clears BSS.
There is no new global-background shutdown/drain policy yet. With the current
admission gate, normal waiter return still requires complete activation drain.
A parked root consumes no CPU; a future permitted attachment resumes it. An
active idle root retains all blocked tasks and wakes through ordinary IRQ events.

Tests: the production host fixture performs 32 ACTUAL alternate-stack park/
resume handoffs on one root frame, changes/reuses modeled caller PD storage,
checks exact per-caller results and IRQ flags, zeroed parked CPU/waiter state and
one bootstrap entry, with counted arena reclamation. CPU/MMU mechanics there are
modeled, not native kernel execution; normal and UBSan runs exercise these
stack handoffs. A final injected disk error during root
retirement proves fail-stop before caller output delivery and no repeated
release. Hosted ASan does NOT execute this kernel-private alternate-stack ABI;
its production allocation/retirement/publication tests still run with ASan/UBSan.
Native x32/ARM/m68k suites execute real user tasks through the owned root, enforce
root-stack/guard assertions and preserve register/FPU/MMU, nested Pexec, join,
group exit, orphan, >8-peer fairness and resource-baseline regressions. Root idle
and parked root are distinct states, not preemption evidence.

Exact remaining blocker: an independent background task still needs a durable
controller/launcher return contract, and a waiting caller needs an independently
owned completion/result/admission record that can be consumed or abandoned.
The single waiter cannot be detached before drain while task preparation uses
its compatibility PD/launch chain. No new ordinary async admission outside an
activation is enabled; no claim of background execution after the outer waiter
returns. A2b must also define how an unmanaged caller yields into the global
root after its synchronous return, without borrowing a reclaimed syscall stack.
#909 remains the public PROCESS waiter; do not build a parallel Pwait consumer.

Before preemption/SMP, protect root park/attach transitions, waiter/result
ownership and final detachment with the existing planned publication/leaf-runqueue
ordering. Replace the global single-waiter/current-task/error/launcher state with
per-CPU state, serialize shutdown versus admission and provide wait generations.
No readiness callback or destructor under a future runqueue lock. IRQ masking
alone is not cross-CPU synchronization. CUIS stream cancellation stays disabled.
