pTOS status
===========

pTOS is an experimental portable TOS-compatible operating system.  A
configuration being present means it is supported by the build system; it does
not by itself promise the same hardware coverage or software compatibility as
EmuTOS.  This file records platforms that have been boot-tested.

Tested platforms
----------------

  platform                     | status | notes
  -----------------------------+--------+--------------------------------------
  Raspberry Pi 2B              | tested | native ARM build and boot
  Raspberry Pi 3               | tested | native ARM build and boot in 32-bit mode
  Raspberry Pi 400             | tested | Raspberry Pi 4-class hardware
  QEMU ARM virt                | tested | serial-console boot; use highmem=off; every process in an address space of its own (virt-arm-aspace)
  QEMU raspi2b                 | tested | every process in an address space of its own (rpi2-aspace); not tested on the hardware
  QEMU m68k virt               | tested | serial-console boot; the 68040 MMU with the kernel in the upper half and every process in an address space of its own (virt-m68k-aspace)
  QEMU x86-64 PC               | tested | UEFI/OVMF boot; EmuCON runs as an x32 program in ring 3 (no AES/EmuDesk)
  Hatari Atari emulation       | tested | m68k Atari configurations
  Hatari Falcon 68030/040      | tested | atari512: pBench in CI, regression tests by hand
  Hatari Falcon/TT, MMU on     | tested | the kernel in the upper half and every process in an address space of its own (falcon-mmu, falcon-aspace, falcon-aspace040: 68030 and 68040); CI builds Hatari from a pinned commit (tools/hatari-pin.sh)
  Amiberry Amiga 030/040/060   | tested | the ROMs with the kernel in the upper half (amiga-mmu, amiga-mmu040) and with every process in an address space of its own (amiga-aspace, amiga-aspace040); CI uses a pinned Amiberry (tools/amiberry-pin.sh)

Other configurations are maintained as portability targets and may be
build-tested without equivalent runtime validation.  See configs/ and
readme.md in the source tree (https://github.com/kelihlodversson/pTOS) for
the available configurations and current development work.

Testing
-------

Build a target with its defconfig, then build the regression-test disk
(CONF_WITH_REGRESSION_TESTS, on by default -- `make menuconfig` if it isn't):

    make rpi2_defconfig && make
    make test-hd

Boot the image with test-hd.img attached in the appropriate emulator or on the
target hardware.  The test program writes PASS/FAIL results to the console.
The emulator commands and test-harness details are in tests/readme.md in the
source tree (https://github.com/kelihlodversson/pTOS).

The current runtime status is intentionally narrower than EmuTOS's historical
compatibility matrix.  pTOS's purpose is to develop and validate portable
hardware support; the upstream EmuTOS project remains the reference for broad
compatibility with established Atari hardware and software.
