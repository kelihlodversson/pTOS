Current binding decision: COW Pfork AND COW Pvfork
-------------------------------------------------
Both calls use proc_clone(NEW_PROCESS,PRIVATE_VM). One saved-return constructor,
one resource/snapshot/THREAD/publication/rollback path. Only parent continuation
policy differs: immediate Pfork or exact-child suspended Pvfork. This is an
accepted deliberate FreeMiNT memory-sharing deviation: ordinary private child
writes do not change parent memory; the child has its own logical user stack.
No shared parent/child KASPACE, shared writable stack or parent-root detach
requirement applies. Explicitly shared mappings retain their semantics, but
pTOS public MAP_SHARED remains unsupported. Non-MMU fork stays outside Phase6.

Seven essential answers
-----------------------
1. Same trap instruction: yes only within saved-return admission above;
   no claim for Thumb, 030/6888x, 060, fastcall, arbitrary TLS/segments or
   pending/other FPU/exception frames. Native proof required for new path.
2. Selected child root: backend already supports it; common equality guards
   and cloned bridge must be extended, authenticating captured source identity.
3. All PROCESS resources: no. Checked refs do not create descriptor bindings.
   Environment/basepage and raw image metadata need explicit fork policy too.
4. Parent blocking without kernel-stack sharing: existing bounded shared probe
   does this via ksched_wait_ready(non-consuming exact KPROC snapshot), fresh
   child stacks. Arbitrary shared-stack C use is not an accepted vfork API.
5. Executable replacement preserving PROCESS/PID: no accepted transaction.
6. Exact child release: final completion observation already exact/non-consuming;
   committed replacement release is missing. Pexec4/104 launch is insufficient.
7. Cooperative scheduler: sufficient for restricted private construction and
   independent dispatch. No preemption/SMP, public PROCESS dispatch, public
   Pexec4/104 or GUI dependency is needed for this increment.

Initial policy
--------------
Reject non-sole THREAD and other live same-root PROCESS callers before resources.
Do not copy C stacks, jmp_buf, scheduler continuations, borrowed parent PD or
return-frame pointers. Copy only user state into child-owned startup. Public
Pfork/Pvfork are CONF_WITH_FORK (on by default in the native process profile)
and return EINVFN without it.
The test-only private continuation has no descriptor inheritance claim. Neither an exit-only
Pvfork approximation nor a passing prerequisite completes public fork.

Implemented scope (Draft PR972)
-------------------------------
The private saved-return adapter authenticates saved.space against the retained
transaction source_space, while preparing in selected tx.space. It reuses
thread_startup's cloned bridge path. x32 constructor CR3 is preserved; ARM/m68k
launchers select the KTHREAD root through their existing entry owners. Only the
child syscall result changes. Neither parent kernel stack nor capture pointer
is copied. The private test parent returns PID immediately; the shared proof
retains its old final-completion wait. All fallible work precedes the existing
spawn publication, with abort releasing acquired owners and collapsing source
COW after failed private construction. Both existing native test gates must
be selected; no shipped preset changes.

Original C-stack support uses a separate resident private-copy stack hold,
selected ONLY for authenticated cloned-return startup. Ordinary/shared entries
still require heap/mmap stack metadata. The new hold checks resident USER|WRITE
and backend private ownership, retains the selected root, and grants no lazy
reservation or permission. KPROC private_runtime remains the full copied top-
stack owner. Hosted controls reject absent/readonly/nonprivate/invalidated stack
leaves, wrong/equal source/selected roots and fail every constructor allocation.

New real user trap fixtures check original C frames/stack, distinct PID/TID/root,
DATA/BSS/heap/stack and anonymous/lazy/file private COW, both write orders,
nested private saved-return, early parent independence and once-only public
wait. Existing assembly probes now also run private and report integer/condition/
FPU checks through child status, without shared diagnostics. Seven preparation
prefixes are injected; original backend failure sweeps remain. These are not
exhaustive native allocation/TLB/publication fault injection or full resource
inheritance tests. No public Pfork/Pvfork support is counted from them.

The new allocation sweep under ASan/UBSan exposed an existing cloned-bridge
uninitialized lease pointer in thread_return.c. The copied bridge now initializes
hold=NULL before fallible acquisition. Old-source control fails at
kaspace_lease_release with poisoned0xbebe pointer; fixed source passes with
leak checking. It is a correction within the existing bridge owner, not a new
lifetime mechanism. CI runs the startup sweep normally, fortified and sanitized.

-------------------------------------------------------

DATA/stack-cap inheritance follows the existing factory. Existing CWD/drive and
selected standard-handle policy is independent, not blindly activated here.

The default-off same-image scheduler transport is independently native-testable.
Its private diagnostic handoff count is NOT a KPROC committed-exec generation.
Public Pexec(200) is implemented and on by default (CONF_WITH_EXEC_REPLACE): a different-root ELF or classic PRG commit on a new
basepage (FreeMiNT overlay semantics) for anchors at the
scheduler root and for nested children through their launcher frame, with one
KPROC committed-exec generation per commit. Pfork and Pvfork are CONF_WITH_FORK.

Both eventual fork calls construct independent PRIVATE_VM/COW children; Pvfork
additionally suspends the exact parent THREAD. No shared-parent VM/user-stack
detach is needed. Only the exact child's genuine committed-exec generation or
its later canonical final PROCESS completion may release that dependency.
Ordinary launch, staging, failure or the same-image transport cannot release it.

Full #970 native acceptance requires a DIFFERENT executable/root through the
real GEMDOS Pexec(200), retaining PROCESS/PID/initial TID on a new basepage, no old return,
exactly-once authenticated committed-exec publication and independent later
completion/reaping. Require x32 FAT, A7 FAT/PFS and 040 FAT/PFS, all resource and
rollback controls and five shutdown checks each. Do not infer it from this
prerequisite's tests, synthetic prepared entries or a modeled event.

EXEC200.TOS (tests/pclone/exec200_native.c, exec200_image.c) is that test. It
runs in both the "private ELF staging" and "PROCESS descriptors" CI jobs of the
matrix above, which require these markers:
- "native Pexec(200) same-PROCESS executable/root replacement: PASS" (anchor);
- "native Pexec(200) from an anchored Pexec(0) child: PASS" (a managed
  THREAD's Pexec(0) child, an anchor since #1015);
- "native nested Pexec(200) launcher relaunch: PASS" (a Pexec(0) child kept on
  the nested carrier by the regression kernels' switch; only where
