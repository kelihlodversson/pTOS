B1: architecture-owned interrupted-user state (#713)
====================================================

Implementation plan and boundaries
-----------------------------------
B0 repair comes first (panic declaration and prepared-slot initialization with
strict GCC13/architecture warning gates). B1 does not enable a timer dispatcher,
reschedule request or arbitrary kernel/IRQ continuation switch.

B1a: separate global queue ownership from boot-CPU execution/root/attachment
storage; pin a dispatched execution to that CPU until verified root handoff.
Reaping and record reuse must reject an on-CPU execution even if the loaded
current-task pointer has already been cleared by backend context restoration.
Exercise the actual existing x32/ARM/m68k cooperative backends, nested Pexec,
A2c return/park/resume, cancellation and exactly-once cleanup. This is the first
independent production increment, not a claim of complete interrupted frames.

B1b x32: reuse irqasm.S's saved 15 GPRs, FXSAVE and five-word user iretq frame.
Define shared C/assembly offsets and validate user CS/SS, RFLAGS, RIP/RSP and
frame origin. Retain CR3/ASPACE and TSS/syscall/IRQ-stack identity separately
from the register payload. Copy only into preallocated THREAD-owned storage;
keep the original IRQ return unmodified until capture/register-pattern tests
pass. A kernel-mode IRQ must never be mistaken for a five-word user frame.

B1b ARM Cortex-A7: extend the existing IRQ SRS/return wrapper with all R0-R12,
user SP/LR, SPSR/CPSR/return PC, full D0-D31/FPSCR and the banked IRQ/SVC SP/LR
needed to identify and abandon the exception continuation safely. Preserve
8-byte stack alignment and use C/assembly layout assertions. Existing syscall
frames cannot substitute for this: SVC dispatch may clobber scratch R12 and
IRQ code currently saves only the ABI-required subset. Capture tests precede
any modified RFE/exception-return path.

B1b m68k: retain D0-D7/A0-A6, USP, supervisor/exception-stack identity, SR/PC,
vector/format and exact exception-frame bytes, plus MMU root/control identity.
Decode sizes by CPU/model and format; never copy a guessed constant length for
030/040/060 bus/fault frames. Save the CPU-specific FSAVE state, FP0-FP7 and
FPCR/FPSR/FPIAR using existing architecture primitives. Validate all supported
formats and reject unsupported frames without changing RTE. Use QEMU040,
pinned Hatari030/040 and Amiberry060 caches off/on with nonzero FPIAR; do not
claim QEMU060 or native fastcall evidence without execution.

B1c: bind each captured frame to retained THREAD/execution/CPU/ASPACE identities
and explicit stack owners. Reconcile loaded launcher and error-continuation
compatibility globals with CPU-local storage before IRQ captures may escape
the current exception. No allocation/callback/user copy in IRQ capture. A
capture is not permission to resume: safe exception-stack acknowledgement and
return validation are mandatory before any eventual restore path.

B2 alone adds deferred requests and a verified outer USER-return handoff, with
owner/leaf/callback/fault/nested-launcher exclusions and revalidation. C alone
adds controlled user-only preemption and CPU-bound no-Syield progress tests.
SMP remains disabled: a boot-CPU slot/accessor is not an SMP implementation.

Current B1a ownership
---------------------
The shared queue owns stable task records, RR cursor, admission and shutdown
policy. A separate CPU-local execution record owns current/in-flight execution,
root stack/context/resume, scoped caller attachment, pending clone handoff and
leaf-recursion state. There is one boot CPU today; additional CPUs must supply
architecture-local selection and actual shared-queue locking before activation.

Dispatch claims the execution for that CPU before transferring control. It
remains on-CPU through nested synchronous launchers, blocking preparation,
termination intent and launcher finalization. Restoring the root context may
clear the loaded current pointer, but cannot release this claim. Only the root,
after verifying it is on its own permanent stack, acknowledges the handoff.
Then and only then may THREAD/backend resources or task records be reaped/reused.
The claim is a lifetime pin, not a second stack owner or completion mechanism.

Root CPU snapshots include their launcher/error images; task snapshots retain
the corresponding suspended execution images. The architecture-loaded
current_launch/active and global run/errbuf compatibility slots still belong to
the single boot CPU and are not safe for multiple CPUs or asynchronous kernel
switching. Their full conversion is B1c, not implemented by renaming a structure.
No full interrupted-user register payload is captured/restored by B1a. Existing
cooperative setjmp/native contexts are not advertised as interrupt frames.

Integration evidence must distinguish scheduler-stack/CPU ownership tests,
modeled host contexts, real native execution and complete IRQ-frame preservation.
Use an isolated validation branch for latest epic/#907 + the #910/#914 stack;
never merge unrelated CUIS removals into this scheduler PR to make tests pass.
Preserve both #917 physical-input admission fences and keep their cooperative
precondition explicit until C introduces an operation-admission handshake.

B1a validation (CPU ownership, not full interrupt-frame evidence)
----------------------------------------------------------------
Production-code host tests explicitly restore a cleared loaded-current pointer
while the old execution is terminal: root reap refuses it until CPU handoff
acknowledgement. They also cover both anchor-release orders, admission rollback,
shutdown, retirement/reentrancy, detached results, blocked tasks and root reuse.
GCC13 fortified and ASan/UBSan CUIS/ownership suites pass. Hosted CPU/MMU contexts
are models; these results do not establish architecture IRQ register capture.

Actual native execution: x32 desktop 23/0 plus five shutdown checks; ARM Cortex-A7
27/0 plus five; m68k 68040 26/0 plus five. Existing public A2c launcher-return/
later-child dispatch, twelve mixed PROCESS/THREAD peers, nested launchers,
CPU/FPU state, joins, group cancellation, fault/TSR and cleanup tests are retained.
The x32 memory/GEM/input boot suite and eager scheduler-disabled boot pass.
Amiberry v8.5.0 68060 passes 25/0 caches off/on with strict nonzero FPIAR.
Classic 192 KiB ROM/test disk, clone ABI/decoder, ELF52 and gitready pass.
Pinned Hatari Falcon/TT execution and isolated latest-epic combined validation
are recorded separately in the PR/checkpoint evidence after their completion.

B1b first increment: x32 device-IRQ capture
-------------------------------------------
include/arch/x86_64/irqframe.h defines the exact 688-byte FXSAVE/GPR/vector/
user-iretq image. C checks every field offset and total size; irqasm.S shares
these constants. Before device dispatch/callbacks, it passes the original image
to bdos/arch/x86_64/interrupt_user.c. It still restores that original FXSAVE,
GPR and iretq image; the captured copy is never installed as a continuation.

The generic target query admits only the boot CPU's pinned RUNNING execution,
matching live KTHREAD/PROCESS/ASPACE and current PD. Nested Pexec executing a
different PROCESS, blocked/stopped threads and leaf critical sections are
ineligible. The query changes no reference counts and invokes no callbacks.
It requires the existing masked device-IRQ entry and cannot yield. THREAD owns
preallocated backend capture storage before publication. No IRQ allocation,
user copy, demand fault, notification or reschedule occurs.

The architecture backend validates native user CS/SS, low user RIP/RSP,
RFLAGS privilege bits, vector/padding, CR3 against the retained KASPACE backend,
and exact IRQ-frame/TSS-top/syscall-top binding. It copies all 512 FXSAVE bytes,
15 GPRs and the user iretq frame, stamps execution/TID/CPU and advances a bounded
per-execution capture sequence. Exhaustion refuses capture rather than wrapping.
Only numeric register/source-address provenance is copied; it is never used
as a borrowed image pointer or dereferenced after IRQ return. Existing KTHREAD
ownership retains ASPACE and stack holds; this adds no second resource owner.

The valid flag means only a copied diagnostic image within this on-CPU dispatch.
It does NOT authorize restoring it, prove mapping permissions for future return,
or represent a newly captured kernel IRQ. Root acknowledgement invalidates it
before stack/record reclamation. B2 must require a fresh eligible user boundary
and revalidate bindings/leases; it must never resume an old diagnostic snapshot.
TLS and AVX/XSAVE state are unsupported; this is the existing x87/MMX/SSE ABI.

A native ring-3 probe sets distinct nonzero upper/lower 64-bit GPR patterns,
all 16 XMM registers, x87 ST0/control, MXCSR and DF, then executes a bounded
no-syscall/no-yield loop. The test-gated kernel checks the actual captured bytes;
root reports the result outside IRQ. The user probe also checks GPR, FPU/SSE
and DF preservation after IRQ return. This is capture/return evidence, NOT
CPU-bound scheduling progress or preemption. The memory-test boot requires this
marker plus its existing full verdict. Ordinary desktop kernels still capture,
but compile out kernel pattern diagnostics; the desktop user probe remains.

Production-code host tests model CPU queries and check immutable source/copy
ownership, failed CR3/stack binding, sequence exhaustion and unchanged kernel
IRQ behavior. Separate scheduler tests reject foreign CPU, nested PROCESS,
incompatible ASPACE, blocked and leaf-held targets. Native memory/GEM/form/input
and desktop23/0+five shutdown checks pass; ARM27/0+five and m68k04026/0+five are
compatibility execution, not new interrupted-frame evidence. Sanitized and
fortified ownership/capture tests remain separately identified as host execution.

Remaining B1b/B1c
------------------
ARM and m68k interrupted-user payload capture remains planned above; existing
native clone/FPU execution does not prove it. Before any captured frame may
escape its original exception, finish CPU-local loaded launcher/error state,
ARM banked/exception/VFP ownership and m68k uenter/FPU/frame staging. x32 loaded
current_launch, run/errbuf and syscall compatibility globals also remain boot-
CPU-only; this increment neither converts those globals nor switches kernel
frames. B1c and B2 are not complete. Preemption stays disabled.
