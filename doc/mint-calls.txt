MiNT / MagiC system calls in pTOS (the audit of #454)
=====================================================

What pTOS has now that it had no way to give before: per-process address
spaces with page-level permissions (include/procmem.h, ASPACE_PROT_*), lazy
memory, per-process limits (Psetlimit), checked user pointers
(bdos/uaccess.c), a kernel-side process record (bdos/kproc.c). Reference:
FreeMiNT (sys/ssystem.c, sys/dosmem.c, sys/syscall_vectors.c,
sys/mint/ssystem.h) and https://freemint.github.io/tos.hyp/en/.

The decision column: DONE (with the PR), PLAN (a group of this issue, own PR),
EINVFN (cannot be honoured, the call says so), OUT (not in this issue).
Where a call or mode needs the address space, it is only there with
CONF_WITH_USER_ASPACE; the architecture independent parts carry no x86-64
names.

Cookies (readable with Ssystem(S_GETCOOKIE))
--------------------------------------------

  Set today (bios/machine.c fill_cookie_jar): _CPU, _FPU, _VDO, _MCH, _SWI,
  _SND, _FRB (only with alternative RAM), _AKP, _IDT, _FDC, __NF, XHDI, SCSI, _5MS (as
  the machine has them), and the ColdFire ones.  _FLK is not set (fill_cookie_jar() has
  only its comment): until file and record locking is implemented it stays out.
  "MiNT" is not set either: it would promise Pfork, signals and the rest.

  DONE (group 4): _CPU and _FPU of a CPU that is no 68k.  The Atari values are small
  numbers (0, 10, ..., 60; bit masks), and a program that takes the number for one of
  those takes a foreign CPU for a 68k (x86-64 had the raw CPUID signature there, ARM the
  raw ID register).  Bit 31 is set now, which no 68k value has (include/cookie.h):
  _CPU = 0x80000000 | the ELF machine number (ARM 40, x86-64 62, also for x32),
  _FPU = 0x80000001 (hardware floating point: VFP, SSE2).  _MCH and _VDO are
  MCH_NOHARD and VDO_NOHARD without Atari hardware, as they were.  The kernel's own
  mcpu is not changed; nothing in the kernel reads the cookie.

Not in this issue
-----------------

Pfork/Pwait/signals (real multitasking), MiNT file systems and device drivers
(Dcntl, XFS), networking.
