Generalising the x86-64 process and memory features (#453)
==========================================================

The x86-64 port added features to shared code (bdos/, bios/, include/) under
x86-64 names and behind architecture #ifdefs.  The aim (#453) is general names,
Kconfig feature options (CONF_WITH_USER_ASPACE, CONF_WITH_KPROC,
CONF_WITH_USER_COPY, ...) instead of architecture tests, and the differences
between CPUs in bios/arch/<ARCH>/ and bdos/arch/<ARCH>/, the differences between
boards in bios/machine/<name>/.  A feature need not exist on the other
architectures yet; its option depends on the ones that have it (and may be
selected on x32).  This file lists the interface, group by group, and what has
been done with each group.

The groups are the x86_64_* symbols that code outside the x86-64 directories
uses (grep for x86_64_ and X86_64_ in bdos/*, bios/*.c, include/, aes/, desk/,
cli/ and util/ to regenerate it).

1. Address spaces                                                      DONE
   x86_64_aspace_*, X86_64_ASPACE, X86_64_USER_* (layout), the page fault
   reserve: now aspace_*, ASPACE, USER_*, ASPACE_FAULT_*.  The page-table root
   is aspace_root() (a CR3 value on x86-64), kproc_user_root().  Users:
   bdos/kproc.c, bdos/elfld.c, bdos/bdosmain.c, include/progimage.h.  The
   implementation stays where it is (bios/machine/pc-x86_64/aspace.c on top of
   the page tables of bios/arch/x86_64/pgtable.c); the page-table format is the
   CPU part, the physical page allocator the board part.
   Still to do: guard the users by CONF_WITH_USER_ASPACE alone (a few
   #ifdef __x86_64__ remain in bdos/bdosmain.c and bdos/proc.c), and move
   include/procmem.h's declarations into a header named for the feature.

2. Process memory window (procmem)                                     DONE
   x86_64_procmem_* is now procmem_* (alloc, free, mfree, owner, size, gen,
   contains, pins, keep, ...); the ownership functions that bdos/proc.c defines
   (Pterm/Ptermres/Mfree side) are proc_free_owned, proc_make_resident,
   proc_release_block, proc_drop_child_record, proc_mfree, proc_resident_pd and
   proc_resident_len.  Users: bdos/proc.c, bdos/umem.c, bdos/bdosmain.c,
   bdos/mem.h, bios/bios.c.  The block pool the basepage and environment come
   from (ownership, generations, pins).  Shared design (ownership and
   generation checks); the board part (where the window is, X86_64_LOW_TPA_*,
   x86_64_low_tpa_init) stays in bios/machine/pc-x86_64/ and goes with group 5.

3. Launching and the ring-3 transition                                 DONE
   (the part in shared code)  bdos/proc.c no longer names the architecture
   for these features: x86_64_prepare_launch, _ring3_caller, _check_launch,
   _hand_over, _give_back are now prepare_launch, caller_has_aspace,
   check_launch, hand_over, give_back_image; x86_64_{mark,take}_kernel_code_pd
   are mark/take_kernel_code_pd; x86_64_kstack_alloc/free are kstack_alloc/free.
   They are guarded by CONF_WITH_USER_ASPACE at each call site (no stub macros
   for the other architectures).  The new CONF_WITH_PROCMEM (selected by
   CONF_WITH_USER_ASPACE; also selects CONF_WITH_KPROC) guards what takes
   process blocks from the procmem window: alloc_tpa(), alloc_env(),
   proc_free_owned(), Ptermres' proc_make_resident().
   Left, because they are real architecture differences and not features:
   struct gouser_stack and its set-up in proc_go(), the p_hitpa alignment in
   init_pd_fields() (the SysV/x32 entry convention), and proc_go() returning
   to its caller after the child ran (the x86-64 launch model has no gouser()
   unwinding); x86_64_call_on_stack (used only by aes/arch/x86_64/gemstart.c)
   and the static x86_64_kexec_resume (only in bdos/arch/x86_64/rwa.c) are
   private to their architecture directories and keep their names.  The
   upcall the exception handler makes when a process faults is general now:
   proc_fault() in bdos/proc.c (see group 4).  Entering ring 3 (iretq, CR3,
   syscall stacks) is bdos/arch/x86_64/rwa.c.

4. Program images and the user fault upcall                           DONE
   x86_64_x32image_check/layout/load, x86_64_x32_layout_valid/valid_in/load,
   x86_64_emucon_image, x86_64_x32probe_image and the types X32_IMAGE,
   X32_LAYOUT, X32_SEGMENT are now image_check/image_layout/image_load,
   layout_valid/layout_valid_in/layout_load, emucon_image, testprobe_image and
   PROG_IMAGE, PROG_LAYOUT, PROG_SEGMENT; include/x32image.h is
   include/progimage.h (guarded by CONF_WITH_USER_ASPACE).  Users:
   bdos/kproc.c, bdos/elfld.c, bios/bios.c.  An ELF layout (segments, entry)
   is not x86-64 specific; the rules it is checked against (the image window,
   no W+X for a built-in program) and the mapping stay in
   bios/machine/pc-x86_64/x32image.c.
   x86_64_user_fault became proc_fault(cause, code, address, pc, sp) in
   bdos/proc.c: the exception handler (bios/arch/x86_64/panic.c) decodes the
   vector into a cause name and passes the architecture's error code as `code`;
   reporting the fault and ending the process (Pterm(-1)) is shared.  The
   message is "process fault: <cause> code=... addr=... pc=... sp=..." (the CI
   boot test greps "process fault:").

5. Fixed low memory pools (a board matter)                             DONE
   The pool (x86_64_low_kdata_*) and the x86_64_vector_5ms_ptr and
   x86_64_scsidriv_root_ptr indirections existed only so that the '_5MS' and
   'SCSI' cookies could hold a 32-bit address of a kernel variable.  An x32
   program has no use for either cookie (no hooked 5 ms tick, no SCSI driver),
   so they are no longer published there: the new CONF_WITH_ADDR_COOKIES
   (bios/Kconfig; follows the architecture, off on x86-64) guards them in
   fill_cookie_jar(), and vector_5ms/scsidriv_root are ordinary variables
   everywhere.  The pool, the pointers and their __x86_64__ branches are gone.

6. Hardware access from shared drivers
   x86_64_inb/outb/ide_insw/ide_outsw (bios/ide.c), x86_64_kernel_trap
   (include/biosbind.h, include/xbiosbind.h, aes/gsx2.c, desk/gembind.c),
   x86_64_sti/x86_64_irq_init (bios/kprint.c, bios/bios.c),
   x86_64_gop_probe/_init (bios/screen.c), x86_64_smbios_machine_name
   (bios/machine.c), x86_64_apply_higher_half_relocations (bios/font.c),
   x86_64_pmem_free_bytes (bios/initinfo.c), x86_64_ps2_mouse_irq.  Each is
   one call that a general name (io_inb(), irq_enable(), machine_name(), ...)
   plus the existing machine/ or arch/ implementation covers.

7. Architecture #ifdefs that guard a feature
   __x86_64__ / ARCH_X86_64 / "__arm__ || __x86_64__" in bdos/bdosmain.c,
   bdos/proc.c, bdos/umem.c, bios/bios.c, bios/xbios.c, include/xbiosbind.h,
   include/biosbind.h, bios/ide.c, bios/vectors.h, include/intmath.h ...
   Each is either a real difference (move to arch/) or a feature (Ssystem
   additions, per-process address spaces, lazy memory, Psetlimit, ring-3
   pointer validation): give the feature its Kconfig option.

Porting candidates (the audit of step 4 of #453)
------------------------------------------------

What would need an MMU with per-process page tables (ARM with the MMU on, m68k
with a PMMU, #202): private address spaces, demand paging and overcommit,
Psetlimit's stack size, the guard page.  What does not: the KPROC record
(kernel-private process state), user-pointer validation (CONF_WITH_USER_COPY
already builds on m68k and ARM), Psetlimit's memory limits 2 and 3, the Ssystem
additions, Malloc(-1) semantics under limits.  A group is "mechanism" (x86
page tables, CR3, SYSCALL) or "policy" (what may be launched, what is limited);
only the mechanism goes under arch/ or machine/.
