Trusted THREAD construction and native startup (#892)
=====================================================

Current supported scope
-----------------------
One proc_clone transaction and one cooperative scheduler serve x32 ILP32,
ARMv7-A Cortex-A7 MMU and m68k040 MMU. CPU-specific context/entry backends stay
in the existing launchers. Pinned 030/060 shared-VM compatibility is distinct
from independent PRIVATE_VM support. No timer preemption, SMP, TLS or public
fork/vfork/shared-Pexec policy is enabled by this interface.

Policy boundaries
------------------
SAME_PROCESS/SHARE_VM attaches a distinct TID to the source PROCESS/PID and
KASPACE. NEW_PROCESS/SHARE_VM creates a distinct PROCESS/PID with one THREAD
while retaining that KASPACE. Resource-copy bits independently select standard
handles and CWD for NEW_PROCESS; they are invalid for SAME_PROCESS. Nonstandard
FD inheritance and future public Pexec/fork policy are not inferred from VM.

PREPARED_PROCESS is caller-owned identity construction, not runnable admission.
Its caller supplies the empty target and keeps disposal ownership. Identity-only
commit cannot authorize execution of a startup draft. LOADED_PROCESS/PREPARED_VM
constructs the existing loader target's non-runnable initial THREAD, using its
explicit selected construction space. It allocates no second PROCESS/PID and
never clones/adopts the parent's root in place of the loader's root. All fallible
THREAD construction precedes irreversible loaded-image transfer.

Gated PRIVATE_VM creates an independent KASPACE through the existing backend;
only NEW_PROCESS is supported. Child destruction precedes source COW collapse
on rollback. See aspace-clone.txt for CPU/mapping restrictions. Ordinary public
Pclone without CLONE_VM still fails EINVFN. Saved-syscall-return probes are
separate default-off tests, not public Pfork/Pvfork.

Construction and publication
-----------------------------
Arguments/results/transactions are kernel-owned. The transaction retains live
source/target KPROC and selected KASPACE identities; a reference is not a borrowed
PD or an execution-stack continuation. THREAD owns membership, PROCESS/KASPACE
references and a durable stack hold. No observer reference alone owns execution.

The startup draft prepares the CPU image, independent syscall and scheduler
stacks, a trusted RX return bridge, entry/bridge/stack leases, optional PID/TID
output leases and reversible observer registration. Temporary supervisor-only
compatibility borrows are generation checked and have explicit rollback bits.

All backing/COW preparation, allocations, controller/parent retention, observer
registration, task reservation, mapping checks and physical output/frame aliases
precede final publication. Source execution identity/current root, membership,
group cancellation and mapping leases are revalidated before seal. TASK_RESERVED
is not runnable, waitable or a completed child.

The serialized no-fail boundary transfers each owner exactly once, prepares
resident return/PID/TID stores and publishes RUNNABLE/TASK_NEW with barriers.
After the first external store there is no allocation, user copy, callback,
destructor, yield or recoverable failure. Transaction-shell release occurs
outside publication exclusion. No active stack is reclaimed by its own CPU.

An unpublished failure undoes only acquired resources, preserving user outputs
and caller-owned images. Failed observer admission undoes its own partial work;
successful admission adds one release obligation. Abort consumes its canonical
handle before callbacks; published abort is rejected. Identity-only commit and
runnable publication have different results and cannot be interchanged.

Scheduler and loader integration
---------------------------------
Ordinary/deferred preparation calls ksched_process_prepare, which reserves stable
storage and invokes kproc_prepare_async_thread -> kproc_prepare_user_thread ->
proc_clone_prepare_loaded_thread. Already-prepared root-group images use that
same loaded-thread factory before scheduler execution adoption. Thus loader
construction and root admission use the same policy/lifetime checks; the
scheduler still owns its arena, backend stack, dispatch, waits and root reap.

Public function-entry Pclone and trusted proc_clone_spawn/exec use prepared
startup drafts through proc_clone_commit_prepared. Root-group loaded images use
the existing loader's entry preparation, not an invented function-entry bridge.
The remaining kthread_create probe in MEMTEST deliberately attempts an invalid
association after clone publication and must be refused; it is not a launch path.

The permanent scheduler root/controller and retained admission/result records
are kernel-owned. Unmanaged bounded Syield can reenter the same runqueue after
an async launcher returns. Logical parent, controller and synchronous waiter
are distinct. Nested synchronous Pexec remains its own launcher continuation;
an unassociated nested caller cannot impersonate a managed clone THREAD.

Architecture-owned entry
-------------------------
x32: prepared GPR/FXSAVE state, user selectors/RFLAGS/RIP/RSP and root enter via
the existing ring-3 path. FS/GS bases start zero; no TLS. Red zone, alignment and
complete return slot are accounted for. Kernel syscall and scheduler stacks
are independently allocated and transferred, not aliases of the user stack.

ARM A32: AAPCS R0 argument, aligned user SP, LR bridge, zero initial integer/VFP
state and user CPSR. Existing SVC/exception-return code owns banked SP/LR,
SPSR and VFP/FPSCR preservation across actual switches. No x32 red zone.

m68k: user SR, USP and native stack return-PC/argument layout (two-byte native
alignment), independent SSP and format-0 initial RTE. Full integer/FPU state
uses the existing CPU-specific backend. Null FRESTORE frame handling is model
specific, including the 060 twelve-byte frame. Cross-page two-byte-aligned
outputs/frame pieces acquire every physical alias before sealing. QEMU040
cannot prove nonzero FPIAR; strict Amiberry060 tests provide separate evidence.

Normal void-entry return supplies THREAD status zero. Explicit Pterm and faults
use the existing thread-only handoff. The launcher restores its own root/CPU
state and releases the abandoned syscall stack after leaving it. Non-final
THREAD exit leaves PROCESS resources/completion live; the final THREAD alone
runs PROCESS finalization. Root later reaps the stopped scheduler continuation,
startup/observer/bridge and durable user-stack hold. Leader-first DRAINING
anchors survive independently; #893/#909 remain exit/join/reaping owners.

Mapping and cleanup scope
--------------------------
Logical KASPACE leases retain VA/rights; sealed aliases protect physical store
preparation. Mapping replacement/protection invalidates or refuses conflicting
leases. Startup permission validation is mapping-owned, including m68k logical
EXEC without NX; no original parent-PD metadata supplies authority after reuse.
Long-lived execution holds end only at stopped root reclamation.

Ordinary cleanup is protected by the accepted execution-scoped cancellation
envelope, not IRQ masking around callbacks. TASK_RETIRING is private during
prepared-image destruction. Final references/destructors run outside leaf
runqueue and GUI exclusion. Filesystem close failures use exact SFT ownership
and bounded quarantine/recovery; they do not justify retaining a dead PD/stack.
Arbitrary fatal/nonlocal callback/destructor unwind remains unsupported.

Before preemption/SMP, PROCESS ownership, mapping/lease mutation and publication
need the documented #713 lock protocol. Local IRQ exclusion is not an SMP lock.
Copied diagnostic IRQ frames are not runnable continuations; no arbitrary IRQ
or kernel-frame switch is authorized here.
