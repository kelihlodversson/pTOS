pTOS - standard ELF shared libraries (#660)
==========================================

Status and scope
----------------

This is the design and initial implementation work for a userspace ELF
runtime linker. Kernel PT_INTERP handoff and a freestanding self-relocating
LD.SO are implemented and verified with filesystem-loaded DSOs under QEMU.
The implemented core reads ELF32 dynamic metadata, performs SysV-hash
lookup and ordered-scope symbol resolution, discovers the dependency graph,
and eagerly applies RELA relocations. The architecture-neutral planner is
lib/ldso/relocate.c;
lib/ldso/arch/x32/reloc.c supplies x32 relocation widths and arithmetic.
lib/ldso/graph.c builds a bounded dependency closure through mapper callbacks.
lib/ldso/image_plan.c validates ELF32 load plans; lib/ldso/image.c populates
private userspace images;
x32 format policy is selected separately in arch/x32/image_abi.c.
bdos/elfinterp.c opens the named interpreter, and lib/ldso/startup.c constructs
the private initial stack. lib/ldso/runtime.c loads dependencies, binds all
objects eagerly, seals permissions and runs constructors/finalizers.
A separate dynamic CRT and shared client helper reuse selected libcmini
functions. Read-only physical-page sharing and a complete shared libcmini
remain to be implemented.

Lazy private anonymous mapping services are implemented separately as Mmap,
Munmap and Mprot, under CONF_WITH_MMAP (see doc/mmap.txt). The linker feature
selects that option. These services enforce W^X, accounting and process
ownership; they do not yet provide file-backed shared code pages.

CONF_WITH_ELF_SHARED is an experimental, off-by-default Kconfig option.  It
builds this core into obj/ldso/libldso.a, separately from the kernel.  It
requires CONF_WITH_ELF_LOADER, CONF_WITH_USER_ASPACE and, initially,
ARCH_X86_64.  Both x32 and the address-space prerequisite are intentional:
standard shared libraries must never fall back to a flat address space.

Shared C code is controlled by the feature/build configuration, not by
architecture-specific preprocessor tests.  Architecture selection belongs
in Kconfig and the build rules; relocation and startup backends belong in
separate files.  Do not widen the Kconfig dependency to ARM or m68k until
their MMU-backed, separate-process-address-space implementations have merged
to master and the corresponding linker backend has been tested.  FDPIC and
non-MMU loading are outside this issue.

The sections below distinguish implemented kernel startup and userspace core
operations from the remaining runtime-linker and page-sharing milestones.


ELF format and toolchains
------------------------

The initial target is the x32 psABI: little-endian ELFCLASS32, EM_X86_64,
ILP32 C types and pointers, executing x86-64 instructions in long mode.
ELF32 does not mean EM_386, and ELF64/LP64 is not an alternative encoding.
Use an x32-capable GCC and GNU binutils (native gcc -mx32 on Linux, or
x86_64-elf tools supporting -mx32 and elf32_x86_64).

An ordinary, fixed-address ET_EXEC with PT_INTERP is sufficient.  Do not
require PIE.  Its dependencies and the interpreter are standard PIC ET_DYN
objects built with -fPIC -shared, with PT_DYNAMIC and DT_* entries.  Use
--hash-style=sysv for the initial subset.  The kernel must not require
section headers, --emit-relocs, PT_PTOS_RELOC or PT_PTOS_IMPORTS on this path.

tools/test-elf-shared.py builds an independent libleaf.so, libtest.so and
ET_EXEC consumer using the actual compiler/linker.  The consumer requests
/GEMSYS/LIB/X32/LD.SO with PT_INTERP; libtest.so carries a transitive
DT_NEEDED and a constructor.  Host tests resolve symbols and apply the actual emitted relocations.
The ring-3 self-test separately maps the two DSOs with Mmap, relocates them,
seals text RX and data RW/NX, and calls through their GOT/PLT. It manually
calls the relocated constructor and verifies fresh data after unloading and
reloading. The harness uses the shared image admission/population code,
seals RELRO and checks it with Maccess. It does not implement PT_INTERP
startup or the runtime linker's constructor execution. The graph discovers libleaf.so
from libtest.so's actual DT_NEEDED rather than preloading it.

The x32 backend supports NONE, RELATIVE, RELATIVE64, GLOB_DAT, JUMP_SLOT,
32, 32S, PC32 and 64 RELA relocations.  x32 pointers are 32 bits, but some
relocation slots are 64 bits; relocation width is a property of the type,
not sizeof(void *).  Check signed/unsigned overflow as specified for each
type.  Reject unsupported relocation types before starting the application.
Initial applications should use PIC accesses to data even in ET_EXEC,
avoiding COPY relocations until copy-relocation semantics are implemented.

GNU-hash-only objects, TLS, symbol versioning, IFUNC, STB_GNU_UNIQUE,
SHN_COMMON, dlopen/dlsym/dlclose, lazy binding, auditing and Linux libc
compatibility are not in the initial subset.  Future load admission must
reject unsupported required facilities explicitly.  The current metadata
reader skips tags it does not interpret; it is not that admission check.


Kernel responsibilities and process entry
----------------------------------------

Keep the existing PRG and static-ELF dispatch and entry conventions.  Select
the standard dynamic startup path only through a validated PT_INTERP, never
merely because an ELF is ET_DYN or has PT_DYNAMIC (static PIE may have both).
Malformed or unsupported dynamic objects must fail, not enter the static
loader's additive relocation/import path.  A bare DSO is not an executable.

The kernel validates the executable and interpreter headers and PT_LOAD
segments, maps both into the child's own address space and enters the
interpreter at its own entry point.  Preserve the executable entry separately.
Interpreter admission requires ET_DYN, the matching machine/class/endian,
no nested PT_INTERP and no pTOS-private imports or compact relocations.
The kernel neither resolves DT_NEEDED nor performs their symbol binding.
The interpreter must bootstrap its own relocations before calling C that
relies on relocated addresses; the kernel does not relocate it. The current
probe is independently linked PIC with no self relocations.

PT_INTERP must be unique, nonempty, bounded, exactly NUL-terminated and an
absolute pathname.  The parser must validate file offsets and sizes before
reading.  The kernel opens that exact interpreter, with no shell expansion
or environment search. ELF slash paths are translated to GEMDOS separators
on the explicit boot drive, independent of the caller's drive and directory.
Colon, backslash and control bytes are refused. Failure to open it is a load
failure; the main program is never entered in its place. Disabled shared
support rejects PT_INTERP instead of falling through to static relocation.

The standard x32 initial stack is distinct from the existing pTOS
function-call entry contract in doc/process-entry.txt:

    RSP -> uint32_t argc
           uint32_t argv[argc], followed by a zero pointer
           uint32_t envp[envc], followed by a zero pointer
           Elf32_auxv_t auxv[], terminated by { AT_NULL, 0 }

Each auxv entry is two 32-bit words.  RSP is 16-byte aligned at the initial
instruction, with no synthetic return address; the startup assembly creates
the ordinary RSP+8 C-call alignment before invoking a C function.  All
pointers and auxiliary addresses must fit in x32 user memory.  Copy the
argument strings, environment, vectors and auxiliary data into the child's
private stack with checked arithmetic; do not expose parent/kernel pointers.
lib/ldso/startup.c and the host/ring-3 probes implement the producer/consumer
contract. Short GEMDOS tails (0..126 bytes) split on spaces/tabs; single and
double quotes group text, are removed and preserve empty arguments. Adjacent
quoted/unquoted pieces concatenate. Backslashes are literal; unmatched quotes
or embedded NULs are invalid. argv[0] is the supplied executable filename.

With tail length 127, an exact ARGV= environment marker supplies a following
NUL-separated list including argv[0]. The marker and all following entries
are omitted from envp. With a short tail that payload is omitted, but unused.
ARGV=NULL: extensions for empty arguments are explicitly unsupported. Missing
extended argv or unterminated environments fail. Bounds are 32768 environment
bytes, 1024 filename bytes including NUL and a 128 KiB construction buffer.
Strings and vectors are copied at load time; later edits of the public
basepage or environment cannot change the staged startup arguments.

Required auxiliary entries:

    AT_PHDR    runtime address of the executable's program-header table
    AT_PHENT   sizeof(Elf32_Phdr), 32
    AT_PHNUM   executable program-header count
    AT_ENTRY   executable's runtime entry, not the interpreter's entry
    AT_BASE    interpreter load bias
    AT_PAGESZ  address-space backend's page size (4096 initially)
    AT_EXECFN  pointer to the copied executable pathname
    AT_PTOS_BASEPAGE (0x5000)  child's own public GEMDOS basepage
    AT_PTOS_BOOTDRIVE (0x5001) kernel boot filesystem drive, A=0 through Z=25
    AT_NULL    terminator

The executable's headers must be in readable user memory; map or copy them
explicitly when no PT_LOAD covers them.  Do not synthesize AT_PHDR by adding
the bias to a file offset unless the segment mapping proves it valid.
Kernel bookkeeping, not a mutable basepage, owns entries and mapping handles.
The kernel clears all general registers except RSP on standard ELF entry;
RDI/RSI do not carry the legacy function-call entry contract. The interpreter
must transfer to AT_ENTRY on the original standard stack, supplying the normal
runtime-linker finalizer callback in RDX. LD.SO supplies dl_runtime_fini;
the minimal ABI probe supplies zero. A normal CRT calls this callback before
Pterm, after application exit processing. Repeated calls are harmless.

Pexec(PE_LOAD/PE_GO/PE_GOTHENFREE) retains kernel-owned executable/interpreter
entries and private mappings through split load/launch. Dynamic images stay
in the child's pending address space; they are never exposed as a patchable
relocatable block in the caller's heap. Discarding a staged basepage destroys
the pending address space; successful launch adopts it. Failures and Pterm
release ownership exactly once. File operations catch disk-error longjmps
before releasing the bounded transient file buffers and interpreter handle.

The initial kernel policy limits the executable to [0x00400000,0x00800000)
(eight PT_LOAD segments maximum for each image), preserving ET_EXEC addresses; a PIE may be
biased into this window. The interpreter is aligned in
[0x0f000000,0x0fff0000), above Mmap and below the ancestors page, avoiding the
supervisor framebuffer window. Each ELF file has an 8 MiB input limit, with
allocation failure returning ENSMEM. Temporary file buffers are freed before
launch. Interpreter bytes count with the main image for Psetlimit core limits.
The inherited stack limit must accommodate the populated initial stack.
The kernel leaves RELRO writable until the interpreter has bound relocations.

Boot tests cover ET_EXEC and PIE, direct/split launch, extended argv,
entry-register clearing,
transfer to the executable, public-field tampering, staged discard, repeated
cleanup, missing/wrong-machine/nested interpreters, duplicate PT_INTERP,
non-executable entry points, truncated files and 64 allocation-failure points.
Allocator, handle/directory-reference and process counters return to baseline.


Memory services and permissions
------------------------------

Mmap, Munmap and Mprot now expose private anonymous mappings and checked
permission changes (doc/mmap.txt). Existing file calls can fill RW pages
before Mprot makes text RX. Malloc/Mxalloc are separate private heap services.
File-backed mappings and read-only physical-page sharing remain to be
implemented. The interpreter uses private anonymous mappings for its DSOs.
For standard PT_INTERP processes, Mprot also permits changes to the main
image/interpreter segment pages recorded in kernel-owned layouts, enabling
RELRO sealing. Stack, basepage and image holes remain ineligible; W^X applies. ELF32
admission is in lib/ldso/image_plan.c; userspace population is in image.c.

The mapping window is [0x01000000, 0x0f000000), outside USER_IMAGE_*, the
ancestors page, heap/stack and guards. Anonymous reservations are atomic and
use full-reservation accounting. Backing pages are zero-filled on first legal
touch; Mprot updates untouched reservations without allocating pages.
MAP_FIXED_NOREPLACE is available; destructive
MAP_FIXED is refused. File-backed object mappings must keep these guarantees.
An ET_EXEC must keep its linked virtual addresses; the legacy static loader's
relocate-to-fit rule cannot be reused for a standard ET_EXEC.

Validate every segment's file extent, filesz <= memsz, address arithmetic,
power-of-two alignment/congruence and page-rounded extent before mapping.
Reject incompatible overlapping segments, reserved/user-limit addresses,
entry points outside executable memory, and W+X page unions.  Keep data/GOT
private and NX.  Apply relocations only to approved private writable pages;
reject DT_TEXTREL and relocations into shared text.  Protect PT_GNU_RELRO
after eager binding.  Flush/synchronize instruction caches through the
architecture backend where necessary.

The image reader validates a complete immutable file without section headers,
allocation or syscalls. Separate DSO, interpreter and executable roles enforce
ET_DYN/no-nested-interpreter and executable-entry constraints. Executables
require a bounded absolute PT_INTERP and mapped program headers; ET_EXEC is
kept at its linked addresses, while PIE/DSO biases must preserve p_align.
The initial format policy is ELF32 EM_X86_64, little endian, zero e_flags,
4096-byte pages and a maximum image span of 224 MiB. Plans are bounded to
128 program headers and 32 load segments. Overlapping memory extents,
conflicting permissions on a shared page, W+X, non-readable loads, executable
stacks, PT_TLS and pTOS-private relocation/import headers are refused.
PT_DYNAMIC must be uniquely file-backed, with matching file/virtual offsets
and equal file/memory sizes. Dynamic lookup and relocation tables must lie
entirely in readable file-backed segments; zero-filled holes/BSS are not
accepted as metadata. The caller must keep the file and plan unchanged.

The population step checks destination capacity, alignment and runtime
address bounds, zeroes the entire private span and copies each segment's
file bytes. It returns a dynamic-object view; failure requires discarding
the mapping. It does not allocate or seal memory. The ring-3 harness supplies
Mmap/Mprot/Munmap, protects gaps with PROT_NONE, seals text RX/data RW-NX and
applies whole-page PT_GNU_RELRO after eager binding (rounding its end down to
avoid protecting writable data beyond RELRO). It currently reserves only
page-aligned images; larger p_align reservation and trusted file I/O remain
runtime-mapper work. No ELF admission path in this userspace core changes
the existing kernel static-ELF or PRG loader.

Read-only code-page sharing needs reference-counted backing pages keyed by
stable file identity, offset and contents/version, with a defined policy for
files modified while mapped.  aspace_map_page() currently borrows a page;
it does not implement such a cache or its lifetime.  Private mappings are
needed first, then shared physical read-only mappings must be proved between
two distinct process address spaces.  Never share writable relocation state.
Process teardown drops references, freeing a backing page exactly once when
the last mapping is gone.  No address-space backend means no shared libraries.


Userspace link engine, search and lifetime
-----------------------------------------

Keep dependency traversal, object identity, dynsym/hash processing and symbol
scope architecture-neutral.  Put startup, relocation width/semantics, PLT
and cache operations in small backend files.  No general symbol lookup or
ELF import service belongs in the kernel.  No kernel address may escape into
a DSO as an ordinary symbol; kernel/CUIS operations remain syscall services.

The initial engine uses SysV DT_HASH, bounded dynsym/strtab reads and
DT_NEEDED traversal.  lib/ldso/dynamic.c provides metadata, per-object lookup and ordered-scope
resolution; lib/ldso/graph.c supplies dependency traversal.  It accepts global/weak definitions of NOTYPE,
OBJECT or FUNC with DEFAULT/PROTECTED visibility, excludes undefined/local/
HIDDEN/INTERNAL symbols, and leaves address outputs untouched on lookup
failure.  SHN_ABS is not biased.  Matched TLS/IFUNC/COMMON symbols fail
explicitly.  Malformed hash chains have bounded traversal.  The current
resource limit is 32 DT_NEEDED entries per object; exceeding it fails.
The caller must supply a stable, entirely readable contiguous image view,
with gaps zero-filled. ELF-header/segment admission is in image_plan.c;
file-backed metadata checks are in image.c. The mapper owns reservations and
permissions.

dl_graph_open builds the executable-first breadth-first scope in DT_NEEDED
order. Its caller owns stable graph storage; a mapper callback acquires
references with stable file identities, and a release callback drops them.
Exact case-sensitive names are cached, file identities deduplicated, and
cycles terminate without repeated loads. Only bare dependency names are
accepted; an available SONAME must equal the request. Path tags and other
unsupported feature flags fail before discovery proceeds. A missing file,
callback failure, invalid name/SONAME or 128-object limit unwinds every
acquired reference, leaving the borrowed root untouched. dl_graph_close is
idempotent and releases references in reverse acquisition order; it executes
no user finalizers. The mapper still has to implement trusted-directory I/O,
stable file identities and file-replacement policy.

The graph also supplies a deterministic initialization schedule: iterative
DFS postorder, visiting children in DT_NEEDED order and skipping edges to
active ancestors. Each object appears once; acyclic dependencies precede
their dependents. Within cycles this traversal rule fixes the order, since
no order can put every member before its dependents. Constructor execution
and finalizer tracking remain a separate implementation step.

The resolver's global scope is the executable, followed by its
dependency closure in deterministic breadth-first DT_NEEDED order.  The
first eligible definition wins, including weak definitions; unresolved weak
references resolve to zero, unresolved strong references are errors.
Protected definitions bind locally inside their defining object; local and
hidden symbols never participate in inter-object lookup.  These binding
rules are implemented by dl_resolve_symbol; the caller supplies the scope.

The relocation planner validates every write before changing the image.
Destinations must lie within caller-approved private writable segment ranges;
relocations into lookup/dynamic/relocation metadata and overlapping writes
are rejected. Failure leaves the image unchanged. Caller-owned scratch space
must be disjoint from all image views. Bounds are 4096 relocation records,
128 scope objects and 32 writable ranges per call. REL, text relocations,
RELR, versioning, symbolic binding and path tags are rejected by this initial
relocation path. Final RELRO permissions and architecture cache synchronization
remain mapper responsibilities.

Start with eager binding for every object, regardless of a lazy-binding flag.
Handle cyclic dependency graphs without repeated loads or unbounded recursion.
Run dependency constructors before their dependents, once per object, with
an explicitly tested deterministic rule for strongly connected components.
Implement DT_PREINIT_ARRAY for the executable and DT_INIT/DT_INIT_ARRAY as
specified by the ABI.  Finalizers run in reverse initialization order on
normal CRT-managed exit; a raw Pterm, crash or forced exit only guarantees
kernel resource cleanup, never execution of user callbacks.

Initial installation layout:

    /GEMSYS/LIB/X32/LD.SO      interpreter named by PT_INTERP
    /GEMSYS/LIB/X32/*.SO       trusted system-library directory

These are paths rooted on the pTOS boot filesystem, translated by the file
interface; they do not presume a Linux root filesystem.  DT_NEEDED and
DT_SONAME are case-sensitive ELF names even where the filesystem folds case;
define identity checks before caching.  Initially allow bare dependency
names from that directory, not relative paths, the current directory,
LD_LIBRARY_PATH or LD_PRELOAD.  RPATH/RUNPATH, $ORIGIN and privileged-launch
policy need a separate specified extension; unsupported path tags must not
be silently advertised as honoured.  The main program and interpreter can
be installed independently of their dependent DSOs.


Initial runtime filesystem profile
----------------------------------

The build produces obj/ldso/ld.so; install it as GEMSYS\LIB\X32\LD.SO
on the kernel boot drive. Dependencies are searched only in that directory,
using AT_PTOS_BOOTDRIVE, never the current drive, directory or environment.
The main executable must supply PT_PHDR so LD.SO can derive its load bias
from AT_PHDR. Interpreter link base is zero; bootstrap accepts only symbol-free
RELATIVE and RELATIVE64 self relocations, validates all writes before applying
any and requires no libc or pre-relocated pointers.

The initial FAT profile accepts strict ASCII 8.3 names (letters, digits, '_',
'-', one dot), with exact case-sensitive DT_SONAME equal to DT_NEEDED. This
rejects alternate-case aliases. Identity is the canonical directory-entry name
within this single directory, backed by the first immutable private snapshot
for that process, rather than an inode number. Hash collisions are rejected.
The dependency graph reuses an exact name without reopening it. FAT has no
hard links; other filesystem/long-name alias policies need a separate extension.
Each file is bounded to 8 MiB, read completely, checked for size changes and
compared against a second complete read before use. An observed change aborts
loading; later replacement does not change the retained snapshot. This is not
an atomic filesystem snapshot or a cross-process object cache.

Private reservations preserve p_align, including padding. Gaps/padding become
PROT_NONE, segment permissions become R/RW/RX, and RELRO becomes R before any
constructor. All dependency mappings are private, including read-only pages.
Executable preinitializers run first; graph DFS postorder initializes each
object once (DT_INIT then INIT_ARRAY). Finalization reverses that order,
FINI_ARRAY in reverse then DT_FINI. Hook arrays and executable targets are
validated before calling user code. Raw Pterm only performs kernel cleanup.
A load failure exits 127 before application entry. Missing libraries and
symbols print the dependency context; bootstrap failures exit directly.


Dynamic CRT and client helper
-----------------------------

obj/ldso/dyncrt.o is a separate standard-ELF startup object; do not combine it
with libcmini's existing crt0/minicrt0, which expect a legacy basepage entry.
It preserves the original stack and passes RDX, the loader's finalizer, to
__ptos_start in libptos.so. The helper calls ordinary
main(int argc, char **argv, char **envp), then exit(main_result).

Install obj/ldso/libptos.so in the same GEMSYS\LIB\X32 directory as LD.SO.
It is an initial client-helper subset, not a complete shared libcmini. It
compiles libcmini's strlen, strcmp, strncmp and getenv directly from the pinned
submodule as PIC; legacy libcmini source/startup/build behavior is unchanged.
The helper supplies environ, ptos_basepage, ptos_write, atexit, exit and _Exit;
lib/ldso/client/ptos.h declares the additional interface. ptos_write returns
Fwrite's byte count or negative GEMDOS error, without errno translation.
Other libcmini APIs, including allocation and stdio, are not supplied here.

Its DT_INIT establishes environ and the basepage from startup vectors before
dependent library constructors. Main-executable PREINIT_ARRAY still runs first;
those callbacks receive argc/argv/envp directly and must not assume the helper
has initialized environ yet. The CRT installs the finalizer on entry, so exit
before CRT entry cannot promise loader finalization. The helper keeps at most 32 pending
atexit callbacks. Normal exit pops them in reverse registration order, then
invokes the loader callback, then Pterm. Callbacks may register another callback while exiting.
A repeated exit during exit processing terminates immediately; _Exit always
bypasses both callback lists. The helper does not implement C++ __cxa_atexit,
thread-local state, exception unwinding or buffered-stream cleanup.

For example, build an application using the subset with an x32 toolchain:

    gcc -mx32 -fPIC -fno-builtin -nostdlib -no-pie \
        -Ilib/ldso/client -Ilib/libcmini/include \
        -Wl,--hash-style=sysv,-z,now,-e,_start \
        -Wl,--dynamic-linker,/GEMSYS/LIB/X32/LD.SO \
        obj/ldso/dyncrt.o app.c -Lobj/ldso -lptos -o app.elf

Use -pie in place of -no-pie for PIE. Compile all additional client DSOs as PIC,
with SysV hashing, a strict 8.3 SONAME, and explicit DT_NEEDED dependencies.
Do not link the static libcmini archive alongside the client helper: duplicate
runtime globals and exit implementations would create inconsistent state.
The boot probe uses a separate libuse.so and independently compiled main,
checks getenv in a dependency constructor, main arguments, 32-handler capacity,
LIFO ordering, registration during exit, return from main, exit from the DSO,
_Exit bypass, and resource
cleanup for both ET_EXEC and PIE. Four lifecycle PASS messages prove that the
normal paths actually reach the final dependency destructor.


Implementation and validation milestones
---------------------------------------

1. This change: x32-only Kconfig gate, ABI/design contract, freestanding
   metadata/SysV lookup core, tests using actual ET_EXEC/PIC ET_DYN output.
2. Private anonymous Mmap/Munmap/Mprot services are implemented, with
   permission faults, limits, isolation, failure cleanup and CI boot tests.
   ELF32 load admission, private image population, RELRO sealing and runtime
   file snapshots are implemented. File backing remains. Split dynamic-image
   ownership is implemented.
3. PT_INTERP mapping, private initial stack/auxv and startup ABI probes are
   implemented for direct and split Pexec. Static ELF/PIE, built-in images
   and m68k PRG paths retain their existing loading conventions.
4. Ordered scope and eager x32 relocations are implemented and tested in
   ring 3. Bounded dependency discovery, BFS scope, cycle scheduling and
   rollback are implemented. Self-relocating LD.SO and its trusted-directory
   file mapper run an ET_EXEC consumer of separate libdyn.so/librt.so files
   under QEMU, including executable symbol interposition.
5. Preinitializers, constructors, finalizers and the RDX callback are tested.
   A separate reusable dynamic CRT and shared client-helper component run
   ET_EXEC/PIE C programs using libcmini string/environment functions.
   Remaining: complete shared libcmini and its broader runtime services.
6. Reference-counted read-only page sharing, two-process isolation, W^X and
   permission-fault probes, plus corrupted ELF, missing libraries/symbols,
   cycles, invalid relocations, rollback and repeated-load leak tests in CI.
7. ARM/m68k backends only after their isolated-address-space prerequisites
   merge.  Verify m68k -fpic/-fPIC and emitted relocations then; PIE is not
   a prerequisite.  FDPIC, non-MMU, TLS and advanced features stay separate.

Run the first milestone's tests with:

    python3 tools/test-elf-shared.py

They require kconfiglib, a native host compiler and an x32-capable gcc/ld;
CC_HOST and X32_CC can override the compiler commands.  Test outputs are
temporary and do not modify the active .config or repository files.

To build the userspace core, select pc-x86_64_defconfig, enable
CONF_WITH_ELF_SHARED in menuconfig, then make CROSS_COMPILE= on Linux.
Disabling the option leaves ordinary static builds unchanged.  An archive
build alone is not proof of runtime behavior. With shared support enabled,
tools/test-mmap-boot.sh also requires the ring-3 relocation PASS marker.
Kernel interpreter startup is covered by a separate PT_INTERP PASS marker.
A separate LD.SO runtime PASS marker covers filesystem dependency loading,
binding, lifecycle ordering, permissions and repeated successful/failed loads.
Physical-page sharing remains unimplemented.
