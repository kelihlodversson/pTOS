Native x32 AES clients and kernel service (#404, #613, #626, #659, #651)
==========================================================

CONF_WITH_X32_AES enables typed ring-3 clients and kernel-owned application
registration, messages, input events, windows, object snapshots and update
ownership. It depends on
the optional x32 VDI support. pc-x86_64-aes_defconfig selects both; the plain
PC and VDI-only configurations leave AES services disabled. The EmuCON-only
baseline is independent of this feature.

This is the shared service boundary for native applications and accessories.
The cooperative AES scheduler and native EmuDesk are selected by
pc-x86_64-accessories_defconfig. pc-x86_64-desktop_defconfig instead loads
EmuDesk as an x32 process using the same typed boundary. The legacy AES implementation stays in the kernel on ARM/m68k.
No raw AESPB, GEMBLK,
AESGLOBAL or kernel code/data pointer becomes part of this x32 interface.
Generic ring-3 GEM trap class 2 remains rejected, including opcodes 200/201.

Application API
----------------

include/aes_client.h is standalone: it needs no generated kernel headers.
These x32 functions return a GEMDOS LONG status, not the legacy WORD return
plus mutable AES global array. Prototypes and buffer directions are explicit:

    LONG aes_appl_init(const char *name, AES_APP_INFO *info);
        Read a terminated name of 1-8 ASCII letters/digits/underscore/dot/
        hyphen, copying only through its terminator; write exactly 12 bytes
        of info (4-byte aligned). Names are case-insensitive and stored in
        uppercase. A different live process cannot register the same name.
        Repeating init for the same process/name returns its current info;
        attempting to rename a live registration returns EACCDN.

    LONG aes_appl_exit(void);
        Release this process's registration, incoming messages and both
        update locks, including all recursive acquisitions.

    LONG aes_appl_find(const char *name);
        Read a name with the same contract as init. Return its live app id,
        or ESRCH. The caller must itself be registered.

    LONG aes_appl_write(WORD recipient, const AES_MESSAGE *message);
        Copy exactly 16 bytes (2-byte aligned) into the recipient's bounded
        kernel queue. Valid ids are 1-32767. The sender field supplied by
        the caller is ignored and replaced with its authoritative app id.
        Type must be nonnegative and reserved must be zero. The five data
        WORDs are opaque values; the kernel never follows them as pointers.
        There is no extended-length message or retained user buffer.

    LONG aes_appl_read(AES_MESSAGE *message);
        Write exactly 16 bytes (2-byte aligned), consuming the oldest
        message in this process's queue only after a successful copy.
        Return EAGAIN if empty. There is no foreign receiver/owner argument.

    LONG aes_evnt_poll(UWORD mask, AES_EVENT *event);
        mask must be AES_EVENT_MESSAGE (0x0010). Write exactly 20 bytes
        (2-byte aligned). Return 0 and an all-zero event if empty; otherwise
        return 0x0010 and the oldest message with events set to 0x0010.
        Unsupported masks are EINVAL. This original message-only API and its
        20-byte result remain unchanged; combined input uses aes_evnt_multi.

    LONG aes_wind_update(WORD code);
        0/1 release/acquire the desktop-update lock; 2/3 release/acquire the
        mouse-control lock. Both are recursively owned by the process's
        registration, with a maximum depth of 32767. A conflicting acquire
        returns EAGAIN; release by a nonowner returns EACCDN. There is no
        silent transfer or unbounded wait inside the service. This provides
        kernel-owned cross-client coordination. Typed window calls respect
        both tokens and also use the native manager's synchronization during
        each call. These tokens coordinate typed clients; they do not suspend
        legacy kernel dialogs/menus across arbitrary user waits.

The library uses ordinary x32 SysV C calls; the program-entry contract in
process-entry.txt (#387) is unchanged. No user context/state argument is
needed because each syscall identifies the current KPROC.

    LONG aes_evnt_wait(UWORD mask, AES_EVENT *event);
        Loaded accessories with AES_FEATURE_WAIT may wait cooperatively for
        AES_EVENT_MESSAGE. Validate/back the 20-byte destination before
        blocking, then validate copyout again on resume in the caller's
        address space. Return AES_EVENT_MESSAGE on delivery. Ordinary Pexec
        clients and nested children return EACCDN: they have no accessory
        coroutine. This call cannot run inside a user callback.

    LONG aes_appl_yield(void);
        Give other AES tasks a turn and resume this accessory's syscall.
        Registration is required; ordinary Pexec clients, nested children
        and user callbacks return EACCDN.

    LONG aes_evnt_multi(const AES_EVENT_REQUEST *request, AES_INPUT_EVENT *event);
        Associated accessories with AES_FEATURE_INPUT combine keyboard (0x01),
        button (0x02), rectangle 1 (0x04), rectangle 2 (0x08), message (0x10)
        and timer (0x20) events. Return the completed mask, or 0 for an empty
        poll. All result fields are initialized; message/key/click values
        are zero unless their event completed.

        mask must contain at least one supported event; reserved must be 0.
        flags is 0 to block or AES_EVENT_POLL for a nonblocking check. A zero
        timer is immediately ready; positive milliseconds are rounded up to
        AES ticks, with a maximum of 0x7fffffff. A poll ignores positive
        timers even if a tick passes during the call; it never starts a
        future timer. Button waits accept 1-255 clicks, a nonzero mask of the
        two mouse buttons (1-3) and a state contained in that mask. The click
        count caps the returned count, following native AES rules. Each selected
        rectangle has outside=0 (enter) or 1 (leave), positive width/height,
        and right/bottom coordinates at most 32767.

        Keyboard input comes from the task's own AES queue. Mouse conditions
        and delivery follow AES focus ownership; a background task does not
        satisfy its mouse wait using the focused task's current state. This
        call does not grant focus. Opening/topping a window uses native AES
        focus ownership.
        Completed button waits return the completing event's coordinates and
        button state, even if later transitions or another task's native
        event return overwrite the shared mouse history. A queued press/release
        pair preserves the press's own coordinates even after motion while
        held, and its click count is capped by the request. Other mouse
        coordinates/buttons and modifiers use the native AES snapshot.
        Unfocused polls do not consume the saved transition.
        The key field contains the scan code in its high byte and character
        in its low byte. Modifiers use the existing vq_key_s bit assignments.

        Copy the complete, 4-byte-aligned request before registering events.
        Validate the 2-byte-aligned output before consuming input or blocking,
        and check copyout again on resume. Request/output overlap is safe.
        Only trusted request copies/native event records survive suspension.
        Losing waits are cancelled before return. A typed message is dequeued
        only after successful copyout. If output becomes invalid during the
        wait, return EIMBA; native input may already have been collected, while
        the typed message stays queued. Programs launched by the native AES
        shell in graphics mode receive a scoped association with AES task
        zero. Other Pexec clients, including nested children, return EACCDN;
        they cannot borrow the suspended parent's event/window ownership. User callbacks cannot call it. Exit/restart cancels all waits.
        Revoking registration from a callback wakes every blocking input
        wait, including waits without messages; they cancel their event
        registrations and return EACCDN, including when the callback has
        already registered the process again before that wait resumes.

Window API (#626)
-----------------

Only associated clients advertising AES_FEATURE_WINDOW can use these calls.
Ordinary Pexec clients, nested children and user callbacks are refused.
All window requests use copied scalar records; no native wind_get/set field
selector, object tree or pointer-bearing parameter array crosses the boundary.

    LONG aes_wind_create(UWORD kind, const GRECT *full);
        Allocate a native window; return its positive handle. kind is the
        low 12 native AES gadget bits, named AES_WINDOW_* in aes_client.h.
        The full rectangle must leave a positive work area. Handles can be
        reused after deletion; callers must discard deleted handles.
        A freed native handle stays reserved while its old service call is
        unwinding; creation returns EAGAIN until that bookkeeping is released.

    LONG aes_wind_open(WORD handle, const GRECT *rectangle);
    LONG aes_wind_close(WORD handle);
    LONG aes_wind_delete(WORD handle);
        Open a created window, close an open one, or delete either state.
        Opening/topping follows native stacking and focus rules. Repeated
        open/close in the wrong state returns EINVAL. Deleting an open window
        closes it first. Desktop handle 0 cannot be mutated.
        A native desktop/application reset can invalidate accessory handles;
        clients recreate windows when reopening after that reset.

    LONG aes_wind_get(WORD handle, AES_WINDOW_INFO *info);
    LONG aes_wind_set_rect(WORD handle, const GRECT *rectangle);
        Query only the caller's window or the public desktop geometry (0).
        Change current border geometry in either open or closed state.
        Dimensions must be positive and leave positive work dimensions.
        Coordinates and computed border/work rectangles must fit signed WORD
        arithmetic; width/height and right/bottom leave two pixels for the
        native shadow (maximum 32765), and x/y are at least -32765.
        Rendering/moves also require the combined screen, requested bounds
        and allocated windows' old current bounds to span at most 32767 in
        each axis, reserving four pixels for the two native shadow additions
        during resizing. Thus rendered dimensions are at most 32763, with
        tighter limits when distant bounds widen the union. Reject wider
        unions with EINVAL before native arithmetic or any geometry change.
        MOVER windows also require the native title-drag constraint width
        (screen width + border width - box width - 6, minus the 3D adjustment
        where enabled) to fit a positive signed WORD. This applies with or
        without a NAME gadget; non-mover windows retain the rendering bound.

    LONG aes_wind_set_text(WORD handle, UWORD field, const char *text);
        field is AES_WINDOW_NAME or AES_WINDOW_INFO_LINE. Copy a terminated
        string of at most AES_WINDOW_TEXT_MAX (127) bytes. Empty text is
        valid. The caller may immediately change or free its source. Fixed
        kernel-owned window slots retain both strings until window deletion;
        no user pointer reaches native rendering or survives the syscall.
        Text for an absent title/info gadget is retained without redrawing a
        missing native object.

    LONG aes_wind_top(WORD handle);
    LONG aes_wind_slider(WORD handle, UWORD field, WORD value);
        Top an open owned window. Slider fields are AES_WINDOW_HSLIDE,
        VSLIDE, HSLSIZ or VSLSIZ; values are 0..1000, with -1 also accepted
        for the native default size. Native AES normalizes zero to one.
        Position and size updates require the corresponding HSLIDE/VSLIDE
        gadget, even on closed windows; otherwise EINVAL leaves state intact.

    LONG aes_wind_rect(WORD handle, UWORD next, GRECT *rectangle);
        next=0 starts the owned window's visible-work-rectangle walk;
        next=1 advances it. Zero width/height marks the end. The output is
        copied successfully before advancing or restarting the cursor. A
        failed copyout preserves the cursor for retry. No cleanup can dispatch
        between selection, copyout and cursor commit, or after commit before
        returning success. The completed syscall defers optional return-work
        hooks until a later syscall or user IRQ boundary; stack, watchdog and
        fatal-owner validation still run. This policy belongs to the current
        trap invocation, including across nested callbacks and AES dispatch.
        Mutating that window restarts its cursor.
        Each call rescans the current native list by ordinal, retaining no
        native rectangle-node pointer across calls. Handle zero also supports
        FIRST/NEXT enumeration of the desktop's visible areas, with a separate
        cursor per associated AES task. The native desktop has no ISOPEN flag;
        its rectangle list remains enumerable. Clients clip VDI to these
        rectangles; window ownership does not replace workstation clipping.

        The x86-64 native rectangle pool reserves the worst case for all
        handles and transient splits: NUM_WIN*(2*NUM_WIN-1)^2+4 nodes.
        A list is partitioned by at most NUM_WIN-1 other rectangles; their
        edges form at most 2*NUM_WIN-1 bands on each axis. Include cached
        lists of closed windows and four nodes allocated during a split.
        This costs about 28 KiB with eight handles or 240 KiB with sixteen,
        and requires no allocation during window changes or cleanup.

    LONG aes_wind_calc(UWORD mode, UWORD kind, const GRECT *input, GRECT *output);
    LONG aes_wind_find(WORD x, WORD y);
        Calculate border from work (AES_WINDOW_BORDER=0) or work from border
        (AES_WINDOW_WORK=1), rejecting arithmetic overflow or empty results.
        Input/output overlap is supported. Find returns the global handle
        under the point, 0 for desktop, or -1 for no hit. It grants no access
        to a foreign window's private state. Get also reports the global top
        handle, while owner and all other fields remain private.

These calls return E_OK except create/find. Invalid/deleted handles return
EIHNDL; foreign and desktop mutation attempts return EACCDN. Both coordination
tokens and the native manager's lock can cause EAGAIN. Native fields that
expose pointers or global color/desktop mutations are not part of this API.
Requests recheck cancellation, the native lock and both typed coordination
tokens after cleanup can dispatch, before accessing the requested native
handle. Cleanup also rechecks the native lock after each yielding close and
before visiting another window. If deletion closes a window but loses the
lock, EAGAIN leaves that closed handle owned and available for retry.
Unregister, normal exit/fault and restart close/delete the client's windows,
clear its retained text and discard pending redraws. A callback may revoke
and renew registration while a window call is suspended: that call returns
EACCDN and never writes its old result into the renewed registration. Cleanup
inside user callbacks only retires resources; native deletion runs after the
callback returns, through a return-work hook or the completing window call.
Normal appl_exit also completes native deletion directly outside callbacks,
including builds without callback support. Process termination drops its AES
association before native cleanup can yield and reuse the old basepage.
Each busy reservation records the AES coroutine executing that continuation.
Owner unregister/exit releases only reservations belonging to the executor
whose calls have unwound; cleanup suspended on another task remains pinned.
Abandoned borrowed reservations are released when their executor finishes.
Session drain releases every remaining reservation only after all accessory
continuations have been cancelled.
Deletion closes first, then rechecks slot/native ownership after the close
can yield, before deleting the still-owned closed handle. Explicit deletion
and deferred cleanup share this path. Closed-window geometry remains queryable
until deletion; deletion normalizes native dimensions before returning its
rectangle nodes, so invisible windows cannot obscure other windows or leak
the rectangle pool. A native reset also retires stale, non-busy records even
when a later create chooses a different handle. Restart marks cancelled tasks
dead before clearing their contexts, so cleanup messages cannot fall back to
their unconsumed legacy queues. Other yielding calls likewise recheck ownership
and native validity before changing bookkeeping or copying results.

Native WM_REDRAW notifications are clipped to the screen before coalescing
to one bounding rectangle per owned window. Empty intersections are dropped;
retained redraws therefore cannot overflow WORD dimensions across window moves.
They move into the client's FIFO when space is available, after
already queued messages. Window drawing never waits for its own full queue.
Deleting/unregistering discards pending redraws; already queued messages may
still refer to deleted handles, as with native AES. Other control messages
retain their FIFO and backpressure behavior.
Native arrow/scrollbar actions deferred while the associated task is runnable
also enter this FIFO with sender 0. Read, poll, wait and combined waits collect
them; a full FIFO preserves the deferred action until enqueue succeeds.

Unless documented otherwise, successful calls return E_OK. Calls other
than init require registration. Disabled service classes return EINVFN. Malformed
scalars or names return EINVAL, inaccessible/misaligned buffers EIMBA,
registration/ownership violations EACCDN, absent recipients/names ESRCH,
full/empty queues or contended locks EAGAIN, exhausted memory ENSMEM and
recursive lock overflow ERANGE. Failed buffer validation does not consume
a message or create a registration. An actual lazy-memory fault terminates
only the calling process and invokes the same teardown path.

Representations (native byte order)
------------------------------------

AES_APP_INFO (12 bytes, alignment 4): UWORD version at 0 (0x0100: this client
ABI's version), WORD id at 2, UWORD queue_capacity at 4 (8), UWORD reserved
at 6 (zero), ULONG features at 8 (MESSAGE=1, UPDATE=2, WAIT=4, INPUT=8, WINDOW=16).
WAIT, INPUT and WINDOW are advertised only for associated AES tasks. It is a value
result, not writable shared service state. Editing it cannot change ownership.

AES_MESSAGE (16 bytes, alignment 2): WORD type at 0, sender at 2, reserved
at 4 (zero), data[5] at 6. Messages are application data, not authenticated
kernel-generated window/input notifications when sender is positive. The
recipient can identify which registered process sent one from the supplied
sender field. Native window notifications have sender=0, which user sends
cannot forge; their data[0] is the native window handle. WM_REDRAW (20) has
x/y/width/height in data[1..4]; WM_CLOSED (22) requests a close and leaves the
window open until its owner calls aes_wind_close/delete.

AES_EVENT (20 bytes, alignment 2): UWORD events at 0, reserved at 2 (zero),
AES_MESSAGE message at 4. Output records and unused fields are initialized;
no kernel stack or address is copied into them.

AES_EVENT_RECT (10 bytes, alignment 2): WORD outside at 0 and GRECT at 2.
AES_EVENT_REQUEST (36 bytes, alignment 4): UWORD mask/flags at 0/2,
clicks/button_mask/button_state/reserved at 4/6/8/10, mouse1/mouse2 rectangles
at 12/22, and ULONG timer_ms at 32. It contains no pointers.
AES_INPUT_EVENT (32 bytes, alignment 2): UWORD events/reserved at 0/2,
WORD mouse_x/mouse_y at 4/6, UWORD buttons/modifiers/key/clicks at 8/10/12/14,
and AES_MESSAGE at 16. The existing AES_EVENT remains 20 bytes.

AES_WINDOW_INFO (52 bytes, alignment 2): WORD handle/owner at 0/2,
UWORD kind/flags at 4/6, GRECT full/work/current/previous at 8/16/24/32,
and WORD hslide/vslide/hslsiz/vslsiz/top/reserved at 40/42/44/46/48/50.
The owner is the registration id, flags contains AES_WINDOW_OPEN, top is the
global top handle (0 for desktop), and reserved is zero. It contains no
strings, pointers, native AES task ids or mutable server state.

GRECT remains the existing four WORDs x/y/width/height (8 bytes, alignment 2),
now defined in grect.h so rectangle helpers need no kernel configuration.
Static assertions check the public layouts in the x32 and LP64 views.

Caller-local helpers
---------------------

The library builds util/rectfunc.c itself, the implementation already shared
by AES and the desktop; it does not duplicate the geometry algorithms:

    BOOL inside(WORD x, WORD y, const GRECT *rect);
    WORD rc_equal(const GRECT *a, const GRECT *b);
    WORD rc_intersect(const GRECT *source, GRECT *destination);
    void rc_union(const GRECT *source, GRECT *destination);
    void rc_constrain(const GRECT *bounds, GRECT *rectangle);

All rectangle accesses execute in ring 3. Existing WORD geometry semantics
are retained. Invalid local pointers can fault the caller, never authorize
kernel access. None of these helpers registers an application, touches Line-A
or draws. Object-tree helpers and resource manipulation are candidates for
similar extraction only after their dependencies and native tree ownership
are specified; USERDEF execution also needs #432.

Supervisor convention and ownership
-----------------------------------

RAX = (0x101ULL << 32) | function, with a/b/c/d in RDI/RSI/RDX/R10. These
services accept actual ring-3 callers with private process address spaces.
All unused arguments must be zero. Scalars are checked at full 64-bit width
before narrowing, and every user span belongs to the current process.

    function   a                b                 c/d
       0       name input*      AES_APP_INFO out* unused
       1       unused           unused            unused
       2       name input*      unused            unused
       3       recipient id     AES_MESSAGE in*   unused
       4       AES_MESSAGE out* unused            unused
       5       event mask       AES_EVENT out*    unused
       6       update code      unused            unused
       7       message mask     AES_EVENT out*    unused
       8       unused           unused            unused
       9       request input*   input event out*  unused
      10       window request*  result or unused  unused

The private window request is 24 bytes (alignment 4): UWORD operation at 0,
WORD handle at 2, UWORD selector/kind at 4/6, WORD value at 8, zero reserved
at 10, ULONG x32 data address at 12, and GRECT at 16. FIND uses rectangle.x/y;
all other geometry and text are copied from data. Operations 1..12 are
CREATE, OPEN, CLOSE, DELETE, GET, RECT, TEXT, TOP, SLIDER, VISIBLE, CALC, FIND.
Only GET writes the 52-byte info; VISIBLE/CALC write an 8-byte rectangle;
other output arguments must be zero. Every unused request field is zero.
The original exports 0..14 remain unchanged; the 12 window exports append
at 15..26 in the order declared in aes_client_exports.h.

The kernel attaches AES_CLIENT_STATE to KPROC, not the public basepage or a
caller-supplied context pointer. The id comes from the kernel process record;
ids may be reused after process exit and are not ownership capabilities.
Registration records and eight-message FIFO queues come from the supervisor
heap. A bounded input copy is complete before a message is enqueued. No user
pointer survives a call, including one pointing to the caller's stack.

appl_exit and normal/fault process teardown unlink the registration, free the
queue and release both locks before destroying the process record/address
space. Queued messages contain copied scalar data and sender ids, not links
to another process record; already-delivered messages remain valid after the
sender exits. No process can dequeue, close, or release another's state by
supplying an id. Coordination currently follows the single-CPU synchronous
process model; contended window synchronization returns EAGAIN. Native
window operations may yield when releasing synchronization to a waiter.
Their trusted input copies survive suspension and output is revalidated.
Registration revocation cancels the call even if a callback immediately
registers again; in-flight window records retire only after the call unwinds.

Imports and SDK
----------------

    make pc-x86_64-aes_defconfig
    make
    make x32-aes x32-vdi

obj/x32/libptos-aes.a supports static linking. libptos-aes.so.1 is a link-time
stub for .ptos.imports consumers, not a filesystem DSO to install or execute.
It exports 31 functions, including five rectangle helpers and three object/
dialog/resource functions described in aes-objects-x32.txt, and aes_shell.
The single ordered list in aes_client_exports.h is used by the stub, client
image, packer and loader. The namespace is aes:, ABI major 1/minor 0.

An application may link both libptos-aes.so.1 and libptos-vdi.so.1. The packer
accepts these explicit dependencies once each and maps each known symbol to
its namespace. Unknown libraries, duplicate dependencies, unknown functions,
data symbols and legacy gemdos imports remain refused. Both namespaces use
the existing PT_PTOS_IMPORTS format without changing its version. Pexec
validates every import before binding; unavailable/unknown namespace, name,
version, kind or malformed binding yields EPLFMT and releases the image.

Example (supply the application's process-entry startup object):

    $CC -mx32 -ffreestanding -fPIE -nostdlib -Wl,-pie,--no-dynamic-linker \
        -Wl,-m,elf32_x86_64,--build-id=none,-e,_start \
        -Wl,-z,max-page-size=0x1000,-z,noseparate-code \
        -Iinclude app.c start.o -Lobj/x32 \
        -l:libptos-aes.so.1 -l:libptos-vdi.so.1 -o app.elf
    ./ptos-elf-pack --strip-shdr app.elf APP.TOS

The optional kernel embeds the client image at a private read-only executable
window at 0x0ffd0000 (maximum 64 KiB, before the separate VDI/ancestors windows).
The linker rejects mutable global state. Its validated export header supplies
all entry addresses; applications contain no address constants or runtime
symbol lookup. Mapping happens before an irreversible PE_LOAD image transfer
and the process address space owns/frees every mapped page. Neither namespace
exports a raw LP64 kernel address.

desk/gembind.c stays on its existing ARM/m68k trap ABI. The typed x32 library
provides one reusable binding layer for future standalone EmuDesk and gemlib
ports, coordinated with #123. It does not add another copy of desk's GEMBLK
marshaling or pretend that the native API is the classic AESPB ABI.

---------------------------

Tests
------

make aes-contract-test checks native layouts, the shared local geometry and
the complete legacy-operation inventory. make x32-aes-import-test produces
AESIMP.TOS/AESREL.TOS and seven malformed import fixtures in obj/x32/. The
host checks a real mixed AES/VDI packed application and rejects duplicate
libraries or unknown functions. Copy obj/x32/AES*.TOS to the PC boot disk,
plus obj/x32/x32probe.elf as X32AES.TOS and X32VDI.TOS, alongside the usual
VDI and process-loader fixtures.

The optional AES boot test uses two live ring-3 registrations, real queue
copies and event polling, authoritative sender ids, recursive/foreign update
ownership, normal exit without appl_exit, explicit exit and a fault while
owning locks. Allocator snapshots must return to their starting state. It
also checks full/FIFO/empty queues, rejected read-only outputs without losing
a message, page-boundary strings/outputs, malformed scalar/pointer/name
arguments and unchanged class-2
rejection. Imported applications repeat the checks using both namespaces,
including relocation and a write attempt against the read-only AES client.

The plain PC and VDI-only boots verify local helpers work and that AES
services/imports are refused. Dedicated CI boots supply the fixtures and
require "x86-64 AES client: PASS" and "x86-64 AES imports: PASS" for all three
PC configurations, plus the aggregate memtest PASS and EmuCON launch. A boot
disk without AESIMP.TOS skips the disk import test; the baseline/regression
path does not require that fixture.

External x32 desktop and shell coordination (#651)
-------------------------------------------------

pc-x86_64-desktop_defconfig enables CONF_EXTERNAL_DESK and builds emudesk.prg
as a freestanding, statically linked x32 ELF image. It has the documented
ENTRY_PROGRAM basepage/register/stack contract and keeps the process-entry
stack. The native AES shell loads EMUDESK.PRG from the boot drive. Missing
EmuDesk falls back to EMUCON.TOS. The EmuCON-only baseline stays unchanged.

A trusted native dos_exec() in graphics mode grants the next loaded process
an association with AES task zero. The grant is consumed once and checked
against the KPROC parent. Nested user Pexec children get independent process
records but cannot inherit the suspended parent's native event/window/tree
ownership. Returning from the graphical process detaches the association,
retires its retained objects/windows and performs accessory close notification
even after a fault or typed appl_exit(). Loaded accessories retain their own
AES tasks and receive a Desk-menu entry using their filename. Menu labels
have session-long kernel storage, including after accessory exit. Accessories
discard/reset window handles at AC_CLOSE; the native shell resets windows at
application boundaries. Window operations can return EAGAIN during this
handoff and clients must retry or discard a handle invalidated by the reset.

The desktop's classic function wrappers are a local adapter, not a legacy
AESPB syscall ABI. desk/x32/ serializes only connected source objects into
bounded immutable snapshots; indirect specs are resolved locally and internal
alignment flags are removed. Menus and the desktop keep owned snapshots;
dialogs copy back edited text/state. USERDEF receives values on the owner's
user stack and reconstructs a caller-local PARMBLK before invoking dr_code.
File enumeration, file selection, resource-file materialization, alert trees,
box outlines and geometry conversion stay in the desktop process. Mono bitmap
standard/device formats are identical, so read-only built-in mono data does
not need an in-place transform. Colour resource palette planes remain in
standard format until the kernel constructs its owned snapshot.

include/aes_shell.h adds aes_shell(const AES_SHELL_REQUEST *) at service
function 12. Its 28-byte, 4-byte-aligned request has operation/value/extra,
a zero reserved WORD, two x32 addresses, a byte count and a GRECT. Every
operation validates unused fields as zero. There is no retained user pointer.
This scheduling/display boundary is forbidden from user callbacks.

  WRITE: foreground only. value is the existing SHW_* mode, extra is isgem
    and bytes is isover (0..2). EXEC copies a terminated command of at most
    128 bytes and exactly 128 tail bytes. TOS filename (<13 bytes) and directory
    (<114 bytes) component limits protect native path concatenation. The
    native command-tail buffer lives in kernel storage, not the bootstrap
    basepage, which is unmapped under a ring-3 caller's address space.
  GET/PUT: foreground only; copy at most 4192 saved-desktop bytes through data.
  WDEF: foreground only; copy a startup filename and directory through data/
    second, enforcing their native 13/114-byte capacities including NUL.
  DCLICK: associated task; rate 0..4, query/set extra 0/1; return the rate.
  KEY: associated task; return the shifted character for scancode 0..127.
    No keyboard-table address is exposed.
  DAMAGE: associated task; redraw the positive bounded GRECT after a dialog.
    Both coordinates lie in -10000..10000 and dimensions in 1..10000.
  RESET: foreground only; notify accessories, wait for their close handshake
    and reset the native window manager. The desktop uses it before typed
    appl_exit(), including an in-process restart after reading an INF file.

All return LONG status (WRITE and DCLICK retain their native successful
result). Invalid alignment/mapping is EIMBA, malformed/unused fields EINVAL,
excess byte/component sizes ERANGE, and missing association/foreground
authority EACCDN. Native synchronization can return EAGAIN. Shell copies are
bounded and completed before their state changes; user callbacks cannot
suspend a shell continuation. Physical display access still uses the typed
VDI library and its process-owned workstation.

Runtime coverage
----------------

    make pc-x86_64-desktop-tests_defconfig
    make -j8
    make x32-desktop-test
    python3 tests/x32_desktop/run.py

Supply --ovmf-code/--ovmf-vars if they are not at the standard Linux/macOS
paths. --output selects the log/screenshot directory. The runner stages a
fresh FAT ESP and writable firmware variables, drives actual PS/2 input,
rejects any FAIL/fault/panic/reset and verifies:

  - CPL3 and the process-entry ABI for EmuDesk, an accessory and a graphical app;
  - real menu selection, About, disk-window icon/text drawing and USERDEF;
  - held-button selection/drag wait compatibility (classic mask 0xff -> 3);
  - a graphical app launched from EmuDesk, bad pointer/size/command rejection,
    saved-shell-buffer copies, private nested-child ownership and accessory IPC;
  - file-selector cancellation, filename editing, loading TYPED.INF and restart;
  - graphical/console transitions and a fresh ring-3 desktop after EmuCON exits;
  - a missing external desktop falling back to the EmuCON prompt.

The pc-x86_64-desktop-tests-340 configuration repeats this under AES 3.4,

tests/emudesk.inf's #Z autorun line, just like an installed desktop. Poweroff,
