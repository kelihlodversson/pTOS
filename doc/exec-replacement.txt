Pexec(200): owned private image staging and remaining commit contract (#970)
=========================================================================

Follow-up: doc/exec-handoff.txt implements the default-off SAME-ROOT native
scheduler/launcher NORETURN transport prerequisite on the accepted epic that
includes #977. It conveys no image-bundle right and publishes no exec event.
The staging transaction below is preserved. Public mode200 remains EINVFN.

Base: accepted epic ec1f04c65d4f7702bd16b9e655f99cceb0a0f91f.
Consumer: Phase6 #895; architecture/scheduler owner #713; loader migration #894.
This increment is default-off CONF_WITH_EXEC_REPLACEMENT_TEST. No shipped preset
selects it. Public Pexec(200) still returns EINVFN. No committed-exec generation
producer is installed. This is a concrete preparation prerequisite, not completed
replacement or Pvfork exec acceptance.

Binding Phase6 policy
---------------------
Both Pfork and MMU Pvfork use the same NEW_PROCESS/PRIVATE_VM COW constructor.
Pvfork additionally suspends its calling parent THREAD until that exact child
finally completes or successfully commits same-PROCESS executable replacement.
The child already has an independent KASPACE and private user stack. There is no
shared parent/child VM attachment or shared writable parent stack to detach.
Ordinary private child writes are invisible to the parent, a deliberate
FreeMiNT Pvfork compatibility deviation. Explicit shared mappings retain their
own mapping policy. Legacy non-MMU execution remains outside this increment.

Implemented ownership
---------------------
exec_replace.c owns an opaque KPROC_EXEC_REPLACEMENT receipt. Preparation
requires the exact current, sole, executing managed THREAD and live started
PROCESS, the current execution number, and a distinct unpublished selected
KASPACE with a distinct backend root. Initial admission rejects source root
peers, other PROCESS use of the selected root, loader loans, pending launch or
mapping mutation, final/group cancellation, nested execution and existing
replacement preparation. The monotonic preparation ticket is an admission
identity, not a committed-exec generation or a public completion.

Root admission inspects existing canonical initial-THREAD and prepared/committed
mapping memberships as well as active/pending root fields. A distinct unstarted
PROCESS may already own a selected or source root through those associations
before either root field is adopted. Both cases reject before admission and
remain rejected by revalidation. No second mapping registry or root-reference
count heuristic substitutes for that ownership check. The fresh loader image
exception cannot contain a competing THREAD/mapping preparation.

The receipt retains the exact source KPROC and both roots. Its existing
KSCHED_CLEANUP_SCOPE defers cancellation delivery while preserving cancellation
visibility; validation rejects a newly cancelled operation. It closes ordinary
THREAD attachment and launch-selection admission on that PROCESS until abort.
It holds no scheduler lock, IRQ exclusion or KASPACE mutation guard across a
yield, allocation, filesystem call or destructor. Final/group cancellation is
not blocked from being requested. The receipt cannot leave its owning execution
or disk-error boundary and cannot survive a return to userspace.

The loader's private proc_exec_replacement_stage consumer reuses exec_common,
kpgmhdrld/kpgmld and the ordinary ELF loader. It uses PE_LOAD internally with a
receipt parameter unavailable to public mode3. ELF loading selects the supplied
private pending KASPACE instead of a caller-heap load. An existing unstarted
loader KPROC/PD is only an owned image container: it receives no THREAD, scheduler
slot, observer, runnable publication, inherited descriptor/CWD references or
mode3 launch grant. The original source KPROC/PID/PD, its descriptor ownership,
THREAD and active root remain unchanged. Nothing moves the staged PROCESS's
resource table into the source. Legacy PRG staging is rejected before allocation
because its moved-TPA ownership requires its own bundle contract.

The receipt retains and owns disposal of the unstarted loader container.
Ordinary loader failure may retire it first; abort then releases the retained
identity idempotently. Abort disposes the staged image, releases its root holds,
drops admission and releases the source before ending cancellation protection.
The caller still owns its selected root and releases it normally after abort.
A disk error uses the existing FS_ERROR_SCOPE / DISK_CALL cleanup path. Successful
staging means a checked pending ELF layout and private root, not a complete new
initial user/kernel execution context or an execution transition.

Kernel-only interface
---------------------
kproc_exec_replacement_prepare(source, thread, selected, &empty_receipt)
  Acquire reversible admission and references; output only after all prefixes.
kproc_exec_replacement_validate(receipt)
  Revalidate exact PROCESS number, TID, execution, source/selected roots and
  current cancellation; selected pending ownership may belong only to the
  receipt's exact unstarted image container.
proc_exec_replacement_stage(receipt, trusted_path, trusted_tail, trusted_env)
  Load a real ELF into selected root using existing loader and checked errors.
kproc_exec_replacement_image_ready(receipt)
  Validate private completed pending image without preparing execution.
kproc_exec_replacement_abort(&receipt)
  Unique owning execution consumes all staged obligations; NULL is idempotent.

No prepare, validation, staging-ready or abort step is an exec event. Public
Pexec(200), its no-return success path and final same-PROCESS handoff are absent.

Verified controls
-----------------
Host tools/test-exec-replacement.py compiles production kproc.c/kaspace.c and
exec_replace.c with modeled CPU/scheduler/already-live THREAD/MMU providers. It
checks wrong identity/root/execution/TID, competing preparation, source sharing,
selected-root use, cancellation, allocation failure and all four retained-owner
failure prefixes. Original PROCESS, sole THREAD, completion, roots and exact
allocation/reference counts remain unchanged with both roots still alive.
Normal, ASan/UBSan/leak and fortified host modes are distinct from native proof.
The host image-disposal provider fails if called: the model does not claim to
execute the loader or successful replacement.

The host tool also executes the actual native runner marker guard with generated
Kconfig headers for all staging/Pclone on/off combinations and present/missing
evidence. Staging=y/Pclone=n is valid and has no Pclone marker producer, so the
runner must not require its marker. Staging=y/Pclone=y still rejects missing
native execution evidence. This changes neither feature dependencies nor public
mode200 availability.

Native private Pclone test transport uses 0xc9700000|selector with NULL request:
  0       prepare, cooperative yield, exact-owner revalidation and abort;
  1..4    fail each source/old-root/new-root/final-validation prefix, ENSMEM;
  0x100   stage existing PIEPROBE.TOS in selected private root and abort;
  0x101   missing file, EFILNF, old execution remains runnable;
  0x102   truncated LOADFAIL.TOS after allocation, error and full cleanup;
  0x103   selected root already bound to foreign unstarted initial THREAD;
  0x104   selected root already owned by foreign prepared mapping membership;
  0x105   source root bound to foreign unstarted THREAD, conservative EACCDN.
The two selected-root controls originally returned E_OK on44a3b22aa with both
foreign active/pending fields NULL. Production-model controls use actual
kproc_thread_attach_space / kproc_clone_prepare_mapping_owners, perform complete
cleanup, then assert EACCDN with both roots still alive and baseline refs restored.
Both source-root sharing variants are also covered by the hosted owner tests.
The managed user test repeats these paths eight times, checks stable source PID
and all45 mapping-lifetime counters after each cycle, and explicitly verifies
public mode200 still returns EINVFN. The accepted source root remains alive;
normal disposal of the temporary staging root does not replace any counter.
The transport exists only in the test configuration; it is not a public API.

BLOCKER970 / issue970: same-PROCESS execution commit
--------------------------------------------------
Affected capability: full Pvfork exec release. Pfork is independent. Exit-only
COW Pvfork testing may proceed without pretending this blocker is resolved.

Production path:
  proc.c exec_common -> kproc_load_begin/load_commit ->
  kproc_prepare_user_thread -> thread_startup -> architecture launcher.
Existing launch metadata and ownership are fields of KPROC, not a separately
owned replacement image bundle. kproc_prepare_user_thread adopts the pending
root and mutates those fields of an unstarted PROCESS. Existing active THREAD
root association cannot change through this constructor.

Smallest reproducible controls:
  python3 tools/test-exec-replacement.py (requires kconfiglib):
  before any replacement ticket, a fresh THREAD
  passed to real kproc_thread_attach_space(source, selected_private_root, ...)
  is rejected while source->active_space differs; source/refcounts unchanged.
  Native gated managed test: Pexec(200,"C:\\PIEPROBE.TOS","",0) == EINVFN.
These are expected negative controls. Header/segment staging succeeds through
existing production loader; that does not bypass the execution association.

Required invariant and missing mechanism:
  Preserve exact source KPROC/PID/PD and PROCESS resource owner, prepare an
  owned image/root/startup bundle without touching the old execution, seal it
  after all fallible work, then perform one reviewed NORETURN commit under
  scheduler/launcher ownership. Keep the source TID initially. Both KPROC and
  KTHREAD root bindings, user return context and architecture syscall/TSS/GS or
  banked supervisor-stack binding must refer to the committed image together.
  Old user continuation must become impossible before the exec generation
  advances. Old syscall/image/root resources must be reclaimed only off their
  executing stacks, by the existing owner. No fabricated PROCESS exit,
  THREAD-only completion, zombie, observer registry or reaper is permitted.

Why available constructors are insufficient:
  proc_clone LOADED_PROCESS/PREPARED_VM requires an unstarted target and
  kproc_thread_attach_space authenticates active_space. Using another PROCESS
  returns a different PID. Replacing the PD pointer would bypass legacy
  SFT.f_own and other identity bindings. Dropping association checks would make
  the THREAD's root disagree with its PROCESS. Existing proc_defer_exit /
  architecture launcher longjmp transfers off the syscall stack for final
  termination and invokes ksched_finish_exit / proc_finalize_exit; using that
  event as exec would publish a false completion and consume live ownership.
  Freeing the active syscall stack or copying its C continuation is invalid.

Smallest safe follow-up:
  Replacement peer admission includes canonical prepared THREAD and mapping
  memberships, even before active_space/pending_space adoption. Its borrowed
  prepared-member alias is inspected only while mapping preparation is
  PREPARING/PREPARED: ABORTING may already have freed it before file-backing
  cleanup reenters admission. A production-owner callback regression verifies
  unrelated-root prepare/validate/abort and exact reference conservation;
  the preceding reader fails that control under ASan. No membership registry
  or cleanup-order change is required.

  Extend the current KPROC loader image owner with an opaque movable bundle
  prepared from this receipt's selected root and staged layout. Add existing
  scheduler/launcher replacement prepare + seal + NORETURN commit, preserving
  source identity and rejecting cancellation/stale execution before seal. Share
  ordinary launch image preparation instead of adding another loader. Preserve
  source descriptor/CWD/resource ownership (#969); do not transplant a temporary
  loader PROCESS table. #971 defines independent source snapshot authority for
  fork; replacement's newly loaded image does not manufacture source rights.
  Committed notification: increment a monotonic generation on the exact retained
  source KPROC only once the new execution is installed and old return impossible;
  call ksched_irq_notify as a readiness hint. No callback registry is needed.

Acceptance to close issue970:
  Real user Pexec200 starts the new program as the same PID/PROCESS (and initial
  sole TID policy), never returns through the old image, and later completes and
  reaps once. Failed/missing/truncated/preparation-fault exec returns an error
  to the original child with its parent still blocked and every reference
  conserved. Successful commit advances only the exact child's generation and
  wakes its parent before independent child completion. Unrelated exec/exit,
  entry/preparation, public waits and THREAD-only exit do not release it. Prove
  syscall/TSS/GS/SVC/RTE state and off-stack old-root reclamation natively on
  x32, ARM A32 and m68k040, both filesystems and five shutdown checks. Unsupported
  CPU/FPU frame classes remain gated. Review #894/#895/#713 ownership together.

Pexec(200) commit design (#970, PR #999)
=======================================

Status: design, implementation in progress. Public mode200 stays EINVFN until
the native matrix, CI and owner reviews pass. This section supersedes nothing
above; it fills the "remaining concrete owner contract" of exec-handoff.txt.

Scope
-----
ELF executables with CONF_WITH_USER_ASPACE and the native scheduler. With per-
PROCESS address spaces the ELF loader puts the image in private pages of the
PROCESS's own root, and the TPA is the basepage only (elfld.c). A classic PRG
runs from its TPA, so replacing it would need a larger TPA, hence a new
basepage address and a new kernel identity: Pexec(200) of a PRG is rejected
(EPLFMT) before any allocation, as staging already does. Non-MMU kernels keep
EINVFN. Legacy PE_GO give-back, shared-VM (4/104) children and multi-THREAD
PROCESSes are rejected by admission, never partially replaced.

Identity
--------
Preserved exactly: KPROC record and number, PID, PD pointer and its TPA
procmem allocation (the kernel identity used by run, SFT f_own and the PID
table), parent identity and p_parent, KTHREAD and TID, PROCESS descriptors,
CWD/curdir/uft, priority, Psetlimit limits, start time and child usage,
completion/observer state and the public wait/reap rights.

The PD stays the program's basepage. At commit its program-visible fields are
rewritten from the staged image: command tail, p_env (new environment block),
p_tbase/p_tlen/p_dbase/p_dlen/p_bbase/p_blen and p_flags. p_parent, p_lowtpa/
p_hitpa (the retained TPA) and kernel-owned compatibility fields are kept. The
executable name becomes the new basename.

Replaced: address space (KASPACE root), image layout, interpreter state, entry
and initial stack, environment allocation, mapping memberships and allocation/
runtime scopes, private stack, DTA search state (VAs of the old image).

Staging (existing receipt, extended)
------------------------------------
kproc_exec_replacement_prepare/proc_exec_replacement_stage are reused. The
loader receives the receipt's SOURCE PD as the basepage address it records in
the initial stack/auxv (kproc.c and kproc_shared_interp.h now take it from the
receipt), because that is the basepage the program will have. The staging
container's own PD/TPA are discarded at commit or abort; its environment block
is the new program's and moves to the source by procmem ownership transfer.

Image bundle
------------
kproc_exec_image_seal(receipt) extracts an opaque, owning KPROC_EXEC_IMAGE:
selected root, layout, interpreter layout/entry, initial SP, stack low/size,
environment allocation (start, end, generation), shared-interp recipe and
reservation births. It then prepares the new root for the source exactly as
kproc_prepare_user_thread prepares a launch, sharing its code: a mapping
membership for the source number, the source TPA and new environment mapped
user-RW, the parent ancestors page and controller mapping, user callbacks and
X32 VDI image pages, the private stack, and a fresh kernel (syscall) stack.
Every step is fallible and reversible; abort releases the bundle and leaves
the source untouched. Sealing has no further failure return.

Commit
------
The #988 handoff gains an image-bundle mode. PREPARING admits the sealed
bundle with the receipt (same PROCESS/TID/execution/ticket). SEALED reserves
the execution number as before. TRANSFERRED/QUIESCENT are unchanged: the old
syscall continuation is abandoned through the launcher-owned stack, and the
task waits on the permanent CPU root. At INSTALLED, under the quiescent token:

  1. swap KPROC image fields with the bundle (new into the PROCESS, old into
     the bundle), including active_space/aspace and mapping memberships;
  2. rebind the KTHREAD's KASPACE to the new root through a new token-checked
     kthread_exec_rebind (the ordinary attach checks stay as they are);
  3. rewrite the basepage fields and transfer environment ownership;
  4. re-enter the ordinary launcher (proc_start_scheduled), which starts the
     new image exactly like a freshly launched program: kproc_user_entry,
     kproc_user_stack, basepage on the stack, the standard ELF entry for
     dynamic programs, and the bundle's kernel stack as the syscall stack.

No allocation, callback, user access or failure return follows TRANSFERRED.

Retirement
----------
After the IRQ mask is restored and with the current SP verified outside both
old kernel stacks (as #988 does), the old bundle is released: old root
(kaspace_put, which also drops its ASPACE-owned heap and mmap lists), old
mapping memberships, old environment allocation, old startup/stacks/hold, the
staging container. All by existing owners; the task stays non-runnable until
this finishes.

Committed-exec event
--------------------
KPROC gains UQUAD exec_generation and kproc_ref_exec_generation(), the exact
interface #972's fork_parent dependency reads. Retirement increments it once,
after the new image is installed and the old return is impossible, then calls
the scheduler's readiness notification. Staging, abort, failure, the same-
image transport, THREAD exit and PROCESS completion never change it; it never
wraps (exhaustion is checked at SEALED and fails the exec cleanly).

Gating
------
CONF_WITH_EXEC_REPLACE (new, default n, depends on the native scheduler, user
address spaces and ELF) builds the implementation. Public mode200 dispatch is
enabled only with it. Shipped configurations select it only after the native
matrix, CI and owner reviews pass.
