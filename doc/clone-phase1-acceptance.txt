Frozen public contract
----------------------
GEMDOS trap #1 opcode190, architecture-native structure pointer plus size.
The original prefix is28bytes; child_pid at28 extends it to32. Sizes28..31
omit PID; >=32 includes it. Only the known prefix is copied once. Unknown tail
bytes are ignored, but supplied address+size must fit32bit user arithmetic.
No version field or integer replacement for public pointer members. Native
alignment: x32/A32 four, m68k two. x32 LP64 kernel uses the explicit user32 wire
snapshot and zero-extends its fields; full native syscall slots are validated
before narrowing. The argument pointer is opaque, not dereferenced.

Flags VM=1, SAME_PROCESS=2, COPY_STANDARD_HANDLES=4,COPY_CWD=8; unknown bits
EINVAL. SAME_PROCESS requires VM and forbids resource-copy bits. VM creates a
new PROCESS/PID sharing ASPACE; VM|SAME_PROCESS creates a THREAD/TID in the same
PROCESS. Resource bits independently copy bindings/CWD, never PROCESS identity.
No resource bits means default standard handles/CWD. No implicit nonstandard
handle inheritance, environment sharing, signal policy, TLS or detach flag.
Success returns positive int32 TID. Optional int32 child_tid reports it;
optional child_pid reports the independently allocated PID or same PROCESS PID.
Neither output is a capability, status store or clear-on-exit location.

Non-NULL TLS fails EINVAL (#908 separate). Ordinary private flags0 and missing
managed context/backend fail EINVFN after argument validation; no child/output.
Disabled/non-MMU configurations fail before touching an invalid pointer.
Pfork/Pvfork, shared-VM Pexec and production PROCESS dispatch remain disabled.
Entry must be executable; stack writable, aligned, large enough for the real
startup frame. Optional outputs are native-aligned writable disjoint words,
not overlapping the startup stack, entry page or trusted return-bridge page.
Other pages use existing writable-memory validation. They may alias the snapshotted
input. No retained output pointer or post-store fallible operation. Public void
entry return is THREAD status0; explicit Pterm uses its existing completion ABI.

FAT/PFS recovery in this candidate
---------------------------------
The original native resource matrix exposed a FAT/PFS namespace collision on
ARM/m68k before clone publication: ckdrv installed a legacy dirtbl index into
PD_CURDIR, while PFS could allocate and immediately release that same number
as its new directory slot. Dgetpath/Dgetcwd lost the non-root directory. The
original failing preparation assertion is retained, including standard PFS.

A one-site diagnostic prototype failed relative loading and was rejected.
The user subsequently authorized the coherent ownership correction in #948:
PFS builds now have one PROCESS CWD namespace; native FAT relative lookup
borrows the authoritative PFS cookie; construction acquires every reference
before publication; teardown releases only its actual namespace. FAT cookies
hold their DND cache nodes, and media invalidation reserves referenced old
slots until their owners release. No parallel PROCESS/CWD registry is added.

Temporary cookies are released before ordinary disk-error longjmp propagation,
including nested rename resolution and search callbacks. Typed helper frames
preserve the existing error continuation/code/rw/drive; they do not swallow
media-change retry or promise arbitrary fatal/destructor unwind safety.
Trailing-slash removal resolves a parent/name pair without discounting an
independent live CWD/search hold or subsequently releasing a freed target.

Production hosted tests count cookie/cache lifetime, failed inheritance,
retirement reentry and real error jumps; the old production source fails the
new unwind baseline assertion. Native public tests cover non-root CWD reads,
all resource flags, nested/orphan inheritance, independent directory mutation
and both exit orders. Traditional FAT remains separate compatibility coverage.
See clone-pfs-prerequisite.txt for the implemented contract and supported scope.
Final exact-head native/CI and owner acceptance remain mandatory: no100%
Phase1 claim, automatic merge or issue closure follows from a source correction.

Native accounting fixture boundary
----------------------------------
A diagnostic m68k run located the first extra private page at10008000, the
start of the second still-owned Malloc stack, immediately after the first
short Pterm return. The existing m68k packed trap reader probes up to13words
and materializes readable lazy argument pages; this was not a retained return
bridge or leaked execution stack. All three owned stack reservations are now
materialized before intermediate accounting. The exact intermediate assertion
and original final pre-allocation baseline assertion remain intact, and all
three stacks must Mfree successfully. This does not claim an exact-arity m68k
trap reader or treat transient materialization as a failed rollback.

Recovery: shared execute-policy ownership
----------------------------------------
The PROCESS-local staged-image lookup was not authoritative for nested
CLONE_VM children. m68k now stores declared EXEC in each MMU leaf, including
when PRIVATE_CLONE=n: U1/software bit9 on040/060, an ignored page-address bit
in030's long descriptor. This is logical admission policy, NOT hardware NX.
Map/protect/move/COW and unmap/root destruction own it with the mapping; no
parent layout, retained PD, PID lookup or parallel permission registry is used.
KPROC asks that shared mapping policy (including COW logical permissions).
Native staged tests now check text/data/BSS/unclaimed image slack directly,
from a CLONE_VM child, and from an orphan after the staged owner retires and
fresh synchronous PROCESSes are constructed. A file handshake releases the
orphan only after the parent's Pwait result; rejected calls preserve both
outputs/full startup sentinel and create no observable child. Host page-table
models separately test an empty child layout and substituted original PD.
This correction is not accepted solely by the model: actual no-PRIVATE_CLONE
m68k040 and x32/ARM native execution remain required.

The implemented in-PR PFS recovery and its audit are documented in
clone-pfs-prerequisite.txt; the earlier proposal-only checkpoint is historical.

The native executable-policy fixture uses ELF on all targets and also classic
file-loaded PRG on m68k. CLNABI.TOS links the same native objects as ELF with
distinct text/data/BSS pages and gaps; runtests.tos retains PRG compatibility.
The trusted loader snapshots the PRG text length after relocation and before
exposing its PD. Preparation maps that TPA logically USER/WRITE and marks only
its text pages EXEC, with no new pin, allocation or physical ownership change.
No post-load writable PD field supplies execute policy. Physical m68k reads/
execution remain unchanged (no hardware NX). A page shared by a text tail and
data necessarily has page-granular rights; tests select a complete data/BSS
page. Basepage-created images without a file-declared text extent keep their
existing caller-supplied-code contract; no public Pexec mode is enabled.
Both file formats must pass all data/BSS/slack rejections, nested clones,
orphan handshake, full sentinels and final resource baselines. The loader-only
borrowed-text primitive has production-code host preflight/rollback coverage;
that is not a model of actual m68k exception execution.
